## 12.21
所谓滑动窗口，只要检验条件正确，就可以大胆收缩窗口，而不是来一个for循环
比如：
```cpp
while(sum>=target){
	minlen=i-j+1;
	result=result>minlen?minlen:result;
	sum-=num[j++];
}
return result==INT_MAX?0:result;
```
并且注意有检验：没有合适的解要返回0！
哈希表相关函数
今天水果成篮复盘：
#### 1. 索引与值的混淆 (Index vs Value) 🚨

- **错误现场**：最开始你写了 `basket[i]++`。
    
- **盲区解析**：这是初学者处理数组最容易犯的错。
    
    - `i` 是**位置**（第几棵树）。
        
    - `fruits[i]` 才是**数据**（这棵树上是什么水果）。
        
- **口诀**：**“操作哈希表，Key 是数组里的值 `nums[i]`，而不是下标 `i`。”**
    

#### 2. 逻辑流向：先判断还是先做事？ (Check-then-Act vs Act-then-Check)

- **错误现场**：最开始你写 `if (basket.size() <= 2)` 包裹整个逻辑，导致一旦超载，代码就“死机”了，因为没有机会去缩小窗口。
    
- **盲区解析**：滑动窗口的标准哲学是 **“先斩后奏”**。
    
    - **错误逻辑**：能不能进？能进再进。（会导致窗口卡住无法调整）
        
    - **正确逻辑**：先进来再说！进来后发现超载了？那就把旧的踢出去，直到合规为止。
        
- **408 考点**：所有的不定长滑动窗口（求最长子串/数组）都是这个模板：**进 -> while(不合规){出} -> 更新结果**。
    

#### 3. 指针 `j` 的“冻结”与 `erase` 的陷阱

- **错误现场**：你曾写过 `if(count==0) basket.erase(fruits[j++])`。
    
- **盲区解析**：这是对控制流理解的偏差。
    
    - **关于 `j`**：只要窗口需要收缩，左指针 `j` **必须**移动，不管是否触发了 erase。否则窗口永远缩不回去。
        
    - **关于 `erase`**：在 `map` 中，value 减到 0 并不代表 key 消失了，key 依然存在且 value 为 0，`.size()` 依然会计数。所以必须手动 `.erase()`。
