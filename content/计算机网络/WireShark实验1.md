2. 在过滤器中输入：`http`
3. 找到HTTP GET请求的数据包

### ✅ 问题2：以太网帧中的目标地址是什么？这是gaia.cs.umass.edu的地址吗？什么设备有这个地址？

**查找位置：**
```
Ethernet II → Destination: [目标MAC地址]
```

- 目标地址：`fc:60:9b:aa:3e:01`
- **不是** gaia.cs.umass.edu的地址
- 这是**我的网关（路由器）**的MAC地址

**原因说明：**
- gaia.cs.umass.edu不在局域网内
- 数据包需要先发给网关
- 网关再把数据包转发到互联网
- 这体现了"下一跳"原则

---

### ✅ 问题3：帧类型字段的十六进制值？对应什么上层协议？

**查找位置：**
```
Ethernet II → Type: [类型值]
```

**答案：**
- 十六进制值：**0x0800**
- 对应协议：**IPv4** 

- `0x0800` = IPv4
- `0x0806` = ARP
- `0x86DD` = IPv6
---

### ✅ 问题4：ASCII "G"（GET中的G）从以太网帧开始出现在第几个字节？

**计算步骤：**
- 以太网帧头：14 字节 (6 字节目的地址 + 6 字节源地址 + 2 字节类型)
- IP 协议头： 20 字节 (标准大小)
- TCP 协议头： 20 字节 (标准大小)
- 总和：14 + 20 + 20 = 54 字节。
- "GET" 命令是 HTTP 数据的开始，它紧跟在 TCP 协议头之后，所以 "G" 字符就位于第 54 字节的偏移位置。
---
### ✅ 问题5：HTTP响应的以太网源地址是什么？是你的计算机还是gaia.cs.umass.edu的地址？

**查找步骤：**
1. 找到HTTP响应数据包（包含 "HTTP/1.1 200 OK"）
2. 查看 `Ethernet II → Source`

- 源地址：fc:60:9b:aa:3e:81 
- **既不是**我的计算机，**也不是** gaia.cs.umass.edu
- 这是**我的网关（路由器）**的MAC地址

**原因：**
- 服务器的响应先到达网关
- 网关转发给你时，以太网帧的源地址是网关
- MAC地址只在局域网内有效

## 📝 第二部分：ARP协议分析

### 准备工作：
1. 执行 `arp -a` 查看ARP缓存
2. 在Wireshark过滤器中输入：`arp`
---
### ✅ 问题12：ARP请求的以太网源地址是什么？

**查找步骤：**
1. 在Wireshark中过滤：`arp`
2. 找到第一个ARP请求（Opcode: request）
3. 展开 `Ethernet II`

**查找位置：**
```
Ethernet II → Source: [你的MAC地址]
```

**答案：**
- 源地址：`a0:29:42:ca:c7:27`
- 这是**我的计算机**的MAC地址
---
### ✅ 问题13：ARP请求的以太网目标地址？对应什么设备？
**查找位置：**
```
Ethernet II → Destination: [目标地址]
```
**答案要点：**
- 目标地址：**ff:ff:ff:ff:ff:ff**
- 这是**广播地址**（Broadcast address）
- 对应设备：**局域网内所有设备**
**原因说明：**
- ARP请求不知道目标的MAC地址
- 所以向局域网内所有设备广播
- "谁有这个IP地址？请告诉我你的MAC地址！"
- 所有设备都会收到，但只有目标IP的设备会回复
---
### ✅ 问题14：ARP消息的帧类型字段值？
**查找位置：**
```
Ethernet II → Type: [类型值]
```
**答案：**
- 十六进制值：**0x0806**
- 对应协议：**ARP** 
---
### ✅ 问题15：以太网帧的起始位置到ARP操作码字段的起始位置之间相隔多少字节？
**计算方法：**
**以太网头部：** 14字节
- 目标MAC：6字节
- 源MAC：6字节
- 类型：2字节
**ARP头部（操作码之前的字段）：**
- 硬件类型（Hardware Type）：2字节
- 协议类型（Protocol Type）：2字节
- 硬件地址长度（Hardware Address Length）：1字节
- 协议地址长度（Protocol Address Length）：1字节
**计算：**
```
14（以太网）+ 2 + 2 + 1 + 1 = 20字节
```

### ✅ 问题16：ARP请求消息的操作码值是什么？
**查找位置：**
```
Address Resolution Protocol (request)
  └─ Opcode: request (1)
```
**答案：**
- 十六进制：**0x0001**
- 十进制：**1**
- 含义：**ARP请求** (request)

**知识点：**
- 操作码 = 1：ARP请求
- 操作码 = 2：ARP应答
