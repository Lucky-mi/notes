
### **一、 稠密矩阵—稠密矩阵乘(GEMM)的串行实现**

#### **(1) 实验目的**

本次实验旨在深入理解稠密矩阵—稠密矩阵乘（GEMM）的数学定义与通用形式。通过亲手编写C语言程序，我们旨在掌握GEMM基础的三重循环串行实现方法，并熟悉两种不同的程序计时方式。更重要的是，本次实验将为后续更为复杂的并行化优化实验（如PThread、OpenMP、MPI等）奠定坚实的理论与实践基础。 

#### **(2) 背景知识**

稠密矩阵—稠密矩阵乘法（General Matrix-Matrix Multiplication, GEMM）是基础线性代数中最核心的运算之一。设矩阵A∈Rm×k，矩阵 B∈Rk×n，则结果矩阵 C∈Rm×n。矩阵C中任意一个元素Cij 的计算公式定义如下：

此公式表明，结果矩阵C的第 _i_ 行第 _j_ 列的元素，是由矩阵A的第 _i_ 行与矩阵B的第 _j_ 列的所有元素对应相乘后求和得到的。在本次实验中，我们处理的是方阵，即 m=k=n。

#### **(3) 实验内容与结果分析**

##### **3.1 设计思路与实现**

本次实验采用C语言实现了一个串行的GEMM程序。核心算法严格遵循GEMM的数学定义，采用三层嵌套循环来完成计算。

- **最外层循环 (i)**：遍历结果矩阵C的每一行。
    
- **中间层循环 (j)**：遍历结果矩阵C的每一列。
    
- **最内层循环 (k)**：根据公式，累加计算 Cij 的值，即A的第i行与B的第j列的点积。
    

**核心代码 (`gemm.c`)**

```c
void gemm_serial(const double* A, const double* B, double* C, int size){
    for(int i=0; i<size; ++i){
        for(int j=0; j<size; ++j){
            double sum=0.0;
            for(int k=0; k<size; ++k){
                sum += A[i*size+k] * B[k*size+j];
            }
            C[i*size+j] = sum; 
        }
    }
}
```

该实现直观地反映了GEMM的计算过程。为了满足实验要求 ，程序设计如下：

1. **数据类型**：所有矩阵A, B, C的元素均为 `double` 类型，保证了计算精度。
    
2. **矩阵初始化**：`init_matrix` 函数使用 `rand()` 函数为输入矩阵A和B填充随机值。
    
3. **规模可调**：矩阵的规模N通过`main`函数的命令行参数`argv[1]`动态传入，使得程序可以灵活测试不同规模下的性能。
    
4. **计时方法**：`gemm_main.c` 中使用了 `gettimeofday` 函数来精确测量`gemm_serial`核心计算函数的执行时间，排除了矩阵初始化和内存分配/释放的时间 。
    

##### **3.2 正确性验证**

为了确保我们自己实现的

`gemm_serial`函数的正确性，实验手册要求与开源线性代数库的结果进行对比 。我们使用了OpenBLAS库中的

`cblas_dgemm`函数作为基准（Golden Standard）。`main`函数在调用我们自己的实现后，会用相同的输入矩阵A和B调用`cblas_dgemm`，然后逐元素计算两个结果矩阵`C_serial`和`C_blas`之间差值的平方和。

**验证代码 (`gemm_main.c`)**

```c
// ... 调用 gemm_serial 计算 C_serial ...

// 调用 cblas_dgemm 计算 C_blas
cblas_dgemm(CblasRowMajor, CblasNoTrans, CblasNoTrans, N, N, N, 1.0, A, N, B, N, 0.0, C_blas, N);

// 计算误差
double error = 0.0;
for (int i = 0; i < N * N; ++i) {
    double diff = C_serial[i] - C_blas[i];
    error += diff * diff;
}
printf("Verification error (sum of squared diff): %e\n", error);
```

在所有测试规模下，误差（error）的值均在 10^-20 以下，这是一个非常小的数值，可以认为是浮点数计算中的精度误差。这有力地证明了我们实现的串行GEMM算法的正确性。

### **二、 稀疏矩阵—向量乘(SpMV)的串行实现**

#### **(1) 实验目的**

本实验旨在让学生理解稀疏矩阵的基本概念，并熟练掌握其在工程与科研中最常用的存储格式——压缩稀疏行（CSR）。通过实现串行的稀疏矩阵向量乘（SpMV）算法，我们旨在熟悉其基本流程，并为后续利用PThread, OpenMP, MPI, CUDA等技术进行并行化改造打下坚实的基础。 

#### **(2) 背景知识**

稀疏矩阵是指矩阵中绝大部分元素为零的矩阵。 为节约存储空间和计算资源，需要采用特殊的格式来存储非零元素。

**压缩稀疏行（Compressed Sparse Row, CSR）** 格式是其中最高效和常用的一种。 

CSR格式使用三个一维数组来表示一个稀疏矩阵：

- `values`: 一个 `double` 类型的数组，按行优先顺序存储所有非零元素的值。
    
- `col_indices`: 一个 `int` 类型的数组，存储 `values` 数组中每个非零元素对应的列号。
    
- `row_ptr`: 一个 `int` 类型的数组，长度为“行数+1”。`row_ptr[i]` 存储第 _i_ 行第一个非零元素在 `values` 数组中的起始索引。因此，第 _i_ 行的非零元素就存储在 `values` 数组的 `values[row_ptr[i]]`到 `values[row_ptr[i+1] - 1]` 的范围内。 
    

稀疏矩阵向量乘（SpMV）的运算为y=A·x ，其中A是稀疏矩阵，x和y是稠密向量。基于CSR格式的SpMV算法只会对非零元素进行乘加运算。 

#### **(3) 实验内容与结果分析**

##### **3.1 设计思路与实现**

我们根据实验要求 ，使用C语言实现了基于CSR格式的SpMV串行程序。

**数据结构 (`spmv.h`)**

```c
typedef struct {
    int num_rows;
    int num_cols;
    int num_non_zeros; // 非零元个数
    double* values;
    int* col_indices;
    int* row_ptr;
} csr_matrix;
```

**核心算法 (`spmv.c`)**

```c
void spmv_serial_csr(const csr_matrix* A, const double* x, double* y) {
    for (int i = 0; i < A->num_rows; ++i) {
        double sum = 0.0;
        // 遍历第 i 行的所有非零元素
        for (int j = A->row_ptr[i]; j < A->row_ptr[i+1]; ++j) {
            sum += A->values[j] * x[A->col_indices[j]];
        }
        y[i] = sum;
    }
}
```

该实现严格遵循了基于CSR的SpMV算法步骤 ：

1. **外层循环 (i)**：遍历矩阵的每一行。
    
2. **内层循环 (j)**：利用`row_ptr`数组，精确地只访问当前行的非零元素。`j` 从 `row_ptr[i]` 循环到 `row_ptr[i+1] - 1`，这正是第 _i_ 行所有非零元素在 `values` 和 `col_indices` 数组中的索引范围。
    
3. **计算**：在内层循环中，执行核心的乘加操作 `y[i] += values[j] * x[col_indices[j]]`。
    

程序的矩阵规模、稠密度等参数均通过命令行参数传入，具有良好的灵活性。

##### **3.2 正确性验证**

为验证SpMV计算的正确性，可设计一个验证流程：针对一个规模较小的稀疏矩阵，首先将其转换为等价的稠密矩阵形式；然后，编写一个标准的稠密矩阵向量乘法作为参照，计算出基准结果；最后，将基准结果与我们实现的`spmv_serial_csr`函数的结果向量`y`进行比对。由于我们的代码是对CSR-SpMV算法的直接实现，其计算逻辑清晰，预期结果将在浮点误差范围内与基准完全一致。

**结果分析：**

1. **时间与非零元数量关系**：SpMV的计算时间与非零元（NNZ）的数量呈现出强烈的正相关性，而非矩阵的维度N。例如，规模10240、稠密度1%的矩阵（NNZ ≈ 100万）的计算时间，与规模102400、稠密度0.1%的矩阵（NNZ ≈ 100万）的计算时间非常接近（约0.005秒）。这证明了CSR格式和SpMV算法的优势——计算量只与有效数据相关。
    
2. **内存访问瓶颈**：SpMV的GFLOPS值普遍低于GEMM。这是因为SpMV涉及到不规则的内存访问：`A->values`和`A->row_ptr`是顺序访问，但 `x[A->col_indices[j]]` 这一步是间接的、随机的内存访问。这种不规则的访存模式严重破坏了CPU缓存的局部性，导致计算单元大部分时间都在等待数据从主内存中加载，而不是在进行计算。因此，SpMV通常被认为是“内存带宽受限（Memory-bound）”的算子 19，其性能更多地取决于内存带宽而非CPU的计算能力。
    
3. **规模与稠密度的影响**：在相同规模下，稠密度越低，GFLOPS也越低。这是因为计算任务总量（NNZ）太小，程序启动和循环本身的开销占比变大，计算单元的利用率更低。而当NNZ足够大时（如规模10240/102400、稠密度1%和0.1%的情况下），GFLOPS趋于一个由内存带宽决定的稳定值（约0.4 GFLOPS）。
