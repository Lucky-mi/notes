 1：考 Amdahl 定律

题目：假设一个程序的 80% 代码可以并行化，剩余 20% 必须串行。

(1) 如果使用 4 个处理器，理论加速比是多少？

(2) 哪怕你有无限个处理器，最大加速比是多少？

解析：

$\alpha = 0.8$, $1-\alpha = 0.2$。

(1) $k=4$。$S = \frac{1}{0.2 + 0.8/4} = \frac{1}{0.2 + 0.2} = \frac{1}{0.4} = 2.5$ 倍。

(2) $k=\infty$。$S = \frac{1}{0.2} = 5$ 倍。

题目：为什么在这个图中，加速比曲线有时会超过线性加速比（即 Super-linear）？
![[{1CE9CD10-1DD9-4140-8EEE-E6C81611B6CB}.png]]

**答案**：这是由于**缓存效应 (Cache Effect)**。当使用更多处理器时，所有处理器的总缓存容量增加。如果数据集能完全装入这些分布式的缓存中，而无法装入单处理器的缓存中，内存访问延迟会大幅降低，导致计算速度的提升超过了处理器数量的增加倍数 。

 **Q1 (简答/名词解释):** 什么是“存储墙” (Memory Wall)？
>  **参考答案：** 指随着技术发展，处理器（CPU）性能的提升速度远快于存储器（Memory）性能的提升速度，导致存储器带宽和延迟成为限制计算机系统整体性能的瓶颈。

> **参考答案：** Cache 解决**速度**匹配问题；虚拟存储器解决**容量**问题。

> **Q3 (简答 - 高频):** 简述程序的局部性原理，并说明它分为哪两类。 
> **参考答案：** 程序的局部性原理指程序在执行时呈现出访问局部区域的规律。
> 
> 1. **时间局部性**：最近被访问的信息很可能在不久的将来再次被访问。
>     
> 2. **空间局部性**：某个存储单元被访问，其附近的存储单元也很可能在不久的将来被访问。


> **Q1 (选择题):** 在 Flynn 分类法中，现代 GPU（图形处理器）主要属于哪一类？ A. SISD B. SIMD C. MISD D. MIMD **答案：** **B (SIMD)**。虽然现代 GPU 也有 MIMD 特性，但其核心计算模式是大量的核心同时执行相同的指令处理不同的像素点，是典型的 SIMD。

> **Q2 (辨析题):** 简述 UMA 和 NUMA 的主要区别。 **参考答案：**
> 
> - **UMA (统一内存访问)**：所有处理器访问内存中任何位置的时间都是相同的，通常通过共享总线实现。
>     
> - **NUMA (非统一内存访问)**：处理器访问本地内存（Local Memory）的速度比访问远程内存（Remote Memory，即其他处理器挂载的内存）要快。NUMA 解决了 UMA 的总线瓶颈问题，扩展性更好。
>     

> **Q3 (判断题):** 在分布式存储系统中，一个节点可以直接通过加载指令（Load Instruction）读取另一个节点内存中的数据。 
> **答案：** **错**。分布式存储中内存是私有的，必须通过网络接口进行显式的消息传递（Send/Receive）来交换数据。

> **Q2 (简答题):** 简述乱序执行（Out-of-Order Execution）的基本思想，并解释为什么结果提交（Commit）阶段必须是按序的？ **参考答案：** * **思想**：允许将多条指令不按程序规定的顺序发送给执行单元，只要操作数准备好即可提前执行，以减少流水线阻塞 。
> 
> - **按序提交原因**：为了确保程序运行结果的正确性（精确异常处理），如果指令执行出错，需要能够恢复到出错前的状态；如果乱序提交，可能会导致寄存器状态不可逆地被错误更新。


> **Q5 (辨析题):** 细粒度多线程与同时多线程 (SMT) 有什么本质区别？ 
> **参考答案：**
> - **细粒度多线程**：在**不同**的时钟周期轮流执行不同线程的指令（纵向并发）。
> * **SMT**：在**同一个**时钟周期内，可以同时发射并执行来自**不同**线程的指令（纵向+横向并发），利用了超标量的多发射能力，资源利用率更高 。

> **答案：** **预测执行 (Speculative Execution)** 或 **乱序执行 (Out-of-Order Execution)** 。

 **题目：** 假设一个程序的串行比例 $F = 5\%$（即 $0.05$），并行部分为 $95\%$。现在使用 $64$ 个处理器 ($n=64$)。

1. 根据 **阿姆达尔定律 (Amdahl's Law)**，加速比是多少？
>     
2. 根据 **Gustafson 定律**，加速比是多少？
>     
 3. 为什么两者的结果差距这么大？     
> 
> **解析：**
> 
 4. 阿姆达尔定律（固定问题规模）：
>     
$$S = \frac{1}{F + \frac{1-F}{n}} = \frac{1}{0.05 + \frac{0.95}{64}} \approx \frac{1}{0.05 + 0.0148} \approx \frac{1}{0.0648} \approx \mathbf{15.4}$$
      (你看，哪怕用了64个核，加速比才15倍，很悲观)
>     
 5. Gustafson 定律（扩大问题规模）：
>    
 公式：$S = n - F(n-1)$ 
>     
$$S = 64 - 0.05 \times (64 - 1) = 64 - 0.05 \times 63 = 64 - 3.15 = \mathbf{60.85}$$     
>     (这就很乐观了，接近理想的64倍)
>     
 6. **原因分析**：阿姆达尔定律假设**问题规模不变**，增加处理器导致每个处理器分到的计算量太少，通信和串行瓶颈占比飙升；而 Gustafson 定律假设**时间不变，问题规模变大**，计算量增加了，串行部分占比相对被稀释了，所以效率更高。

#### **题型 2：分析与简答（重点）**

- **题目**：请简述 **Block（块状）划分** 与 **Cyclic（循环）划分** 的区别，并说明在什么情况下 Cyclic 划分比 Block 划分更有优势？
    
- **参考答案**：
    
    - **区别**：Block 划分是将连续的数据块分配给任务；Cyclic 划分是将数据按照固定的步长（如轮询）交错分配给任务。
        
    - **Cyclic 的优势场景**：当数据各部分的计算负载**不均匀**（即有的数据处理起来快，有的慢），且这种负载分布具有局部聚集性时，Block 划分可能导致某些任务很快做完，某些任务很久做不完（负载不均衡）。而 Cyclic 划分可以将重负载和轻负载的数据分散给不同的任务，从而实现更好的**负载均衡**。

- **题目**：并行计算中，调度的两个主要性能目标是 \________ 和\________ 。在调度过程中，通常需要权衡的两个关键因素是 ________ 和 ________。
    
- **答案**：
    
    - 目标：最小化执行时间、最大化资源利用率。
        
    - 权衡因素：负载均衡（Load Balance）、数据局部性（Locality）。
        
    - _解析_：为了负载均衡，我们可能想把任务到处挪，但这会破坏数据局部性（数据又要重新搬来搬去）。这就是最经典的 **Trade-off**。


- **题目**：什么是 **CPU 亲和性 (CPU Affinity)**？在并行计算中设置 CPU 亲和性有什么好处？
    
- **参考答案**：
    
    - **定义**：CPU 亲和性是指将特定的进程或线程绑定到特定的 CPU 核心或核心集合上，使其仅在指定的硬件单元上运行。
        
    - **好处**：
        
        1. **提高缓存命中率**：防止线程在不同核心间迁移导致 L1/L2 缓存失效。
            
        2. **优化 NUMA 性能**：保证线程优先访问本地内存节点，减少跨节点的远程内存访问延迟。
            

#### **题型 2：分析题（高分题）**

- **题目**：在一个双路 CPU 服务器（NUMA 架构）上，网卡连接在 CPU 0 上。某网络密集型并行程序启动了 4 个线程进行数据包处理。
    
    - (1) 如果不进行任何设置，可能会出现什么性能问题？
        
    - (2) 为了达到最佳性能，应如何进行线程调度映射？
        
- **参考答案**：
    
    - (1) **问题**：操作系统可能会将线程调度到 CPU 1 上。此时，线程需要处理的数据在 CPU 0 的内存/缓存中（因为网卡在 CPU 0），导致大量的跨 CPU 远程内存访问（Remote Memory Access），增加延迟，降低吞吐量。同时，线程迁移也会导致 Cache 抖动。
        
    - (2) **优化**：利用 CPU 亲和性技术，将这 4 个线程**绑定（Pin）** 到 CPU 0 的物理核心上，确保“计算紧随数据”（Compute follows Data），实现本地内存访问和缓存复用。
- **题目**：在进行线程映射时，为什么有时候需要将“相关的线程”放在一起，有时候又需要将“不相关的线程”放在一起？
    
- **参考答案**：
    
    - 将**相关线程**放在一起（如同一个核心或 Socket），可以利用**空间局部性**，共享 Cache 数据，减少通信和同步开销。
        
    - 将**不相关线程**放在一起，可以避免它们争夺同一种硬件资源（如都大量使用 ALU 或都大量访存），从而提高**流水线和硬件资源的利用率**。


- **题目**：并行计算中的动态调度策略主要包括三种模式：\________ 、\________ 和 \________ 。
    
- **答案**：自调度 (Self-Scheduling)、工作窃取 (Work-Stealing)、工作共享 (Work-Sharing)。

#### **题型 2：分析题**

- **题目**：在某些情况下，为什么将 Chunk Size 设置为 1（即 `schedule(static, 1)`，也称为 Cyclic 调度）可能比设置较大的 Chunk Size 具有更好的负载均衡效果？但同时会带来什么负面影响？
    
- **参考答案**：
    
    - **负载均衡**：当循环迭代的计算量变化很大且没有规律时，Chunk=1 可以像发牌一样把任务打散，最大概率地让每个线程分到的总工作量趋于平均。
        
    - **负面影响**：Chunk=1 破坏了数据的**空间局部性 (Spatial Locality)**，因为线程访问的数据在内存中可能是不连续的，会导致缓存命中率下降；同时如果任务粒度太小，可能导致伪共享 (False Sharing) 问题。

法计算题（五星重点）**

- **题目**：假设有一个并行循环共有 100 个迭代任务（$N=100$），系统有 4 个处理器（$P=4$）。请使用 **指导性自调度 (GSS)** 算法，计算前三次任务分配的块大小（Chunk Size）分别是多少？
    
- **解答**：
    
    1. **第一次分配**：
        
        - 剩余 $R_1 = 100$。
            
        - $K_1 = \lceil 100 / 4 \rceil = 25$。
            
    2. **第二次分配**：
        
        - 剩余 $R_2 = 100 - 25 = 75$。
            
        - $K_2 = \lceil 75 / 4 \rceil = \lceil 18.75 \rceil = 19$。
            
    3. **第三次分配**：
        
        - 剩余 $R_3 = 75 - 19 = 56$。
            
        - $K_3 = \lceil 56 / 4 \rceil = 14$。
            
    
    - **答案**：25, 19, 14。
        

#### **题型 2：简答/比较题**

- **题目**：比较 **GSS (指导性自调度)** 和 **TSS (梯形自调度)** 在块大小变化上的主要区别。
    
- **答案**：
    
    - **GSS** 的块大小随分配次数呈**指数级衰减**（一开始很大，迅速变小），能够快速减少调度开销，但在某些极端负载不均下可能因为初始块太大导致不平衡。
        
    - **TSS** 的块大小呈**线性递减**（均匀变小），变化更加平缓，容易控制，适合循环迭代计算量变化比较规律的场景。

- **题目**：请简述 **工作窃取 (Work-Stealing)** 和 **工作共享 (Work-Sharing)** 的主要区别，并说明工作窃取为何在现代并行框架中更受欢迎？
    
- **参考答案**：
    
    - **区别**：
        
        1. **发起方不同**：工作窃取是由**空闲**的处理器发起的（我没活了去偷）；工作共享通常是由**繁忙**的处理器发起的（我活太多了分出去）。
            
        2. **队列结构**：工作窃取使用分布式队列（无中心瓶颈）；工作共享通常依赖一个集中式队列。
            
    - **工作窃取受欢迎的原因**：
        
        - 它极大地减少了**锁竞争**。在负载较重时（大家都忙），工作窃取几乎不需要通信（各干各的），只有在负载不均时才有开销；而工作共享在负载重时反而频繁访问全局队列，容易造成瓶颈。
            
        - 它具有更好的**数据局部性**（自己产生的子任务自己优先处理）。

- **参考答案**：
    
    - **场景 A 选择 SoA**。
        
        - _理由_：计算 `x` 的更新只涉及 `x` 分量。SoA 将所有 `x` 连续存储，允许 CPU 使用 SIMD 指令（如 AVX）一次加载多个 `x` 进行并行加法，且缓存中全是有用的 `x` 数据，无浪费。
            
    - **场景 B 选择 AoS**。
        
        - _理由_：打印单个粒子需要同时访问 `x, y, z, mass`。AoS 将它们紧挨着存储，符合空间局部性，一次访存即可取出所有属性。
            

#### **题型 2：简答题**

- **题目**：简述 **AoS** 和 **SoA** 的区别，并说明为什么现代 GPU 和 CPU 向量编程通常更倾向于使用 SoA？
    
- **答案**：
    
    - AoS 是“结构体的数组”（RGB RGB），适合对象整体访问；SoA 是“数组的结构”（RRR GGG），适合分量批量处理。
        
    - 向量编程倾向于 SoA，是因为它保证了**内存访问的连续性 (Memory Coalescing)**。当对某种属性（如颜色 R）进行批量相同时，SoA 允许硬件一次性加载连续的多个数据到向量寄存器中，极大提升吞吐量。

“如何利用向量化指令处理 AoS 格式的数据？”，标准答案通常是：“先用 **Unzip** 将其转换为 SoA 格式进行计算，计算完后再用 **Zip** 转换回 AoS 格式。”

    - **答案 1 (Merge Scatter)**：

- **题目**：在几何分解（Domain Decomposition）中，什么是 **Ghost Zone (或 Halo Region)**？它有什么作用？
    
- **参考答案**：
    
    - **定义**：Ghost Zone 是在将数据空间划分为多个子区域分配给不同任务时，每个任务在本地内存中额外存储的、属于相邻任务边界数据的**副本**。
        
    - **作用**：为了满足计算时的邻居依赖（如计算微分时需要周围点的值），允许任务读取本地的 Ghost Zone 数据而无需频繁进行网络通信，从而**减少通信开销**，提高并行效率。

#### **题型 2：场景选择题**

- **题目**：以下哪种数据重组操作最适合用于实现“快速排序 (QuickSort)”中的分区（Partition）步骤（即将小于 Pivot 的放左边，大于 Pivot 的放右边）？ A. Gather B. Split C. Bin D. Zip
    
- **答案**：**B. Split**。
    
    - **解析**：快速排序的分区本质上就是把数据按条件（< Pivot 或 > Pivot）分成两堆，这正是 Split 的定义。如果有多个 Pivot 分成多段，那就是 Bin。



- **题目**：什么是 **栅栏 (Barrier)** 同步？
    
- **参考答案**：
    
    - 栅栏是一种全局同步机制。它在程序中设定一个同步点，要求所有参与的线程或进程在到达该点时必须**暂停等待**，直到**所有**线程都到达该点后，才能继续执行后面的代码。这确保了所有线程在进入下一阶段前都完成了当前阶段的工作。
        

#### **题型 2：填空/简答**

- **题目**：在 **BSP (整体同步并行)** 模型中，一个“超级步 (Superstep)”通常包含哪三个有序的阶段？
    
- **答案**：局部计算 (Computation)、全局通信 (Communication)、栅栏同步 (Barrier Synchronization)。
- **题目**：在使用 Barrier 同步时，如果有一个线程因为死循环永远无法到达 Barrier 点，会发生什么后果？
    
- **答案**：**死锁 (Deadlock)**。
    
    - _解析_：因为 Barrier 的规则是“不见不散”。只要有一个人不到，其他人就得永远等下去，导致整个并行程序卡死。


- **题目**：请简述 **自旋锁 (Spin Lock)** 和 **阻塞锁 (Blocking Lock)** 的区别，并说明在什么情况下应该优先选择自旋锁？
    
- **参考答案**：
    
    - **区别**：阻塞锁在获取不到锁时会将线程挂起（睡眠），让出 CPU 资源；而自旋锁在获取不到锁时，线程会处于忙等待（Busy Waiting）状态，在一个循环中不断检查锁的状态，不让出 CPU。
        
    - **选择自旋锁的场景**：
        
        1. **临界区非常短**：线程持有锁的时间很短，等待的时间成本小于线程切换（挂起/唤醒）的开销。
            
        2. **多核处理器**：自旋需要占用一个物理核心空转，如果是单核，自旋会卡死系统。

#### **题型 3：场景选择**

- **题目**：如果你在编写一个数据库系统，其中有一个配置表，几乎每秒钟有 10000 次读取请求，但每天只有 1 次修改请求。为了保证性能和数据安全，你应该使用哪种锁？ A. 互斥锁 (Mutex) B. 自旋锁 (Spin Lock) C. 读写锁 (Read-Write Lock)
    
- **答案**：**C**。

- **题目**：请简述 **互斥锁 (Mutex)** 和 **信号量 (Semaphore)** 的主要区别。
    
- **参考答案**：
    
    - **数量限制**：Mutex 相当于计数为 1 的 Semaphore，只允许一个线程访问临界区（独占）；Semaphore 可以允许 N 个线程同时访问（共享，但限制并发数）。
        
    - **所有权**：Mutex 通常具有**所有权**概念，谁加锁必须由谁解锁；Semaphore 通常没有所有权，一个线程执行 P 操作（等待），可以由另一个线程执行 V 操作（释放/唤醒），这常用于线程间的**同步通知**（A 线程做完某事通知 B 线程）。

#必考 
进程与线程的区别

进程是操作系统进行**资源分配和拥有**的基本单位，而线程是操作系统进行**CPU调度和分派**的基本单位。二者的区别主要体现在四个方面：首先在**资源占用**上，进程拥有独立的地址空间和系统资源，而同一进程内的线程共享进程的全部资源（如代码段、数据段、打开的文件等），仅独立拥有必不可少的程序计数器、一组寄存器和栈。其次在**开销**上，进程切换涉及当前CPU环境的保存及新环境的设置，且需切换页表，开销较大；而线程切换仅需保存和设置少量寄存器内容，不涉及存储管理操作，开销很小。再次在**通信**上，进程间通信（IPC）需要借助操作系统提供的机制（如管道、消息队列），较复杂；而线程间可直接通过读写共享全局变量进行通信，但需做好同步互斥。最后在**健壮性**上，进程之间相互隔离，一个进程崩溃通常不影响其他进程；而一个线程崩溃往往会导致整个进程及其包含的所有线程终止。
