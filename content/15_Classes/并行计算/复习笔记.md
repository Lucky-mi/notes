## [[GPU&CUDA]]
### 🧠 计算机体系结构与异构计算重点 (408/AI架构)

#### 1. 硬件灵活性与效率权衡 (Trade-off)

> [!SUMMARY] 核心结论
> **灵活性 (Flexibility):** CPU > GPU > FPGA > ASIC
> **能效比 (Performance/Watt):** ASIC > FPGA > GPU > CPU
> **开发难度 (Dev Difficulty):** ASIC > FPGA > GPU > CPU

| 类型       | 全称                                      | 描述       | 特点                     | 适用场景                    |
| :------- | :-------------------------------------- | :------- | :--------------------- | :---------------------- |
| **CPU**  | Central Processing Unit                 | 通用处理器    | 软件定义，指令集控制，灵活性最高，效率最低。 | 逻辑控制、复杂串行任务             |
| **GPU**  | Graphics Processing Unit                | 图形处理器    | SIMT 架构，适合大规模并行计算。     | AI 训练/推理、图形渲染           |
| **FPGA** | Field-Programmable Gate Array           | 现场可编程门阵列 | 硬件电路可重构，半定制。           | 原型验证、低延迟通信、小批量专用硬件      |
| **ASIC** | Application-Specific Integrated Circuit | 专用集成电路   | 电路物理固化，不可更改。           | 大规模量产的 AI 芯片 (如 TPU)、矿机 |

#### 2. GPU 编程模型与存储层次 (CUDA)

##### 编程模型开源性
* **❌ CUDA:** NVIDIA 私有标准 (闭源)。
* **✅ OpenCL / OpenMP / OpenACC:** 开放标准 (开源/通用)。

##### GPU 存储器速度层级 (Memory Hierarchy)
从快到慢 ($T_{access}$ 延迟递增)：

1.  **Register (寄存器)**
    * *位置:* On-chip (SM 内部)
    * *延迟:* ~0 cycle
    * *范围:* 线程私有 (Thread Private)
2.  **Shared Memory (共享内存)**
    * *位置:* On-chip (SM 内部，用户可控缓存)
    * *延迟:* ~20-30 cycles
    * *范围:* 线程块内共享 (Block Shared)
3.  **Local Memory (局部内存)**
    * *位置:* Off-chip (显存 DRAM，但不仅限于此)
    * *注意:* 名为"Local"，实际很慢。用于寄存器溢出 (Spilling)。
4.  **Global Memory (全局内存)**
    * *位置:* Off-chip (显存 DRAM)
    * *延迟:* ~400-800 cycles
    * *范围:* 全局共享 (Host & Device)

### PPT重点总结
- **层级区分**：要能分清 **Core (核心)** 和 **Node (节点)** 的区别。
    
    - **Core** 是芯片里的，通常共享内存。
        
    - **Node** 是网络里的（一台电脑），通常内存独立。
        
- **组件功能**：如果考到“我们在哪里提交作业？”，答案是 **Login Node (登录节点)**，而不是计算节点。
    
- **Infiniband**：记住这个词，它是高性能计算网络的代名词，特点是**高带宽、低延迟**。

**Q1 (简答/填空):** 2005年以后，微处理器性能提升的主要驱动力发生了什么变化？为什么？
**参考答案：** 驱动力从提高**主频（时钟频率）** 转向了增加 **核心数量（并行度）** 。原因是撞上了 **“功耗墙”** （或散热限制），单核频率无法在保持合理功耗的前提下继续提升。

Q1 (计算题/选择): 假设有 $N$ 个处理器，对长度为 $N$ 的数组进行求和。串行算法的时间复杂度为 $O(N)$，使用树形归约（Tree Reduction）的并行算法时间复杂度是多少？

**答案：** $O(\log N)$ 1。

Q2 (代码分析): 观察 PPT 22页的代码，为什么这个双重循环可以简单地通过 \#pragma omp parallel for 进行并行化？

**答案：** 因为数组元素之间的计算**没有数据依赖**（No data dependency）2，且各个迭代步是独立的。
**Q3 (简答/名词解释):** 什么是 SPMD？在热传导方程的并行实现中，为什么需要“交换边界信息”？
**参考答案：** * **SPMD** (Single Program, Multiple Data) 是指所有处理器运行同一个程序副本，但处理不同的数据子集（根据处理器ID执行不同分支）。 * **交换边界原因**：因为使用了区域分解（Domain Decomposition），每个处理器只计算一部分网格。计算子区域边界上的点时，依赖于相邻处理器所持有的数据（邻居数据），因此必须通信传输这些边界值 。

**Q4 (判断):** 在热传导方程的并行求解中，不同时间步（Time Steps）的计算可以并行执行吗？

**答案：** **不可以**。PPT 24页指出“下个时间步的计算依赖于上一步的计算结果”，因此时间步之间必须**同步**，不能乱序并行 。

| ------- | ------------------- | ----------------------- |
| **前提**  | **问题大小不变** 8        | **问题大小增加** 9            |
| **目标**  | 同样的工作量，跑得更快         | 同样的时间，跑更多的工作量 10        |
| **关注点** | **强可扩展性** 11        | **弱可扩展性** 12            |
| **视角**  | 悲观（受限于串行瓶颈）         | 乐观（规模换效益）               |
题型 1：考 Amdahl 定律

题目：假设一个程序的 80% 代码可以并行化，剩余 20% 必须串行。

(1) 如果使用 4 个处理器，理论加速比是多少？

(2) 哪怕你有无限个处理器，最大加速比是多少？

解析：

$\alpha = 0.8$, $1-\alpha = 0.2$。

(1) $k=4$。$S = \frac{1}{0.2 + 0.8/4} = \frac{1}{0.2 + 0.2} = \frac{1}{0.4} = 2.5$ 倍。

(2) $k=\infty$。$S = \frac{1}{0.2} = 5$ 倍。

题型 2：概念辨析

题目：为什么在这个 PPT 第29页的图中，加速比曲线有时会超过线性加速比（即 Super-linear）？

**答案**：这是由于**缓存效应 (Cache Effect)**。当使用更多处理器时，所有处理器的总缓存容量增加。如果数据集能完全装入这些分布式的缓存中，而无法装入单处理器的缓存中，内存访问延迟会大幅降低，导致计算速度的提升超过了处理器数量的增加倍数 。

这张图（PPT第5页）非常经典，两条线原本是并行的，后来分叉越来越大。
![[{54B906AC-0C95-4D8F-9F8E-4152C857C1E8}.png]]
- **现象**：
    
    - **灰色线 (HW FLOPS)**：硬件的计算能力（CPU速度）每2年增长3倍，呈指数级飞涨 。
        
    - **绿色线 (DRAM BW)**：内存带宽的增长速度远远慢于CPU，每2年只增长1.6倍 。
        
- **结论**：**CPU 和 内存 之间的性能差距日益扩大**。这就好比法拉利跑车（CPU）跑在乡村土路（内存）上，跑车再快也没用，因为路太堵。这道阻碍CPU性能发挥的屏障，就叫 **“存储墙”** 。

为了解决不同的矛盾，我们引入了两个中间层：

1. **虚拟存储器 (Virtual Memory)**：
    
    - **解决问题**：**容量** 。
        
    - **位置**：主存 和 辅存（硬盘）之间 。
        
    - **原理**：利用硬盘充当内存，让程序以为自己有很大的内存空间（逻辑地址）。
        
2. **Cache 存储系统**：
    
    - **解决问题**：**速度** 。
        
    - **位置**：CPU 和 主存 之间 。
        
    - **原理**：利用少量极快的 SRAM 缓存热点数据，缓解存储墙问题。

> **Q1 (简答/名词解释):** 什么是“存储墙” (Memory Wall)？
>  **参考答案：** 指随着技术发展，处理器（CPU）性能的提升速度远快于存储器（Memory）性能的提升速度，导致存储器带宽和延迟成为限制计算机系统整体性能的瓶颈。

> **Q2 (选择):** Cache 的引入主要是为了解决什么问题？虚拟存储器的引入主要是为了解决什么问题？ 
> **参考答案：** Cache 解决**速度**匹配问题；虚拟存储器解决**容量**问题。

> **Q3 (简答 - 高频):** 简述程序的局部性原理，并说明它分为哪两类。 
> **参考答案：** 程序的局部性原理指程序在执行时呈现出访问局部区域的规律。
> 
> 1. **时间局部性**：最近被访问的信息很可能在不久的将来再次被访问。
>     
> 2. **空间局部性**：某个存储单元被访问，其附近的存储单元也很可能在不久的将来被访问。

根据内存是大家**共用**还是**私有**，可以分为三类。这里有几个必须搞懂的缩写。

- **共享存储 (Shared Memory) —— 一个大锅饭** **（PPT 第 12 页）**
    
    - 所有处理器都能直接访问同一块物理内存。
        
    - **关键分类（必考）**：
        
        - **UMA (Uniform Memory Access, 统一内存访问)**：大家离锅的距离一样远，谁去盛饭（访问内存）花的时间都一样。常见于早期的多核。
            
        - **NUMA (Non-Uniform Memory Access, 非统一内存访问)**：现在的高性能服务器都是这个！内存分散在不同 CPU 旁边。CPU 访问**自己旁边**的内存很快，访问**别人旁边**的内存就慢。
            
    - **优点**：编程简单（变量大家都能看见）。
        
    - **缺点**：人多了抢锅铲（总线竞争），扩展性差，很难做到几百个核以上。
        
- **分布式存储 (Distributed Memory) —— 各自的饭盒** **（PPT 第 13 页）**
    
    - 每个处理器有自己**私有**的内存。
        
    - **通信**：如果我要你的数据，不能直接拿，必须发**消息**（Message Passing，比如 MPI）向你要。
        
    - **优点**：扩展性极强（可以几万台机器连起来）。
        
    - **缺点**：编程难（要显式地写发送/接收代码）。
        
- **混合架构 (Hybrid) —— 现在的超算** **（PPT 第 14 页）**
    
    - **宏观上**：分布式（很多台机器连起来）。
        
    - **微观上**：共享（每台机器内部是多核共享内存的）。
        
    - 也就是我们常说的 **MPI + OpenMP** 混合编程模式的基础。

> **Q1 (选择题):** 在 Flynn 分类法中，现代 GPU（图形处理器）主要属于哪一类？ A. SISD B. SIMD C. MISD D. MIMD **答案：** **B (SIMD)**。虽然现代 GPU 也有 MIMD 特性，但其核心计算模式是大量的核心同时执行相同的指令处理不同的像素点，是典型的 SIMD。

> **Q2 (辨析题):** 简述 UMA 和 NUMA 的主要区别。 **参考答案：**
> 
> - **UMA (统一内存访问)**：所有处理器访问内存中任何位置的时间都是相同的，通常通过共享总线实现。
>     
> - **NUMA (非统一内存访问)**：处理器访问本地内存（Local Memory）的速度比访问远程内存（Remote Memory，即其他处理器挂载的内存）要快。NUMA 解决了 UMA 的总线瓶颈问题，扩展性更好。
>     

> **Q3 (判断题):** 在分布式存储系统中，一个节点可以直接通过加载指令（Load Instruction）读取另一个节点内存中的数据。 
> **答案：** **错**。分布式存储中内存是私有的，必须通过网络接口进行显式的消息传递（Send/Receive）来交换数据。

**Q1 (计算题):** 假设一条指令分为取指、分析、执行 3 个阶段，每个阶段的时间都是 $\Delta t$。 (1) 若串行执行 100 条指令，需要多少时间？ (2) 若采用流水线执行，理论上需要多少时间？ **解析：** (1) 串行时间 = $100 \times (3 \Delta t) = 300 \Delta t$。 (2) 流水线时间 = 第一条指令完整时间 + 剩余指令 $\times$ 瓶颈节拍。 $T = 3 \Delta t + (100 - 1) \times \Delta t = 3 \Delta t + 99 \Delta t = 102 \Delta t$。 **加速比** $\approx 3$ 倍。

流水线把 CPI 降到了 1，还能更低吗？能！也就是一个周期执行多条指令（CPI < 1）。

1. **超标量 (Superscalar) —— 多车道高速公路** **（PPT 20-21页）**
    
    - **定义**：一个周期**同时**取多条指令、译码多条、执行多条 。
        
    - **对比**：
        
        - **标量**：单车道，一次过一辆车。
            
        - **超标量**：多车道，一次并排过几辆车。
            
    - **实现**：静态（VLIW，编译器排好） vs 动态（Superscalar，硬件自己排）。
        
2. **乱序执行 (Out-of-Order, OoO) —— 不许占着茅坑不拉屎** **（PPT 22-24页）**
    
    - **痛点**：按序执行（In-Order）时，如果第一条指令卡住了（比如在等内存数据），后面的指令就算能跑也得干等着 。
        
    - **解决**：**乱序执行**。只要指令所需的数据准备好了，就可以跳过前面卡住的指令先执行 。
        
    - **关键约束（PPT 24页图）**：虽然“执行”是乱序的，但最后的 **Commit（提交/写回结果）** 必须是**按序**的 (In-order) 。
        
    - _为什么要按序提交？为了保证程序逻辑正确，万一中间出错（中断/异常），能恢复到正确的状态。_
        
#### 🎯 **考题预测**

> **Q2 (简答题):** 简述乱序执行（Out-of-Order Execution）的基本思想，并解释为什么结果提交（Commit）阶段必须是按序的？ **参考答案：** * **思想**：允许将多条指令不按程序规定的顺序发送给执行单元，只要操作数准备好即可提前执行，以减少流水线阻塞 。
> 
> - **按序提交原因**：为了确保程序运行结果的正确性（精确异常处理），如果指令执行出错，需要能够恢复到出错前的状态；如果乱序提交，可能会导致寄存器状态不可逆地被错误更新。

#### 模块四：多线程 (Multithreading) —— 别让 CPU 闲着

**（对应 PPT 第 29 - 30 页）**

这里讲的是**硬件多线程**，目的是在单核里藏更多的任务，掩盖等待时间。PPT 30页的彩图非常直观，请重点看那张图。

1. **粗粒度多线程 (Coarse-grained)**：
    
    - **策略**：平时不切，只有遇到**大堵车**（比如 L2 Cache Miss，要等很久）才切换到另一个线程 。
        
    - **缺点**：对于短时间的等待（小堵车），切换的开销划不来 。
        
2. **细粒度多线程 (Fine-grained)**：
    
    - **策略**：**每个时钟周期**都强制轮转切换线程 。
        
    - **优点**：完全隐藏了所有等待。
        
    - **缺点**：单线程跑得慢了（因为总是被打断） 。
        
3. **同时多线程 (SMT / Simultaneous Multithreading)** —— **最强王者** **（PPT 29页底部 & 30页最右图）**
    
    - **策略**：也就是 Intel 的 **超线程 (Hyper-threading)**。
        
    - **原理**：在一个时钟周期内，同时发射**不同线程**的指令给不同的执行单元 。
        
    - **图解**：PPT 30页最右边的图，你会发现红、绿、黄、褐四个线程的指令**塞满**了同一个周期的不同槽位，没有任何空闲（白色格子最少）。这就是压榨性能的极致。
        

#### 🎯 **考题预测（难点辨析）**

> **Q5 (辨析题):** 细粒度多线程与同时多线程 (SMT) 有什么本质区别？ **参考答案：**
> 
> - **细粒度多线程**：在**不同**的时钟周期轮流执行不同线程的指令（纵向并发）。 * **SMT**：在**同一个**时钟周期内，可以同时发射并执行来自**不同**线程的指令（纵向+横向并发），利用了超标量的多发射能力，资源利用率更高 。


#### 模块三：赌博与批处理 —— 预测执行与 SIMD

**（对应 PPT 第 25 - 28 页）**

1. **预测执行 (Speculative Execution) —— 赌一把** **（PPT 25-26页）**
    
    - **场景**：遇到 `if-else` 分支，不知道该走哪条路。
        
    - **策略**：不管了，猜一条路（通常猜大概率发生的）先跑着。猜对了就赚了（流水线没断），猜错了就回滚 。
        
    - **副作用**：大名鼎鼎的 **Meltdown (熔断)** 和 **Spectre (幽灵)** 漏洞就是利用了预测执行留下的痕迹来窃取数据 。
        
2. **向量指令 (SIMD) —— 批处理** **（PPT 27-28页）**
    
    - **定义**：一条指令处理一堆数据。比如 `c = a + b`，一次性把一个数组的 `a` 和 `b` 全加了 。
        
    - **例子**：Intel 的 **SSE** (128位)、**AVX** (256位/512位) 。
        
    - **编程注意**：数据最好是**连续**的，且**对齐 (Cache Aligned)** 。

#### . 为什么是多核？

**（PPT 32 页）**

- **根本原因**：还是那个**功耗墙**。单核频率上不去了，只能靠堆核心数量来提升性能（横向扩展）。
    
- **典型结构**：
    
    - **L1 Cache (私有)**：指令(i-cache)和数据(d-cache)通常是分开的。
        
    - **L2 Cache (私有/统一)**：每个核自己用 。
        
    - **L3 Cache (共享)**：所有核共用一块大的 L3，这是多核通信的重要场所 。
        

#### 2. 核怎么连？—— 总线 vs. 片上网络

**（PPT 33 页）**

- **总线共享 (Bus Shared)**：
    
    - **原理**：所有核挂在一根线上。
        
    - **优点**：简单。
        
    - **缺点**：**扩展性差**。核多了线就堵了 。
        
- **片上网络 (NoC / On-chip Network)**：
    
    - **原理**：像互联网一样，每个核是一个路由器节点，数据包在格子里跳（Mesh结构，PPT右下角图）。
        
    - **优点**：**扩展性好**，带宽大。
        
    - **缺点**：复杂 。

### 模块二：两大拦路虎 —— 一致性与连贯性 (必考难点！)

**（对应 PPT 第 34 - 36 页）**

这两个词中文翻译很像，但含义完全不同，是**辨析题**的超级考点。

#### 1. 存储一致性 (Memory Consistency) —— 顺序问题

**（PPT 34 页）**

- **核心问题**：**“大家看到的读写顺序是一样的吗？”**
    
- **场景**：核 A 先写了变量 X，再写变量 Y。核 B 能不能保证先看到 X 变了，再看到 Y 变了？如果乱序执行导致核 B 先看到 Y 变了，程序逻辑就崩了 。
    
- **一句话总结**：保证**不同内存地址**的操作顺序在所有核看来是一致的。
    

#### 2. 缓存连贯性 (Cache Coherence) —— 最新值问题

**（PPT 35 - 36 页）**

- **核心问题**：**“我读到的是不是最新的？”**
    
- **场景**：变量 `a` 在主存里是 0。核 A 把它读进 Cache 改成了 1。核 B 去读 `a`，如果它读的是主存里的旧值 0，那就出错了。
    
- **一句话总结**：保证**同一个内存地址**的最新写入值能被所有核看到 。
    
- **解决方案**：
    
    - **MESI 协议**：给 Cache Line 打标签（修改、独占、共享、无效）。
        
    - **硬件实现**：侦听协议 (Snooping) —— 大家都在总线上偷听，一旦有人改了数据，我就把我的作废 。
        

#### 🎯 **考题预测（重中之重）**

> **Q1 (辨析题):** 请简述 Cache Coherence（连贯性）和 Memory Consistency（一致性）的区别。 **参考答案：**
> 
> - **Cache Coherence (连贯性)**：关注的是**同一个数据项**在多个 Cache 副本中的数值是否一致。保证写操作能被其他核心看见。
>     
> - **Memory Consistency (一致性)**：关注的是**不同数据项**的读写操作在所有处理器眼中是否遵循相同的**顺序**。
>     

> **Q2 (选择题):** 在多核处理器中，MESI 协议主要用于解决什么问题？ A. 流水线冲突 B. 缓存连贯性 (Cache Coherence) C. 存储一致性 (Memory Consistency) D. 虚存地址映射 **答案：** **B**。

- **操作系统的并发**：
    
    - **目标**：**吞吐率**和**公平性**。
        
    - **场景**：同时跑 QQ、微信、浏览器。系统要保证大家都能动，别卡死。
        
- **并行程序的并发**：
    
    - **目标**：**最小化执行时间**（跑得越快越好）。
        
    - **场景**：一个程序内部拆成很多个小任务一起跑。
- **【辨析/简答题】 (重要程度：⭐⭐⭐⭐⭐)**
    
    - **题目**：请简述“数据并行”与“任务并行”的区别，并各举一个计算机领域的例子。
        
    - **标准答案思路**：
        
        - **区别**：数据并行是多个处理单元对**不同的数据子集**执行**相同的操作**；任务并行是多个处理单元执行**不同的计算任务**（可能处理相同或不同的数据）。
            
        - **例子**：
            
            - _数据并行_：图像处理中，对一张图片的每个像素点同时进行“灰度化”处理；矩阵乘法。
                
            - _任务并行_：浏览器中，一个线程负责下载文件，另一个线程负责渲染网页，第三个线程响应用户鼠标点击。
                
- **【选择题】**
    
    - **题目**：以下哪种场景最适合使用数据并行模式？
        
    - A. 编译器同时进行词法分析、语法分析和代码生成
        
    - B. 操作系统同时运行Word和Excel
        
    - C. 对一个包含10亿个浮点数的数组进行每个元素加1的操作
        
    - D. Web服务器同时处理登录请求和数据库查询
        
    - **答案**：C。（其他选项更多体现的是任务并行或流水线）。
        
- **【填空题】**
    
    - **题目**：在并行编程中，如果将一个大数组切分为若干小块分配给不同线程，且每个线程执行相同的计算逻辑，这种模式称为________。
        
    - **答案**：数据并行 (Data Parallelism)。
#### **1. 设计空间设计空间：并行编程的四个层次 (Page 6) ★★★重点**

在并行编程中，我们不是直接写代码，而是从上到下经过四个阶段。这就像盖房子：先想怎么分工，再想施工流程，然后选工具，最后管工人。

- **寻找并发性 (Finding Concurrency)**：这是第一步，负责把问题拆开。包括**任务分解**（把大活拆成小活）和**数据分解**（把大数据拆成小块） 。
    
- **算法结构 (Algorithm Structure)**：决定活儿怎么干。比如用**分治**（递归拆分）、**流水线**（像生产线一样）、或者**事件协作** 。
    
- **支持结构 (Support Structure)**：这是程序的框架模式。常见的有 **Master/Worker**（一个主控，多个打工的）和 **SPMD**（单程序多数据） 。
    
- **实现机制 (Implementation Mechanism)**：最底层。涉及**进程/线程的管理**，以及如何利用**共享队列**或**分布式队列**进行交互 。
    

#### **2. 并行程序的实现方法 (Page 7) ★★重点**

这里区分了两种并行的实现逻辑，**“隐式” vs “显式”**。

- **隐式并行 (Implicit Parallelism)**：
    
    - **特点**：程序员不用管，全靠硬件和编译器自动搞定。
        
    - **技术手段**：指令级并行（超标量）、向量指令、硬件多线程等 。
        
- **显式并行 (Explicit Parallelism)**：
    
    - **特点**：程序员得亲自动手划分任务、同步通信 。
        
    - 具体实现工具对比 ：
        

|**实现方式**|**实例**|**优点**|**缺点**|
|---|---|---|---|
|**库例程**|MPI, Pthreads|容易使用（API直接调），性能高|细节太碎（要自己写同步和通信）|
|**编译器注释**|**OpenMP**, OpenACC|简单（一行 `pragma` 搞定），移植性好|受编译器限制，灵活性稍差|
|**语言扩展**|C++11, Java|性能高，极其灵活|门槛高，得掌握语言高级特性|

#### **3. 三种显式并行的代码“长相” 

- **Pthreads (库例程)**：代码比较“冗长”。你需要初始化属性 `pthread_attr_init`，然后显式创建线程 `pthread_create` 。这属于“精细化管理”，适合架构师。
    
- **OpenMP (编译器注释)**：最简单的！只需要在 `for` 循环前加一行 `#pragma omp parallel for` 。编译器看到这行，会自动把数组加法任务分摊给多个核心 。
    
- **C++11 (语言扩展)**：现代感更强。通过 `std::thread` 直接启动一个对象任务 。、

- **【简答/分析题】 (重要程度：⭐⭐⭐⭐⭐)**
    
    - **题目**：请说明并行编程“设计空间”的四个层次，并解释“寻找并发性”层的主要工作。
        
    - **参考答案**：四个层次为：寻找并发性、算法结构、支持结构、实现机制 。寻找并发性层的主要工作是理解问题域，进行**任务分解**和**数据分解**，识别出可以并行运行的潜在子任务 。
        
- **【比较题】 (重要程度：⭐⭐⭐⭐)**
    
    - **题目**：对比 OpenMP 和 Pthreads 两种并行编程方式的优缺点。
        
    - **参考答案**：OpenMP 基于编译器注释，优点是开发效率极高、代码简洁且易于移植 。缺点是灵活性较差。Pthreads 是基于库的线程管理，优点是极其灵活、性能高，但缺点是程序员必须手动处理所有同步和通信细节，开发复杂度大 。
        
- **【辨析题】 (重要程度：⭐⭐⭐)**
    
    - **题目**：判断并说明理由：在并行程序设计中，性能目标与操作系统的并发性能目标是一致的。
        
    - **参考答案**：错误 。操作系统的目标是公平分配资源，提高系统吞吐率和响应时间 ；而并行编程的目标是最小化单个应用程序的执行时间，即极致的加速比 。

### 🔍 补充考题预测 1：Gustafson 定律计算（对比阿姆达尔）

这道题是为了考你是否真的理解了“两个定律算出来结果完全不同”。

 **题目：** 假设一个程序的串行比例 $F = 5\%$（即 $0.05$），并行部分为 $95\%$。现在使用 $64$ 个处理器 ($n=64$)。

1. 根据 **阿姆达尔定律 (Amdahl's Law)**，加速比是多少？
>     
2. 根据 **Gustafson 定律**，加速比是多少？
>     
 3. 为什么两者的结果差距这么大？     
> 
> **解析：**
> 
 4. 阿姆达尔定律（固定问题规模）：
>     
>     $$S = \frac{1}{F + \frac{1-F}{n}} = \frac{1}{0.05 + \frac{0.95}{64}} \approx \frac{1}{0.05 + 0.0148} \approx \frac{1}{0.0648} \approx \mathbf{15.4}$$
      (你看，哪怕用了64个核，加速比才15倍，很悲观)
>     
 5. Gustafson 定律（扩大问题规模）：
>     
>     公式：$S = n - F(n-1)$ 
>     
>     $$S = 64 - 0.05 \times (64 - 1) = 64 - 0.05 \times 63 = 64 - 3.15 = \mathbf{60.85}$$     
>     (这就很乐观了，接近理想的64倍)
>     
 6. **原因分析**：阿姆达尔定律假设**问题规模不变**，增加处理器导致每个处理器分到的计算量太少，通信和串行瓶颈占比飙升；而 Gustafson 定律假设**时间不变，问题规模变大**，计算量增加了，串行部分占比相对被稀释了，所以效率更高。
>

### 🔍 补充考题预测 3：图表分析（效率为什么下降？）

基于 PPT 第 30 页的那张交叉曲线图。

 **题目：** 观察并行效率（Efficiency）随处理器数量增加的变化曲线，通常会发现效率逐渐下降（即 $E_p < 1$ 且越来越小），请简述导致效率下降的三个主要原因。
> 
 参考答案：
> 
 1. 通信开销 (Communication Overhead)：处理器越多，互相传输数据的时间越多，这部分时间不做计算 4。
> 
 2. 同步开销 (Synchronization Overhead)：进程间需要互相等待（比如 Barrier），快的要等慢的。
> 
3. 负载不均衡 (Load Imbalance)：任务很难完美平均分配，导致部分处理器闲置。
> 
 4. 串行部分 (Serial Fraction)：根据阿姆达尔定律，串行部分始终存在，无法被加速。

**1. 调度算法辨析**

> 题目：下列哪个不是基于块的自调度算法？
> 
> A. GSS (Guided Self-Scheduling)
> 
> B. TSS (Trapezoid Self-Scheduling)
> 
> C. FSS (Factoring Self-Scheduling)
> 
> D. 工作窃取 (Work Stealing)
> 
> **答案**：**D**

> **💡 详细解析**：
> 
> - **考点**：`PPT 4. 并行编程的关键问题` 中的循环调度策略。
>     
> - **辨析**：GSS、TSS、FSS 都是专门针对**循环（Loop）**的调度算法，它们的共同点是通过特定的数学公式计算每一次分配给线程的**“块（Block/Chunk）”**的大小。
>     
>     - GSS：块大小指数递减。
>         
>     - TSS：块大小线性递减（梯形）。
>         
>     - FSS：分批次分配，每批次大小减半。
>         
> -  **为什么选D** ：**工作窃取**  是一种通用的 **负载均衡（Load Balancing）** 策略，指的是空闲线程主动去“偷”忙碌线程的任务，它不是一种计算循环块大小的静态/半动态公式。

**6. Amdahl vs Gustafson 定律 (核心)**

> 题目：下列关于Amdahl和Gustafson定律的描述不正确的是？
> 
> A. Amdahl定律追求程序在相同的工作负载下更快运行
> 
> B. Gustafson定律追求程序在相同运行时间内实现更大的工作负载
> 
> C. Amdahl定律追求强可扩展性，Gustafson定律关注弱可扩展性
> 
> D. Amdahl定律关注弱可扩展性，Gustafson定律追求强可扩展性
> 
> **答案**：**D**
> 
> **💡 详细解析**：
> 
> - **考点**：`PPT 1. 并行编程概述` 性能评估。
>     
> - **Amdahl定律**：固定问题规模（Fixed Size），通过增加核数来缩短时间 $\rightarrow$ **强可扩展性 (Strong Scaling)**。
>     
> - **Gustafson定律**：固定时间（Fixed Time），通过增加核数来处理更大的问题规模 $\rightarrow$ **弱可扩展性 (Weak Scaling)**。
>     
> - **结论**：D选项把两个定律对应的可扩展性类型**说反了**，所以选D。

**7. 加速比与效率公式**

> 题目：假设程序串行执行的时间是T1，p个处理单元并行执行该程序的时间是Tp，那么加速比和并行效率的计算公式为？
> 
> A. 加速比Tp/T1，并行效率Tp/T1/p
> 
> B. 加速比T1/Tp，并行效率Tp/T1/p
> 
> C. 加速比T1/Tp，并行效率T1/Tp/p
> 
> D. 加速比Tp/T1，并行效率T1/Tp/p
> 
> **答案**：**C**
> 
> **💡 详细解析**：
> 
> - **考点**：`PPT 1. 并行编程概述` 公式背诵。
>     
> - **加速比 (Speedup)**：$S = \frac{T_{\text{serial}}}{T_{\text{parallel}}} = \frac{T_1}{T_p}$ （通常 $S \ge 1$）。
>     
> - **效率 (Efficiency)**：$E = \frac{S}{p} = \frac{T_1/T_p}{p} = \frac{T_1}{T_p \times p}$ （通常 $0 < E \le 1$）。
>     
> - **对应选项**：C 选项的写法 `T1/Tp/p` 数学上等同于 `T1/(Tp*p)`，是正确的。
>

> **💡 详细解析**：
> 
> - **考点**：`PPT 0/1`。
>     
> - **解释**：凡是计算量巨大、需要数值模拟的科学工程领域都是并行计算的“客户”。
>     

---

#### 二、 填空题

**1. 同步操作种类**

> **题目**：同步操作包括 `____`、`____`、`____`、`____` 四种。
> 
> **答案**：**栅栏 (Barrier)**、**锁 (Lock)**、**信号量 (Semaphore)**、**同步通信操作**
> 
> **💡 考点**：`PPT 4. 并行编程的关键问题`。这是同步机制的四大金刚，背下来即可。

**2. 任务划分方式**

> **题目**：并行程序的任务划分方式包括 `____` 和 `____` 两种。
> 
> **答案**：**域分解 (Domain Decomposition)**、**功能分解 (Functional Decomposition)**
> 
> **💡 考点**：`PPT 3. 并行编程方法`。
> 
> - **域分解**：按“数据”切分（如切分矩阵、切分图像）。
>     
> - **功能分解**：按“任务逻辑”切分（如流水线，一人一道工序）。
>

#### 三、 判断题

**1. 调度的定义**

> **题目**：调度是指将指线程分配给硬件处理单元。
> 
> **答案**：**正确** (True)
> 
> **💡 考点**：`PPT 4`。调度的本质就是 Mapping（映射），决定哪个 Software Thread 跑在哪个 Hardware Core 上。

**2. CPU亲和性 (Affinity)**

> **题目**：不恰当的CPU亲和性设置可能会导致线程迁移到不同核心时丢失缓存数据，以及NUMA系统中不对等的访存开销。
> 
> **答案**：**正确** (True)
> 
> **💡 考点**：`PPT 5. 多线程编程`。
> 
> - **原理解析**：如果线程频繁在不同核心间跳来跳去（迁移），新核心的 Cache 里没有旧核心的数据（Cold Cache），性能会大跌。在 NUMA 架构下，线程跑到远端 CPU 上去访问内存，延迟会更高。所以设置“亲和性”（绑核）很重要。

### 🌟 总结：OpenMP 必背清单

1. **三大子句**：`private` (不初始化，不写回), `firstprivate` (初始化), `lastprivate` (写回)。
    
2. **核心指令**：`parallel for`, `barrier`, `critical`, `master`, `single`。
    
3. **计算归约**：`reduction(+:sum)`。
    
4. **坑点**：`parallel` 结束时必须同步（不能 nowait）；`goto` 不能乱跳。
    

## 一、 单项选择题

### 1. OpenMP 的基本模型

> **题目**：OpenMP是基于 `____` 的并行编程模型 A. 协程 B. 线程 C. 进程 D. 以上均不是

- ✅ **答案**：**B**
    
- **💡 解析**：OpenMP (Open Multi-Processing) 是专为**共享内存系统**设计的**多线程**编程接口。
    
    - _对比_：MPI 是基于进程（Process）的。
        

### 2. 结构块 (Structured Block) 定义

> **题目**：下列两段代码属于结构块的是？
> 
> - **代码段1**：从外部 `goto` 跳入并行域。
>     
> - **代码段2**：从并行域内部 `goto` 跳出。
>     
> 
> A. 代码段1 B. 代码段2 C. 代码段1和代码段2 D. 两个代码段均不是

- ✅ **答案**：**D**
    
- **💡 解析**：OpenMP 对“结构块”有严格定义：**必须是单入口、单出口**。
    
    - **严禁**使用 `goto` 从块外跳入块内，或从块内跳出块外（除非是直接终止程序的 `exit`）。
        

### 3. 编译制导标识符

> **题目**：C程序使用OpenMP时正确的编译制导语句标识符是 A. !$omp B. $omp C. \#pragma omp D. \#omp

- ✅ **答案**：**C**
    
- **💡 解析**：
    
    - **C/C++**：`#pragma omp <directive> [clauses]`
        
    - **Fortran**：`!$omp` 或 `C$omp`
        

### 4. 编译选项 (Linux/GCC)

> **题目**：linux系统中，gcc编译器编译使用OpenMP的C语言并行程序时，需要添加的编译选项是 A. -omp B. -openmp C. -fomp D. -fopenmp

- ✅ **答案**：**D**
    
- **💡 解析**：标准命令示例：`gcc -fopenmp main.c -o main`。
    

### 5. Private 变量的作用域 (易错⭐)

> **题目**：执行下述代码后，最终输出的 val 值是？ （主线程 `val=10` -> 进入 `parallel private(val)` -> 内部修改 -> 退出并行域） A. 0 B. 1 C. 2 D. 10

- ✅ **答案**：**D**
    
- **💡 解析**：
    
    - `private(val)` 会在每个线程内创建一个**新的、未初始化**的局部变量。
        
    - 它**不继承**外部 `val` 的初值（除非用 `firstprivate`）。
        
    - 退出并行域后，外部的 `val` **保持原值不变**（除非用 `lastprivate`）。
        

### 6. 隐式 Barrier (Implicit Barrier)

> **题目**：下列哪个语句包含的结构块结束时 **没有** barrier 同步语句？ A. \#pragma omp parallel B. \#pragma omp for C. \#pragma omp master D. \#pragma omp single

- ✅ **答案**：**C**
    
- **💡 解析**：
    
    - `master` 指令只由主线程（Thread 0）执行，其他线程直接跳过，**不存在同步等待**。
        
    - `parallel`、`for`、`single` 结束时默认都有隐式栅栏。
        

### 7. 线程私有全局变量

> **题目**：下列哪个指令或子句用来将某个全局变量或静态变量声明为各个线程（不仅仅是并行域）私有？ A. private B. threadprivate C. firstprivate D. lastprivate

- ✅ **答案**：**B**
    
- **💡 解析**：
    
    - `private`：仅在当前代码块内有效。
        
    - `threadprivate`：**生命周期贯穿整个程序**，通常用于全局变量，每个线程拥有一份持久的拷贝。
        

### 8. 变量初始化 (Input)

> **题目**：下列哪个子句能够实现：并行域内的私有变量使用并行域外的同名变量初始化 A. firstprivate B. private C. lastprivate D. threadprivate

- ✅ **答案**：**A**
    
- **记忆技巧**：**First** (进入时) **Private** = 继承初值。
    

### 9. 变量写回 (Output)

> **题目**：下列哪个子句能够实现：并行域内的私有变量经过计算后，在退出并行域时，将其值赋给并行域外的同名变量 A. firstprivate B. private C. threadprivate D. lastprivate

- ✅ **答案**：**D**
    
- **记忆技巧**：**Last** (最后一次迭代) **Private** = 写回旧值。
    

### 10. Reduction 语法

> **题目**：对并行域中某个共享变量实现正确的规约运算，需要用到reduction子句，下列使用方法正确的是 A. reduction (+:sum) B. reduction (sum:+) C. reduction [+:sum] D. reduction [sum:+]

- ✅ **答案**：**A**
    
- **语法**：`reduction(operator : list)`，例如 `reduction(+:sum)` 或 `reduction(*:prod)`。

## 二、 填空题 (代码与概念)

### 基础概念类

1. **编译制导语句构成**：前缀 (`#pragma`)、**指导指令** (`directive`)、**子句** (`clause`)。
    
2. **执行模式**：OpenMP 采用 **Fork-Join** 并行执行模式。
    
3. **指令分类**：并行域指令、**工作共享指令**、**同步指令**、**数据环境指令**。
    
4. **Schedule类型**：static、**dynamic**、**guided**、**runtime** (或 auto)。
    

### 代码补全类

**11. 动态调度**

> 题目：使用块大小为2的动态调度方式 代码：`#pragma omp parallel for ... schedule(____)`

- ✅ **答案**：**`dynamic, 2`**
    
- **解析**：`schedule(type, chunk_size)`。
    

**12. 规约与线程数**

> 题目：使得规约运算可以正确完成，且设置并行域中的线程数为8 代码：`#pragma omp parallel for ____ ____`

- ✅ **答案**：**`reduction(+:sum)`** 和 **`num_threads(8)`**
    

**13. Master 与 Single**

> 题目：第一段for循环仅由主线程执行，第二段for循环仅由最先到达的线程执行。 代码： `#pragma omp parallel` `{` `#pragma omp ____ { ... }` (第一段) `#pragma omp barrier` `#pragma omp ____ { ... }` (第二段) `}`

- ✅ **答案**：
    
    1. **`master`** (主线程)
        
    2. **`single`** (单线程执行)
        

**14. 计时函数**

> 题目：获取开始和结束时间 代码：`double start = ____;`

- ✅ **答案**：**`omp_get_wtime()`**
    
- **解析**：这是 OpenMP 标准的计时函数，返回双精度浮点数（秒）。

## 三、 判断题

1. **Ordered 语句**
    
    > 在parallel for语句中，想要指定一段代码任何时候只能有一个线程执行，且要按照线程ID顺序运行，可以用ordered语句。
    
    - ✅ **正确**
        
    - **解析**：`ordered` 强制串行顺序，通常用于打印日志或按序处理。
        
2. **Nowait 与 Parallel (核心坑点)**
    
    > parallel语句指定的结构块后的隐式barrier可以通过nowait子句去除。
    
    - ❌ **错误**
        
    - **解析**：**绝对不行！** `parallel` 区域结束时，所有线程必须汇合（Join）。`nowait` 只能用于 `for`、`sections`、`single` 等工作共享结构。
        
3. **Master 语句**
    
    > master语句指定的结构块仅由主线程执行。
    
    - ✅ **正确**
        
    - **解析**：Master 即 Thread ID 0。
        
4. **Critical 互斥性**
    
    > 使用critical语句时，不同名字命名的临界区是互斥的。
    
    - ❌ **错误**
        
    - **解析**：
        
        - `critical(NameA)` 和 `critical(NameA)` **互斥**。
            
        - `critical(NameA)` 和 `critical(NameB)` **不互斥**（可并发执行）。
            
        - 这允许程序员对不同的资源使用不同的锁，提高并行度
