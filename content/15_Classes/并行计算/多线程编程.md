### 1. 进程 (Process) 的本质 [PPT P4]

考研 408 和期末考中最经典的定义，请务必背熟：

- **定义**：进程是程序在操作系统里的一次**执行**，是操作系统**资源分配**的基本单位 。
    
- **UNIX 进程包含的资源** ：
    
    - **标识符**：进程ID (PID)、用户ID (UID)、组ID (GID)。
        
    - **上下文**：寄存器 (Registers)、程序计数器 (PC)。
        
    - **内存区域**：
        
        - **Text (代码段)**：存放程序指令。
            
        - **Data (数据段)**：存放全局变量。
            
        - **Heap (堆区)**：动态分配的内存 (malloc/new)。
            
        - **Stack (栈区)**：函数调用栈、局部变量。
            
    - **环境与IO**：工作目录、环境变量、文件描述符 (File Descriptors)、动态库等。

### 2. 线程的内存模型 (核心考点) [PPT P5]

Page 5 的图示非常直观地展示了引入多线程后，进程地址空间（User Address Space）发生了什么变化。

**核心逻辑：** 线程寄生在进程内部，它们**共享**进程的大部分资源，但必须保留**独立**的执行流信息。

#### 🔴 线程独享 (Private) —— 必须独立，否则乱套

为了让每个线程能独立执行函数代码，它们必须拥有独立的：

1. **Stack (栈)** ：存放该线程执行过程中的局部变量 (var1, var2)、函数参数、返回地址。如果不独立，线程A的函数调用会覆盖线程B的数据。
    
2. **Registers (寄存器)** ：
    
    - **Program Counter (PC)**：记录当前线程执行到了哪一行指令。
        
    - **Stack Pointer (SP)**：记录当前栈顶位置。
        

#### 🟢 线程共享 (Shared) —— 通信的基础

同一进程内的所有线程共享以下资源（这也使得线程间通信比进程间通信更容易）：

1. **Text (代码段)** ：所有线程执行同一套代码（函数）。
    
2. **Data (全局数据)** ：全局变量 (arrayA, arrayB) 对所有线程可见。**注意：这也是线程不安全问题的根源！**
    
3. **Heap (堆)** ：动态申请的内存是共享的。
    
4. **OS 资源** ：进程ID、打开的文件 (Files)、锁 (Locks)、套接字 (Sockets)。

> **答案：错误**。 **解析**：**进程**是资源分配的基本单位；**线程**是**CPU调度**（或指令执行）的基本单位。

### . 为什么要用线程？(核心优势) [PPT P6]

PPT 第6页放了一张密密麻麻的表格，你不需要背数据，只需要看懂它的**核心结论**：

**📊 数据解读**： 表格对比了在不同硬件平台上，创建一个进程 (`fork()`) 和创建一个线程 (`pthread_create()`) 所花费的时间。

- 例如第一行：创建进程需要 **8.1秒**，而创建线程只需要 **0.9秒**。
    
- **结论**：线程的创建速度比进程快 **10倍甚至100倍**。
    

**🌟 四大优势 (必背)**：

1. **开销小 (Lightweight)** ：
    
    - 创建/销毁线程比进程快得多（因为不需要复制整个页表、文件描述符表等）。
        
    - 线程切换（Context Switch）也比进程切换快。
        
2. **通信方便 (Communication)** ：
    
    - 因为共享数据段和堆，线程间通信可以直接读写变量（Shared Memory）。
        
    - 对比：进程间通信 (IPC) 需要管道、消息队列等复杂机制，开销大。
        
3. **多核高效 (Multi-core Efficiency)** ：
    
    - 在多核CPU上，多个线程可以真正**并行**运行（分别跑在不同核上），显著提升计算密集型任务的速度。
        
4. **改善程序结构** ：
    
    - 可以将复杂的长任务（如GUI界面的后台下载）剥离到独立线程，避免主界面卡死。

### 2. 什么时候适合用多线程？[PPT P7 上半部分]

并不是所有程序都适合多线程，PPT 列出了**三种典型场景**：

1. **可分片并发执行的任务** ：
    
    - 例如：计算两个巨型矩阵相乘，可以将矩阵切成块，每个线程算一块。
        
2. **I/O 密集型任务** ：
    
    - 例如：数据库查询、网络请求。当一个线程在等待 I/O 返回时，CPU 可以切换去跑其他线程，掩盖等待时间（Latency Hiding）。
        
3. **混合型任务** ：
    
    - 某些部分吃 CPU，某些部分吃 I/O，多线程可以平衡负载。

### 3. 多线程协作模型 (核心考点) [PPT P7 下半部分]

这是多线程程序设计的**架构模式**，非常容易出**应用题**或**选择题**。

A. 经理/工人模型 (Manager/Worker)

- **机制**：
    
    - **主线程 (Manager)**：负责接收请求、打包任务，将任务扔进“任务队列”。
        
    - **子线程 (Worker)**：只负责从队列里取任务干活。
        
- **特点**：职责分离，最常用的服务器模型（如 Web Server）。
    

B. 流水线模型 (Pipeline)

- **机制**：
    
    - 将一个大任务拆分为步骤 A -> B -> C。
        
    - 线程 1 专做 A，做完传给线程 2；线程 2 专做 B... 就像工厂流水线。
        
- **特点**：适合步骤清晰、数据流向固定的处理（如视频解码：读取 -> 解码 -> 渲染）。
    

C. 对等模型 (Peer)

- **机制**：
    
    - 跟 Manager/Worker 类似，但主线程在分发完任务后，**自己也下场干活**，变成了 Worker 的一员。
        
- **特点**：所有线程地位平等，最大化利用主线程的计算力。

**Q1:** 请简述线程相比于进程的主要优势，并说明为什么线程间通信比进程间通信更方便？

> **参考答案**：

### 1. 线程安全 (Thread Safety) [PPT P8]

这是多线程编程的“雷区”，也是考试和面试的**绝对重点**。

#### ⚠️ 什么是“不安全”？

PPT P8 的图示非常经典：

- **场景**：Thread 1, 2, 3 同时调用 `subA` 函数。
    
- **问题**：它们都试图修改同一个全局内存地址 `0x4450A` 1。
    
- **后果**：如果三个线程同时读写这个变量，会导致**数据竞争 (Data Race)**，最终结果不可预测（脏数据）。
    

#### ✅ 核心概念 (必背)

1. **程序员的责任**：
    
    - 所有线程共享进程的全局资源。
        
    - **必须**由程序员负责保证对共享数据的**同步访问** 2。操作系统不会自动帮你锁住数据。
        
2. **线程安全的定义**：
    
    - 一个函数被称为“线程安全”的，是指它被多个线程同时调用时，能够正确地处理共享数据，不会出现逻辑错误。
        
    - **注意**：这不仅指你写的函数，还包括你调用的**库函数** 3。
        
3. **库函数的使用原则**：
    
    - 在不确定某个第三方库是否支持多线程时，必须**假设它不支持** 4。
        
    - 这意味着如果不加锁，就只能按“顺序”方式（单线程）调用该库 5。
        
4. **资源限制**：
    
    - **最大线程数量**：系统能创建的线程数是有限的 6。
        
    - **堆栈大小**：每个线程都有独立的栈，线程太多会导致内存耗尽 7。

### 2. 线程池技术 (Thread Pool) [PPT P9]

为了解决“频繁创建销毁线程”带来的开销，工业界普遍使用线程池。

#### 📉 痛点：为什么要用线程池？

- **传统做法**：来一个任务 -> `create` 线程 -> 运行 -> `exit` 销毁。
    
- **缺点**：
    
    - 如果任务执行时间很短（比如处理一个简单的 HTTP 请求），那么**创建和销毁线程的时间**甚至可能超过**执行任务的时间** 8。
        
    - 系统频繁分配和回收资源，开销巨大。
        

#### ⚙️ 线程池原理 (机制)

PPT P9 的架构图清晰地展示了标准模型：

1. **初始化**：程序启动时，一次性创建 $n$ 个线程放入池中（Thread Pool） 9。
    
2. **任务提交**：
    
    - **Task Submitters**（提交者）：不断产生新任务。
        
    - **Task Queue**（任务队列）：任务排队等待执行 10。
        
3. **循环执行**：
    
    - 线程池里的线程是**复用**的。它们从队列取任务 -> 执行 -> **不销毁，放回池中**等待下一个任务 11。
        

#### 🌟 核心优势

- **降低资源消耗**：通过重复利用已创建的线程，降低线程创建和销毁造成的消耗。
    
- **提高响应速度**：任务到达时，无需等待线程创建即可立即执行。

#### 题型 1：名词解释/简答 (必考)

**Q1:** 什么是“线程安全”？如果一个第三方库函数不是线程安全的，在多线程程序中应该如何使用它？

> **参考答案**：
> 
> 1. **线程安全**：指多个线程同时访问同一个对象或函数时，如果不进行额外的同步控制，或者在调用方进行任何其他的协调操作，调用这个对象的行为依然能获得正确的结果。
>     
> 2. **如何使用**：如果库函数线程不安全，必须通过**外部加锁**（如 Mutex）来保证同一时刻只有一个线程调用该函数；或者将其限制在单线程中顺序调用。
>     

#### 题型 2：设计/计算题

Q2: 某服务器每秒收到 1000 个请求，每个请求处理耗时 5ms。如果为每个请求创建一个新线程，创建+销毁线程耗时 2ms。

(1) 请计算在不使用线程池的情况下，处理一个请求的总开销占比是多少？

(2) 使用线程池的主要目的是什么？

> 参考答案：
> 
> (1) 总时间 = 5ms + 2ms = 7ms。额外开销占比 = 2 / 7 ≈ 28.6%。
> 
> (2) 目的：复用线程，消除创建和销毁线程的 2ms 开销，降低系统负载，防止内存耗尽（控制并发数）。

#### 题型 3：判断题

**Q3:** 只要使用了多线程，程序运行速度一定比单线程快。

> 答案：错误。
> 
> 解析：如果任务量小且创建线程开销大，或者存在严重的线程竞争（锁等待），多线程反而可能更慢。

### 1. 什么是 Pthreads? [PPT P11]

#### 📜 历史背景 (为什么要有它？)

在 1995 年之前，各个软硬件厂商（如 IBM, Intel, Sun）都有自己私有的多线程实现 。

- **痛点**：如果你写了一个多线程程序，换台机器可能就跑不起来了，移植性极差 。
    
- **解决方案**：IEEE 在 1995 年制定了标准 **POSIX 1003.1c** 。遵循这个标准的实现就叫 **POSIX Threads**，简称 **Pthreads** 。
    

#### 💻 编程基础 (必考实操)

要把多线程代码跑起来，你必须记住以下两点：

1. **头文件**：在 C 代码中必须包含：

    ```c
    #include <pthread.h>
    ```
    
    
2. 编译命令：
    
    gcc 编译器需要链接 Pthreads 库，必须加上 -pthread 选项：
    
    ```bash
    gcc main.c -pthread
    ```
    
    (注意：不同平台可能略有不同，但 Linux/GCC 下 `-pthread` 是标准做法) 。

### 3. 三大核心功能模块 [PPT P13]

Pthreads 库虽然有 100 多个 API，但我们只需要关注最常用的 **3 类** ：

1. **线程管理 (Thread Management)** ：
    
    - 负责线程的“生老病死”：创建 (create)、终止 (exit)、分离 (detach)、等待 (join)。
        
    - 还包括设置/查询线程属性。
        
2. **互斥变量 (Mutexes)** ：
    
    - 用于**同步**。这就是“锁”。
        
    - 功能：创建/销毁锁、加锁 (lock)、解锁 (unlock)。
        
3. **条件变量 (Condition Variables)** ：
    
    - 用于**通信**。
        
    - 解决“基于特定条件互相通知”的问题（例如：生产者告诉消费者“有货了”）。
        
    - 功能：等待 (wait)、发送信号 (signal/broadcast)。

## 线程的创建与终止

这三页 PPT 讲解了线程生命周期的开始（创建）和结束（终止）。

### 1. 线程创建：`pthread_create` (必背核心) [PPT P15]

这是整个多线程编程的入口，类似于 C 语言的 `main` 函数是进程入口。

**函数原型**：
```c
int pthread_create(pthread_t *thread, 
                   const pthread_attr_t *attr,
                   void *(*start_routine) (void *), 
                   void *arg);
```

**🔍 四个参数详解 (考试填空/改错必考)**：

1. **`thread` (输出参数)**：
    
    - 传一个 `pthread_t` 变量的地址进去。
        
    - 函数成功后，系统会把新创建的 **线程 ID** 写在这个变量里 。
        
2. **`attr` (属性)**：
    
    - 用来设置线程的栈大小、调度策略等。
        
    - **通常设为 `NULL`**，表示使用默认属性 。
        
3. **`start_routine` (函数指针)**：
    
    - **最重要的参数**。新线程启动后，会从这个函数开始执行 。
        
    - **格式要求**：返回值必须是 `void*`，参数也必须是 `void*`。
        
4. **`arg` (参数)**：
    
    - 传递给 `start_routine` 函数的参数。
        
    - 如果你想传一个整数，要强转成 `(void *)`；如果你想传多个参数，必须定义一个结构体，然后传结构体的地址指针。
        

**返回值**：

- 成功返回 0，失败返回错误码 。

### 2. 线程终止：如何优雅地退出？ [PPT P16]

线程结束不仅仅是函数跑完那么简单，PPT 列出了几种情况：

**🚪 主动终止 (正常退出)**：

1. **函数返回**：线程的入口函数（`start_routine`）正常执行完 `return` 。
    
2. **显式退出**：线程自己调用 `pthread_exit(void *retval)` 。
    
    - 这就像进程里的 `exit()`，但它只结束当前线程，不杀整个进程。
        

**💀 被动终止 (非正常)**： 3. **被取消**：其他线程调用 `pthread_cancel(tid)` 强制杀死它 。 4. **进程崩溃**：如果主线程（main）调用了 `exit()` 或者 `exec()`，**整个进程**（包括所有线程）都会立即销毁 。 * **注意**：`main` 函数如果不调用 `pthread_exit` 直接 `return`，通常意味着进程结束。

### 🎯 期末 & 考研考题预测

#### 题型 1：代码填空题 (高频)

**Q1:** 补全代码，创建一个新线程执行 `worker` 函数，参数为 `NULL`。

C

```
pthread_t tid;
int ret = _________(&tid, NULL, _________, NULL);
if (ret != 0) {
    printf("Create thread failed\n");
}
```

> **答案**：`pthread_create`, `worker`。 **注意**：第三个参数直接填函数名 `worker` 即可（函数名即地址）。

#### 题型 2：改错题

**Q2:** 下面的代码有什么问题？

C

```
void *my_thread(void *arg) {
    int value = 10;
    return &value; // 返回局部变量的地址
}
```

> **答案**：线程返回了局部变量的地址。 **解析**：线程结束后，其私有栈（Stack）会被回收，局部变量 `value` 的内存将无效。主线程如果去访问这个返回值，会得到脏数据或导致崩溃。应使用 `malloc` 分配堆内存或返回全局变量/静态变量。

#### 题型 3：简答题

**Q3:** 如果主线程在子线程结束前就调用了 `exit(0)`，子线程会发生什么？

> **答案**：子线程会立即被强制终止。 **解析**：`exit()` 是进程级操作，会销毁整个进程的地址空间，所有依附于该进程的线程都会随之消亡。
