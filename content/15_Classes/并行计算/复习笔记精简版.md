# 并行编程概述
## 1. 核心考点概览 (对应大纲)

- **性能评估指标**：加速比 (Speedup)、并行效率 (Efficiency)
    
- **可扩展性**：强可扩展性 (Strong Scalability) vs 弱可扩展性 (Weak Scalability)
    
- **两大定律**：Amdahl定律 (阿姆达尔定律) vs Gustafson定律 (古斯塔夫森定律)
    
- **HPC排名**：Top500, Green500, 戈登·贝尔奖
    

## 2. 并行程序性能评估

### 2.1 加速比 (Speedup)

- **定义**：衡量并行化后速度提升的倍数。
    
- **公式**：
    
    $$S = \frac{T_{serial}}{T_{parallel}}$$
    - $T_{serial}$：串行执行时间（单处理器）
        
    - $T_{parallel}$：并行执行时间（多处理器）
        
- **理想情况**：线性加速比，即 $S = p$（$p$ 为处理器数量）。
    
- **实际情况**：通常 $S < p$，因为存在通信开销、同步等待和不可并行的串行代码。
    
- **超线性加速比 (Super-linear Speedup)**：极少数情况下 $S > p$。
    
    - _原因_：分解后的小规模数据能全部放入 Cache，导致缓存命中率大幅提升。
        

### 2.2 并行效率 (Parallel Efficiency)

- **定义**：衡量处理器的利用率（即是否每个处理器都满负荷工作）。
    
- **公式**：
    
    $$E = \frac{S}{p} = \frac{T_{serial}}{p \times T_{parallel}}$$
- **取值范围**：通常在 $0 \sim 1$ 之间。$E=1$ 表示拥有理想加速比。
    

## 3. 可扩展性 (Scalability)

### 3.1 强可扩展性 (Strong Scalability)

规模固定，增加进程线程个数时，效率不变。

- **场景**：**问题总规模固定**。
    
- **目标**：随着处理器数量 ($p$) 增加，**总运行时间减少**。
    
- **适用性**：受 Amdahl 定律限制较严重，因为问题规模不变，分到每个核上的计算量变少，但通信开销占比变大。
    

### 3.2 弱可扩展性 (Weak Scalability)
增加进程线程个数时，只有以相同倍率增大问题规模才能使效率值不变。 
- **场景**：**每个处理器的计算规模固定**（即总问题规模随着处理器数量增加而同比例增加）。
    
- **目标**：随着处理器数量 ($p$) 增加，**运行时间保持不变**（或并行效率保持稳定）。
    
- **适用性**：遵循 Gustafson 定律，适合求解更大规模的问题。
    

|特性|强可扩展性 (Strong)|弱可扩展性 (Weak)|
|---|---|---|
|**问题规模**|固定不变|随处理器增加而增大|
|**关注点**|缩短解决时间|解决更大的问题|
|**制约定律**|Amdahl 定律|Gustafson 定律|

## 4. 核心定律 (常考计算题)

### 4.1 Amdahl 定律 (阿姆达尔定律)

- **前提**：**固定问题规模**。
    
- **核心思想**：加速比受限于程序中**必须串行执行**的部分。无论处理器多少，串行部分的时间无法被压缩。
    
- **公式**：
    
    $$S = \frac{1}{(1 - P) + \frac{P}{N}}$$
    - $P$：程序中可并行化的比例 (0 ~ 1)
        
    - $N$：处理器数量
        
    - $1-P$：串行比例
        
- **极限**：当 $N \to \infty$ 时，最大加速比 $S_{max} = \frac{1}{1-P}$。
    
    - _例子_：如果程序 20% 必须串行 ($1-P = 0.2$)，哪怕用 10000 个核，最大加速比也超不过 $1/0.2 = 5$ 倍。
        

### 4.2 Gustafson 定律 (古斯塔夫森定律)

- **前提**：**扩大问题规模**。
    
- **核心思想**：当我们有更多的处理器时，我们倾向于解决更大的问题，而不是更快地解决同一个小问题。随着问题规模增大，可并行部分的比例通常会增加，而串行部分（如初始化）保持相对固定。
    
- **公式**：
    
    $$S(N) = N - \alpha \times (N - 1)$$
    - $N$：处理器数量
        
    - $\alpha$：串行部分在单核执行时间中的比例
        
- **结论**：只要问题规模足够大，加速比可以几乎随处理器数量线性增长。
    

## 5. 行业榜单 (背景知识)

- **Top500**：全球**最快超级计算机** 500 强排名（基于 HPL Linpack 测试基准，浮点运算速度）。每年 6 月和 11 月发布。性能排行榜
    
- **Green500**：全球**最节能（能效比最高）** 的超级计算机排名（Performance per Watt，每瓦性能）。
    
- **Gordon Bell Prize (戈登·贝尔奖)**：高性能计算领域的“诺贝尔奖”，颁发给并行计算领域的**杰出应用成果**（不只是硬件快，还要软件算法好）。
# 并行计算体系结构
## 1. 核心考点概览 (对应大纲)

- **瓶颈问题**：存储墙 (Memory Wall)
    
- **体系结构分类**：Flynn分类法 (SISD, SIMD, MISD, MIMD)、存储模型分类 (UMA, NUMA, 分布式)
    
- **指令级并行 (ILP) 技术**：流水线、多发射、超标量、乱序执行、预测执行、VLIW
    
- **数据级与线程级并行**：SIMD、硬件多线程 (SMT)
    

## 2. 存储墙问题 (The Memory Wall)

- **定义**：处理器速度（CPU Speed）的增长速度远快于存储器速度（Memory Speed）的增长速度，导致处理器在等待数据时处于空闲状态，严重限制了系统性能。
    
- **现象**：CPU "跑得太快"，内存 "跟不上"。
    
- **应对策略**：
    
    - **Cache (缓存)**：利用局部性原理，减少访问主存的次数。
        
    - **多线程 (Multithreading)**：当一个线程等待内存时，CPU切换到另一个线程继续工作（掩盖延迟）。
        

## 3. 计算机系统分类

### 3.1 Flynn 分类法 (必考)

根据**指令流 (Instruction Stream)** 和 **数据流 (Data Stream)** 的数量进行分类：

|类别|全称|描述|典型代表|
|---|---|---|---|
|**SISD**|单指令流单数据流|传统的串行计算机|单核 CPU (早期)|
|**SIMD**|单指令流多数据流|**一条指令**同时作用于**多个数据**|**GPU**, 向量处理器, CPU的AVX指令集|
|**MISD**|多指令流单数据流|多个指令处理同一个数据|极少见 (用于航天冗余容错)|
|**MIMD**|多指令流多数据流|多个处理器独立执行不同指令处理不同数据|**现代多核 CPU**, 集群, 分布式系统|

> **考试陷阱**：GPU 虽然可以运行不同的 Kernel，但在底层架构（Warp/SM）上，它主要利用 **SIMD** (或 NVIDIA 称之为 SIMT) 来获得高吞吐量。

### 3.2 存储模型分类

- **共享内存 (Shared Memory)**：所有处理器通过总线访问统一的物理内存。
    
    - **UMA (Uniform Memory Access)**：所有处理器访问内存任何位置的时间**相同**（SMP 对称多处理器）。
        
    - **NUMA (Non-Uniform Memory Access)**：访问**本地**内存快，访问**远程**（其他CPU管理的）内存慢。
        
- **分布式内存 (Distributed Memory)**：每个处理器有私有内存，通过**网络 (Network)** 显式通信（如 MPI）。
    

## 4. 传统体系结构优化技术 (指令级并行 ILP)

### 4.1 流水线 (Pipelining)

- **原理**：将指令执行过程分解为多个阶段（取指、译码、执行、访存、写回），让多条指令在时间上重叠执行。
    
- **目标**：提高吞吐率（Throughput）。
    
- **问题**：流水线气泡/停顿（Stall），由数据依赖或分支跳转引起。
    

### 4.2 多发射 (Multiple Issue) 与 超标量 (Superscalar)

- **多发射**：CPU 在一个时钟周期内发出多条指令。
    
- **超标量 (Superscalar)**：
    
    - **硬件**动态决定哪些指令可以并行发射。
        
    - 硬件逻辑复杂，但二进制兼容性好（旧程序也能加速）。
        
    - 现代高性能 CPU (Intel i7/i9) 都是超标量架构。
        

### 4.3 VLIW (超长指令字)

- **原理**：**编译器**在编译时分析依赖关系，将多条无依赖的指令打包成一条超长的指令包。
    
- **对比**：
    
    - _Superscalar_：硬件负责调度（运行时）。
        
    - _VLIW_：软件/编译器负责调度（编译时），硬件简单，但编译器很难写。
        
    - _代表_：Intel Itanium (安腾), DSP。
        

### 4.4 乱序执行 (Out-of-Order Execution)

- **原理**：如果当前指令需等待数据，CPU 不傻等，而是跳过它去执行后面不依赖于它的指令。
    
- **核心**：指令按顺序进入（Fetch），乱序执行（Execute），按顺序提交（Commit/Retire）以保证结果正确。
    

### 4.5 预测执行 (Speculative Execution)

- **场景**：遇到 `if-else` 分支时。
    
- **原理**：CPU "猜" 一个方向（分支预测），提前执行那条路上的指令。
    
    - _猜对了_：性能大增。
        
    - _猜错了_：清空流水线，回滚状态（代价大）。
        

## 5. 数据级与线程级并行

### 5.1 SIMD (单指令多数据)

- **特点**：利用长寄存器（如 256-bit），一条加法指令同时计算 8 个 float 数字。
    
- **应用**：图像处理、矩阵运算。
    

### 5.2 硬件多线程 (Hardware Multithreading)

- **目的**：**掩盖存储延迟**（当一个线程 Cache Miss 时，立即切到另一个线程，而不让 CPU 空转）。
    
- **三种粒度**：
    
    1. **细粒度 (Fine-grained)**：每条指令后都切换线程（轮转）。
        
    2. **粗粒度 (Coarse-grained)**：仅在发生长延迟事件（如 Cache Miss）时才切换。
        
    3. **同时多线程 (SMT / Hyper-threading)**：**最强**。在一个周期内，利用流水线中空闲的功能单元，同时发射多个线程的指令。
        
        - _例子_：Intel 超线程技术 (2个逻辑核共享1个物理核的资源)。

# 并行编程方法
## 1. 核心考点概览 (对应大纲)

- **实现方式**：隐式并行 vs 显式并行
    
- **显式并行的分类**：库例程、编译器指令、语言扩展
    
- **基本方式**：数据并行 vs 任务并行
    
- **常用编程模式 (Patterns)**：Stencil (模版/网格)、Pipeline (流水线)、Master-Worker (主从)
    

## 2. 并行程序的实现方法 (必考概念)

### 2.1 隐式并行 (Implicit Parallelism)

- **定义**：程序员编写串行代码，由**编译器**或**硬件**自动发现并行性并进行并行化。
    
- **优点**：程序员负担小，现有串行代码无需修改。
    
- **缺点**：编译器很难完全理解程序的语义和依赖关系，并行化程度通常有限。
    

### 2.2 显式并行 (Explicit Parallelism)

- **定义**：程序员通过特定的指令或函数调用，显式地指定哪些代码需要并行执行、如何同步、如何通信。
    
- **三种主要手段**（常考选择/填空）：
    

|手段|描述|典型代表|优缺点|
|---|---|---|---|
|**库例程** (Library Routines)|调用并行库函数来管理线程/进程|**Pthreads**, **MPI**|+ 灵活，可移植<br><br>- 编码复杂，易出错|
|**编译器指令** (Compiler Directives)|在代码中插入特殊的注释/Pragma|**OpenMP**, OpenACC|+ 简单，保留串行代码结构<br><br>- 功能受限于编译器支持|
|**语言扩展** (Language Extensions)|增加新的语法关键字来支持并行|**CUDA**, UPC|+ 发挥硬件极致性能<br><br>- 移植性差，学习成本高|

## 3. 并行编程的两大基本方式

### 3.1 数据并行 (Data Parallelism)

- **核心**：**数据**被分割成多块，多个处理器**同时执行相同的操作**（指令），但处理不同的数据块。
    
- **适用场景**：图像处理、矩阵运算、向量计算。
    
- _口诀_：“由于数据太多，我们分头做同样的活”。
    

### 3.2 任务并行 (Task Parallelism)

- **核心**：**功能**被分解，不同的处理器执行**完全不同的计算任务**（指令/函数）。
    
- **适用场景**：一个线程做UI响应，另一个线程做后台下载；或者编译器的词法分析与语法分析并行。
    
- _口诀_：“因为事情太杂，你做饭，我洗衣服”。
    

## 4. 常见的并行编程模式 (Parallel Patterns)

在 PPT 中重点介绍了几种结构化的模式，这些是并行算法设计的基础：

### 4.1 Stencil (模版/网格模式)

- **定义**：数组中每个元素的新值依赖于它**邻居节点**的旧值。
    
- **结构**：通常是一个外层循环遍历时间步，内层循环遍历空间网格。
    
- **类型**：
    
    - **5-point stencil (2D)**：依赖上下左右中（十字形）。
        
    - **9-point stencil (2D)**：依赖周围8个邻居加自己（九宫格）。
        
    - **7-point stencil (3D)**：依赖上下左右前后中。
        
- **关键问题**：**边界处理**（Ghost Cells / Halo Regions）和数据同步。
    

### 4.2 Pipeline (流水线模式)

- **定义**：将任务分解为一系列级联的阶段（Stage），数据流经这些阶段，就像工厂流水线。
    
- **特点**：
    
    - 上一个阶段的输出是下一个阶段的输入。
        
    - 适合**流式数据**处理。
        
    - 并行度受限于流水线中最慢的那个阶段（瓶颈）。
        

### 4.3 Master-Worker (主从模式 / Manager-Worker)

- **结构**：
    
    - **Master (Manager)**：负责产生任务、维护任务队列、收集结果。
        
    - **Worker**：从队列取任务执行，完成后将结果返回给 Master。
        
- **优点**：**动态负载均衡**（Dynamic Load Balancing）。处理快的 Worker 可以多做任务，处理慢的少做，非常适合任务负载不均的场景。
    

## 5. 并行编程的基本过程 (了解)

1. **分解 (Decomposition)**：寻找并发性，将问题分解为小任务。
    
2. **分配 (Assignment)**：将任务分配给进程/线程（考虑负载均衡）。
    
3. **编排 (Orchestration)**：设计数据访问、通信和同步。
    
4. **映射 (Mapping)**：将进程/线程映射到物理处理器上（考虑网络拓扑、NUMA）。
# 并行编程的关键问题（重点）
## 1. 核心考点概览 (对应大纲)

- **任务划分 (Partitioning)**：域分解 (数据分解) vs 功能分解
    
- **调度 (Scheduling)**：
    
    - 静态调度 vs 动态调度
        
    - 动态调度算法：GSS, TSS, FSS
        
    - CPU 亲和性 (Affinity)
        
- **数据重组**：AoS (结构体数组) vs SoA (数组结构体)
    
- **同步机制**：Barrier, Lock/Mutex, Semaphore, Condition Variable, Atomic
    

## 2. 任务划分 (Decomposition / Partitioning)

### 2.1 域分解 (Domain/Data Decomposition)

- **定义**：基于**数据**进行的划分。将与问题相关的数据（如矩阵、图像、网格）分解为离散的块，每个任务处理一部分数据。
    
- **类型**：
    
    - **一维分解**：按行或按列切分矩阵。
        
    - **多维分解**：将矩阵切分成一个个小方块 (Block)。
        
- **适用**：大多数科学计算（如矩阵乘法、天气预报）。
    

### 2.2 功能分解 (Functional Decomposition)

- **定义**：基于**计算工作（代码逻辑）** 进行的划分。将总目标分解为不同的子任务（如输入、计算、输出），每个处理器执行不同的函数。
    
- **适用**：流水线处理、复杂的逻辑流。
    

## 3. 调度 (Scheduling) —— **重难点**

#### 2.调度的终极目标

- **两大目标**：
    
    1. **最小化**程序执行时间。
        
    2. **最大化**资源（CPU）利用率。

### 3.1 静态调度 (Static Scheduling)

- **时机**：编译时分配好任务。
    
- **特点**：开销极小，适合负载非常均匀的循环。
    
- **方式**：
    
    - **块状分布 (Block)**：每个线程拿连续的一大块（如 0~9 给 T0, 10~19 给 T1）。
        
    - **循环分布 (Cyclic)**：轮询分发（如 0 给 T0, 1 给 T1, 2 给 T0...），适合循环各次迭代负载不均但有规律的情况。
        

### 3.2 动态调度 (Dynamic Scheduling)（会考算的调度题！）

- **时机**：运行时分配。
    
- **特点**：开销大（需要互斥锁保护任务队列），但能很好地处理**负载不均衡**。
    
- **核心策略**（常考算法）：
    
    1. **自调度 (Self Scheduling / SS)**：每次只拿 1 个迭代或固定大小的块。
        
        - _缺点_：访问队列太频繁，开销巨大。
            
- **核心策略计算详解**（常考计算题）：
    
    假设总迭代次数为 $N$，处理器/线程数为 $P$。
    
     1. 引导式自调度 (Guided Self-Scheduling, GSS)
    
    - **核心逻辑**：每次分配剩余任务的 $\frac{1}{P}$。
        
    - **公式**：
        
        $$K_i = \lceil \frac{R_{i-1}}{P} \rceil$$
        - $K_i$：第 $i$ 次分配的块大小。
            
        - $R_{i-1}$：分配前剩余的迭代次数。
            
    - **示例** ($N=100, P=4$)：
        
        1. **T0 请求**：剩余 100，拿 $\lceil 100/4 \rceil = 25$。剩余 75。
            
        2. **T1 请求**：剩余 75，拿 $\lceil 75/4 \rceil = 19$。剩余 56。
            
        3. **T2 请求**：剩余 56，拿 $\lceil 56/4 \rceil = 14$。剩余 42。
            
        4. **T3 请求**：剩余 42，拿 $\lceil 42/4 \rceil = 11$。剩余 31。
            
    - **特点**：块大小指数级递减，初期大块减少开销，后期小块均衡负载。
        
    
     2. 因式分解自调度 (Factoring Self-Scheduling, FSS)
    
    - **核心逻辑**：**分批次 (Batch)** 分配。每一批次包含 $P$ 个块（每个线程一个），这一批次的总任务量是剩余任务的一半。
        
    - **公式**：
        
        $$K_{batch} = \lceil \frac{R_{current}}{2 \times P} \rceil$$
    - **示例** ($N=100, P=4$)：
        
        1. **第一批次**：拿走剩余的一半 (50个)。每个线程分 $\lceil 50/4 \rceil = 13$ (最后修正总和)。
            
            - T0~T3 各拿 13 个左右。剩余 50。
                
        2. **第二批次**：拿走剩余的一半 (25个)。每个线程分 $\lceil 25/4 \rceil = 7$。
            
            - T0~T3 各拿 7 个左右。剩余 25。
                
    - **特点**：结合了静态（一批分很多）和动态的优点，每批次内大家拿的一样多。
        
    
     3. 梯形自调度 (Trapezoid Self-Scheduling, TSS)
    
    - **核心逻辑**：块大小**线性递减**。
        
    - **公式**：
        
        - 首块大小 (First): $F \approx \frac{N}{2P}$
            
        - 末块大小 (Last): $L = 1$
            
        - 每次递减量 (Decrement): $\delta = \frac{F-L}{Batch\_Count - 1}$
            
    - **特点**：下降比 GSS 平缓，任务分配更加细致和均匀。
**工作窃取：** 随机窃取，空闲时窃取其他任务。所有任务队列空了以后这个程序才结束
**工作共享：** 自己队列未满则将新产生的任务放到自己队列(满了的把线程放池子里)
> - **工作窃取**：我闲了，我主动去**偷**你。（Receiver-initiated，接收者主动）
>     
> - **工作共享**：我忙了，我主动**分**出去。（Sender-initiated，发送者主动）
### 3.3 CPU 亲和性 (CPU Affinity)

- **定义**：将特定的进程/线程绑定到特定的物理 CPU 核心上，不让操作系统随意迁移它。
    
- **目的**：提高 **Cache 命中率**（避免线程迁移导致 Cache 失效）和减少上下文切换开销。
    
- **注意**：在 NUMA 架构下，亲和性设置非常关键，要保证线程绑定的核离它要访问的内存近。
    

## 4. 数据重组：AoS vs SoA (必考辨析)（绝对绝对考

这是并行编程中优化内存访问最关键的技术之一。

### 4.1 AoS (Array of Structures, 结构体数组)

- **形式**：`struct Point { float x, y, z; }; Point p[N];`
    
- **内存布局**：`x0 y0 z0 | x1 y1 z1 | x2 y2 z2 ...`
    
- **缺点**：不适合 SIMD。比如只想计算所有点的 x 坐标之和，加载 x0 时会顺带把无关的 y0, z0 加载进 Cache 行，浪费带宽。
    
- **适用**：面向对象编程，需要频繁同时访问一个对象的多个属性时。
    

### 4.2 SoA (Structure of Arrays, 数组结构体)

- **形式**：`struct Points { float x[N], y[N], z[N]; };`
    
- **内存布局**：
    
    - `x0 x1 x2 ...` (连续)
        
    - `y0 y1 y2 ...` (连续)
        
- **优点**：
    
    1. **SIMD 友好**：可以一条指令加载 `x0-x7` 进行向量计算。
        
    2. **Cache 利用率高**：如果只算 x，Cache 里全是 x，没有浪费。
        
    3. **GPU 合并访问**：非常适合 GPU 全局内存访问模式。
        
- **适用**：大规模数值计算、GPU 编程。
    

## 5. 同步机制 (Synchronization)

- **栅栏 (Barrier)**：所有到达该点的线程必须等待，直到所有线程都到达，才能继续执行。用于阶段性的同步。
    
- **互斥锁 (Mutex/Lock)**：保护临界区 (Critical Section)，保证同一时刻只有一个线程能访问共享数据。
    
- **信号量 (Semaphore)**：控制对有限数量资源的访问（计数器）。
    
- **条件变量 (Condition Variable)**：允许线程挂起等待某个“条件”满足（通常配合互斥锁使用）。
    
- **原子操作 (Atomic)**：不可中断的最小操作（如 atomic_add），通常由硬件直接支持，比锁快。

## 3. 线程管理 API (必背)

Pthreads (POSIX Threads) 是 C/C++ 显式并行编程的标准库。头文件：`#include <pthread.h>`。

### 3.1 创建线程 `pthread_create`
！重点
```c
int pthread_create(
    pthread_t *thread,            // [输出] 线程ID句柄
    const pthread_attr_t *attr,   // [输入] 线程属性 (NULL为默认)
    void *(*start_routine)(void*),// [输入] 线程函数指针 (必须是 void* func(void* arg))

);
```

> **考点**：最后一个参数 `arg` 如何传递多个值？
> 
> - **答案**：定义一个 `struct`，将多个参数打包进去，然后传结构体指针。
>     

### 3.2 结束线程 `pthread_exit`

```c
void pthread_exit(void *retval);
void pthread_cancel()//被其他线程取消
```

- **功能**：显式终止当前线程，并返回一个指针。
    
- **陷阱**：**千万不要返回局部变量的指针**，因为线程结束后其栈空间会被回收，返回的指针将变成悬空指针。
    

### 3.3 等待线程 `pthread_join`
！重点
```c
int pthread_join(pthread_t thread, void **retval);//等子线程结束
int pthread_detach(pthread_t thread);//分离子线程，子线程自行结束。自我回收内存资源
```

- **功能**：阻塞调用者（通常是主线程），直到目标 `thread` 执行结束。类似于进程的 `wait()`。
    
- **作用**：防止主线程先于子线程结束（主线程结束会导致整个进程销毁，子线程会被强制杀死）。

默认属性：
```c
int pthread_attr_init(pthread_attr_t *attr);

int pthread_attr_destroy(pthread_attr_t *attr);
```
### 3.4 线程属性 (分离 vs 可连接)

- **Joinable (默认)**：线程结束后，必须由其他线程调用 `pthread_join` 来回收资源（类似僵尸进程的处理）。
    
- **Detached (分离)**：
    
    - 设置 `PTHREAD_CREATE_DETACHED` 属性。
        
    - 线程结束后，系统**自动回收**资源。
        
    - **不能**对分离的线程调用 `pthread_join`。
###  关键属性设置

- **分离状态 (Detach State)**
    
    - **API**: `pthread_attr_setdetachstate(&attr, int detachstate)`
        
    - **参数**:
        
        - `PTHREAD_CREATE_JOINABLE` (默认)：需要 `pthread_join` 回收。
            
        - `PTHREAD_CREATE_DETACHED`：线程结束自动回收资源。
            
    - **用途**：如果明确不需要等待线程结束，在创建时直接设置为分离，避免僵尸线程。
        
- **堆栈大小 (Stack Size)**
    
    - **API**: `pthread_attr_setstacksize(&attr, size_t stacksize)`
        
    - **用途**：
        
        - **增大**：当线程内有深度递归或大数组时，防止栈溢出 (Stack Overflow)。
            
        - **减小**：当需要创建成千上万个线程，而内存有限时。
            
- **堆栈地址 (Stack Address)**
    
    - **API**: `pthread_attr_setstackaddr(&attr, void *stackaddr)`
        
    - **用途**：让线程使用用户自行分配的内存区域作为栈。常用于嵌入式系统（内存布局受限）或实现自定义的栈管理。
        
- **调度策略 (Scheduling Policy)**
    
    - **API**: `pthread_attr_setschedpolicy(&attr, int policy)`
        
    - **参数**:
        
        - `SCHED_OTHER` (默认)：普通的分时调度（非实时）。
            
        - `SCHED_FIFO`：先进先出（实时调度，一直运行直到阻塞或结束，需要 root 权限）。
            
        - `SCHED_RR`：轮转法（实时调度，有时间片，需要 root 权限）。

## 4. 互斥量 (Mutex) —— 保护数据

用于解决**竞争条件 (Race Condition)**，保证同一时刻只有一个线程访问共享资源（临界区）。

### 4.1 核心 API

1. **初始化**：`pthread_mutex_init(&mutex, NULL)` 或宏 `PTHREAD_MUTEX_INITIALIZER`（静态创建，无需destroy）。
    
2. **加锁**：`pthread_mutex_lock(&mutex)`。如果已被锁，线程会**阻塞**。
    
3. **尝试加锁**：`pthread_mutex_trylock(&mutex)`。非阻塞调用，如果被锁返回 `EBUSY`，常用于避免死锁。
    
4. **解锁**：`pthread_mutex_unlock(&mutex)`。
    
5. **销毁**：`pthread_mutex_destroy(&mutex)` 对应init。
    

### 4.2 死锁 (Deadlock) 四个必要条件

1. 互斥使用
    
2. 持有并等待
    
3. 不可抢占
    
4. 循环等待
    

- **破解方法**：固定加锁顺序（Hierarchy locking）或使用 `trylock`。
    
读写锁在不同模式下加锁和解锁：
#### 5.1 三种状态与模式

1. **读模式加锁 (Read Lock / Shared Lock)**：
    
    - **允许多个线程**同时持有读锁。
        
    - 只要没有线程持有“写锁”，读锁就可以成功申请。
        
2. **写模式加锁 (Write Lock / Exclusive Lock)**：
    
    - **独占**。同一时刻只能有一个线程持有写锁。
        
    - 只有当**没有任何**线程持有读锁或写锁时，写锁才能申请成功。
        
3. **不加锁**。
    

### 5.2 核心 API (必背)

类型：`pthread_rwlock_t`

|操作|函数名|行为描述|
|---|---|---|
|**初始化**|`pthread_rwlock_init`|初始化读写锁|
|**读加锁**|`pthread_rwlock_rdlock(&rwlock)`|**共享模式**。如果当前有写锁，则阻塞；如果有其他读锁，则成功（计数+1）。|
|**写加锁**|`pthread_rwlock_wrlock(&rwlock)`|**独占模式**。如果当前有任何读锁或写锁，都必须阻塞等待。|
|**解锁**|`pthread_rwlock_unlock(&rwlock)`|**通用解锁**。无论是读锁还是写锁，都用这个函数解。|
|**销毁**|`pthread_rwlock_destroy`|销毁锁对象|

### 5.3 优先级问题 (了解)

- **读优先**：只要有读锁，后来的读请求都能插队进入（可能导致写线程饿死）。
    
- **写优先**：一旦有写请求在排队，后来的读请求必须阻塞（防止写线程饿死）。
    
- _Pthreads 标准未强制规定优先级，具体取决于实现，但通常要注意写线程饿死问题。_
  
## 5. 条件变量 (Condition Variable) —— 线程协作

用于线程间的**通知机制**（例如：缓冲区不空了，消费者才能取；缓冲区不满，生产者才能放）。**必须配合互斥量使用**。

### 5.1 核心 API

1. **等待**：`pthread_cond_wait(&cond, &mutex)`
    
    - **原子操作三步走**（常考）：
        
        1. **解锁** mutex（让其他线程有机会修改条件）。
            
        2. **阻塞**等待信号。
            
        3. 被唤醒后，重新**加锁** mutex。
            
2. **发送信号**：
    
    - `pthread_cond_signal(&cond)`：唤醒**至少一个**等待的线程。
        
    - `pthread_cond_broadcast(&cond)`：唤醒**所有**等待的线程。
        

### 5.2 标准代码模式 (重点中的重点)

**为什么必须用 `while` 而不是 `if`？**

- **虚假唤醒 (Spurious Wakeup)**：线程可能在没有收到信号的情况下被操作系统唤醒。
    
- **多线程竞争**：被唤醒时，可能另一个线程先抢到了锁并消耗了资源，导致条件再次不满足。
    

**消费者线程模板：**

```
pthread_mutex_lock(&mutex);
// 必须使用 while 循环检查条件
while (count == 0) {
    // 释放锁 -> 等待 -> 被唤醒 -> 重新加锁
    pthread_cond_wait(&cond, &mutex);
}
// 临界区操作：取出数据
count--;
pthread_mutex_unlock(&mutex);
```

**生产者线程模板：**

```
pthread_mutex_lock(&mutex);
// 修改条件
count++;
// 通知等待的线程
pthread_cond_signal(&cond); 
pthread_mutex_unlock(&mutex);
```

## 6. 复习小贴士

1. **代码填空题预测**：
    
    - 看到 `pthread_create`，注意第四个参数如果是 `&i`，循环中可能会发生数据竞争（所有线程共享同一个 `i` 的地址）。正确的做法是传递值 `(void*)i` 或动态申请内存。
        
    - 看到 `pthread_cond_wait`，前一行必须是 `lock`，外层必须是 `while`。
        
2. **读写锁 (Read-Write Lock)**：
    
    - `pthread_rwlock_rdlock` (读锁)：允许多个读者并行，但写者阻塞。
        
    - `pthread_rwlock_wrlock` (写锁)：独占，所有读者和写者都阻塞。
        
    - **适用场景**：读多写少（Read-mostly）。

# OpenMP编程
基础：什么是 OpenMP、OpenMP 的并行执行模式、结构块和非结构块的判定、OpenMP 编译制导语句的组成

并行域指令：parallel 指令

工作共享指令：for、sections、task 指令，相关子句：schedule、nowait、num_threads

同步指令：master、critical、barrier、atomic、ordered、single

数据环境：threadprivate、private、firstprivate、lastprivate、reduction、copyin

常用库函数：获取和设置线程数、获取当前线程、程序计时
## 1. 基础概念 (对应大纲)

### 1.1 什么是 OpenMP

- **定义**：OpenMP (Open Multi-Processing) 是一套用于**共享内存**并行系统的多线程程序设计标准（API）。
    
- **组成**：由三部分组成（必考填空）：
    
    1. **编译制导语句** (Compiler Directives)
        
    2. **运行时库函数** (Runtime Library Routines)
        
    3. **环境变量** (Environment Variables)
        

### 1.2 并行执行模式：Fork-Join 模型

- 程序开始时，只有**主线程 (Master Thread)** 串行执行。
    
- 遇到并行域 (`parallel`) 时，主线程派生 (Fork) 出一组线程（**线程组 Team**）并行执行。
    
- 并行域结束时，所有线程同步 (Join/Barrier)，只有主线程继续执行，其他线程消亡或挂起。
    

### 1.3 结构块 (Structured Block)

- **判定标准**：**单入口，单出口**的代码块。
    
    - 不允许使用 `goto` 跳入或跳出块。
        
    - 允许在块内调用 `exit()` 终止程序。
        
- OpenMP 指令通常只能作用于结构块。
    

### 1.4 编译制导语句格式

- **C/C++ 格式**：
    
    ```
    #pragma omp directive-name [clause [ [,] clause]...]
    ```
    
    - 必须以 `#pragma omp` 开头。
        
    - 区分大小写。
        
    - 一行写不下可以用 `\` 续行。
        

## 2. 并行域指令 (Parallel Region)

### `parallel` 指令

- **功能**：创建线程组，显式定义并行代码区域。
    
- **行为**：块内的代码会被**每个线程都重复执行一遍**（SPMD 模式）。
    
    - _注意_：如果仅仅写 `#pragma omp parallel` 而不加 `for`，且块内有 `printf("hello")`，N 个线程就会打印 N 次 hello。
        
- **常用子句**：`if`, `num_threads`, `private`, `shared`, `default`, `reduction`。
    

## 3. 工作共享指令 (Work-sharing Constructs)

工作共享指令用于将并行域内的任务**分配**给线程组中的不同线程，而不是让所有线程做同样的事。**它们必须位于 `parallel` 域内（或组合使用）。**

### 3.1 `for` 指令

- **功能**：将 `for` 循环的迭代分配给不同线程。
    
- **限制**：循环必须是**规范格式**（Canonical Shape），即循环变量只能是整数，边界确定，步长不变。
    
- **常用子句**：`schedule`, `nowait`, `ordered`, `collapse`。
    

### 3.2 `sections` 指令

- **功能**：定义一组独立的任务块（非迭代），每个块由一个线程执行。
    
- **结构**：
    
    ```
    #pragma omp sections
    {
        #pragma omp section
        funcA(); // 线程 1 做
        #pragma omp section
        funcB(); // 线程 2 做
    }
    ```
    

### 3.3 `task` 指令 (OpenMP 3.0+)

- **功能**：显式创建任务，放入任务队列，由线程池动态调度。
    
- **适用**：**非结构化并行**（如递归、链表遍历、while 循环），解决了 `for` 指令只能处理规则循环的局限。
    

### 3.4 关键子句 (Clauses)

- **`schedule(type, chunk_size)`** (用于 `for`)：
    
    - `static`: 静态轮转。适合负载均衡。
        
    - `dynamic`: 动态抢占。适合负载不均衡。
        
    - `guided`: 块大小递减的动态调度。
        
    - `runtime`: 由环境变量 `OMP_SCHEDULE` 决定。
        
- **`nowait`**：
    
    - 取消工作共享指令末尾的**隐式栅栏 (Implicit Barrier)**。
        
    - 允许线程做完自己的份内事后，不必等其他人，直接往下跑。
        
- **`num_threads(n)`**：指定并行域内的线程数量。
    

## 4. 同步指令 (Synchronization)

|指令|描述|是否有隐式栅栏|
|---|---|---|
|**`master`**|指定代码块**仅由主线程**执行，其他线程跳过。|**无** (其他线程不等待)|
|**`single`**|指定代码块由**任意一个**线程执行（不一定是主线程）。|**有** (除非加 `nowait`)|
|**`critical`**|**临界区**。同一时刻只允许一个线程执行该块（互斥）。|/|
|**`barrier`**|**栅栏**。所有线程必须到达此处才能继续。|/|
|**`atomic`**|**原子操作**。轻量级互斥，仅保护特定的内存更新（如 `x++`）。|/|
|**`ordered`**|强制循环的某部分按串行顺序执行。需配合 `for` 的 `ordered` 子句。|/|

> **易错点**：`master` 没有同步功能，做完就走；`single` 默认有同步，做完要等大家。

## 5. 数据环境 (Data Environment) —— **难点**

决定变量在并行域内是共享的还是私有的，以及如何初始化。

### 5.1 数据属性子句

- **`shared(list)`**：**共享**。所有线程访问同一内存地址，需注意竞争。
    
- **`private(list)`**：**私有**。每个线程有一份独立的副本。
    
    - **特点**：副本**未初始化**（即使原变量有值）；并行结束后，原变量的值**不可预测**。
        
- **`firstprivate(list)`**：**私有 + 初始化**。
    
    - **特点**：副本初始值 = 进入并行域前原变量的值。
        
- **`lastprivate(list)`**：**私有 + 回写**。
    
    - **特点**：退出并行域时，将**逻辑上最后一次迭代**（或最后一个 section）的值赋给原变量。
        
- **`threadprivate(list)`**：**线程专有全局变量**。
    
    - 生命周期跨越多个并行域。通常用于全局静态变量。
        
- **`copyin(list)`**：用于将主线程 `threadprivate` 变量的值复制给所有子线程的对应变量。
    

### 5.2 `reduction(op: list)` (归约)

- **功能**：自动处理私有变量的创建、初始化和最终结果的合并。
    
- **初始化规则**：
    
    - `+`, `-` 初始化为 `0`
        
    - `*` 初始化为 `1`
        
    - `&` 初始化为 `~0`
        
- **示例**：`#pragma omp parallel for reduction(+:sum)`

需包含头文件 `<omp.h>`。

| ------------------------------- | ---------------------------------- |

## 2. 异构系统种类 (Types of Heterogeneous Systems)

**定义**：异构计算系统是指包含**两种或多种**不同类型的指令集架构 (ISA) 或计算单元的系统。

### 2.1 芯片级异构 (Chip-level / SoC)

- **特点**：不同的计算单元集成在**同一个芯片 (Die)** 上。
    
- **代表**：
    
    - **APU (AMD Accelerated Processing Unit)**：CPU + GPU 集成。
        
    - **SoC (System on Chip)**：手机芯片 (Snapdragon, Apple A系列)，集成了 CPU、GPU、DSP、NPU (神经网络单元) 等。
        
    - **Cell BE** (PS3 处理器)：PPE (通用) + SPE (协处理)。
        

### 2.2 系统级异构 (System-level / Discrete)

- **特点**：通过**总线 (PCIe)** 连接独立的离散计算设备。
    
- **代表**：
    
    - **CPU + 独立 GPU**：最常见的 HPC 架构（如 NVIDIA Tesla 卡）。
        
    - **CPU + FPGA 加速卡**。
        
    - **CPU + ASIC (如 TPU)**。
        

## 3. 异构系统比较 (CPU / GPU / FPGA / ASIC) —— **重点背诵**

考试常考排序题（如：按能效比排序）或特性匹配题。

|特性|CPU (通用处理器)|GPU (图形处理器)|FPGA (现场可编程门阵列)|ASIC (专用集成电路)|
|---|---|---|---|---|
|**全称**|Central Processing Unit|Graphics Processing Unit|Field-Programmable Gate Array|Application-Specific Integrated Circuit|
|**架构特点**|少量强核，大缓存，复杂控制逻辑|大量弱核，高带宽，SIMT 架构|**硬件电路可重构**，LUT (查找表)|**硬件电路固定**，针对特定算法定制|
|**优势**|**通用性强**，逻辑控制复杂，单线程性能高|**吞吐量大**，适合数据并行|**低延迟**，高并发，硬件级流水线|**性能最高，能效比最高**，体积小|
|**劣势**|并行计算能力弱，能效比低|逻辑控制能力弱，IO 延迟高|**开发难度极高** (HDL)，频率较低|**不可编程/不可改**，开发周期长，成本极高(流片)|
|**灵活性**|极高 (软件定义)|高 (软件定义)|中 (硬件重构)|**极低** (一次性)|
|**能效比**|低|中|高|**极高**|
|**适用场景**|操作系统，复杂逻辑串行代码|深度学习训练，图形渲染，科学计算|通信信号处理，低延迟推理|比特币矿机，TPU (张量处理器)|

> **总结排序**：
> 
> - **灵活性 (Flexibility)**: CPU > GPU > FPGA > ASIC
>     
> - **能效比 (Energy Efficiency)**: ASIC > FPGA > GPU > CPU
>     
> - **开发成本 (NRE Cost)**: ASIC > FPGA > GPU > CPU
>     

## 4. 异构编程模型的作用

为什么不能直接写汇编去控制显卡？因为太复杂且不通用。

1. **抽象硬件细节**：向程序员屏蔽底层硬件（如显存管理、总线通信、核心调度）的复杂性。
    
2. **可移植性 (Portability)**：允许同一套代码在不同的异构设备（如既能跑在 AMD GPU 也能跑在 Intel CPU）上运行（如 OpenCL）。
    
3. **提高生产力**：提供高层接口，降低并行编程的门槛。
    
4. **资源管理**：自动管理计算资源和内存资源的分配与调度。
    

## 5. 常见异构编程模型 (Common Models)

### 5.1 CUDA (Compute Unified Device Architecture)

- **厂商**：**NVIDIA** 专用。
    
- **特点**：
    
    - 目前生态最成熟、性能最好的 GPU 编程模型。
        
    - **C/C++ 语言扩展**。
        
    - **缺点**：只能用于 NVIDIA 的 GPU，**不可移植**。
        

### 5.2 OpenCL (Open Computing Language)

- **厂商**：**Khronos Group** (开放标准)。
    
- **特点**：
    
    - **跨平台**：一套代码可以跑在 CPU、GPU (NVIDIA/AMD/Intel)、FPGA、DSP 上。
        
    - **缺点**：为了通用性牺牲了性能，且**代码极其繁琐**（写个 Hello World 要上百行配置代码）。
        

### 5.3 OpenACC (Open Accelerators)

- **厂商**：PGI, Cray, NVIDIA 等发起。
    
- **特点**：
    
    - **基于指令 (Directives)**：类似 **OpenMP** 的用法 (`#pragma acc ...`)。
        
    - **简单易用**：只需在现有代码中加注释，编译器自动生成 GPU 代码。
        
    - **缺点**：控制力度不如 CUDA 细致。
        

### 5.4 C++ AMP (Accelerated Massive Parallelism)

- **厂商**：**Microsoft**。
    
- **特点**：
    
    - 基于 C++ 和 DirectX。
        
    - 主要用于 Windows 平台。
        

### 5.5 HIP (Heterogeneous-Compute Interface for Portability)

- **厂商**：**AMD** (ROCm 平台)。
    
- **特点**：
    
    - 语法几乎和 CUDA 一模一样。
        
    - 可以通过工具 (`hipify`) 将 CUDA 代码自动转换为 HIP 代码，从而在 AMD 和 NVIDIA 显卡上都能跑。

# GPU与cuda编程
## 1. CPU 和 GPU 对比 (必考辨析)

这是理解异构计算的基础。

|特性|CPU (Latnecy Oriented)|GPU (Throughput Oriented)|
|---|---|---|
|**设计目标**|**低延迟** (Low Latency)|**高吞吐量** (High Throughput)|
|**核心数量**|少量强核 (十几到几十个)|大量弱核 (数千个)|
|**控制逻辑**|**复杂** (分支预测、乱序执行)，擅长处理逻辑复杂的串行代码|**简单** (无分支预测或很简单)，擅长处理逻辑简单的数据并行代码|
|**Cache**|**大容量** (L1/L2/L3)，用于减少内存延迟|**小容量** (相对于计算单元)，更多晶体管用于计算 (ALU)|
|**并行模式**|MIMD (多指令流多数据流)|**SIMT** (单指令流多线程) / SIMD|
|**延迟隐藏**|依靠 Cache|依靠**大量线程切换** (Context Switch)|

> **一句话总结**：CPU 像是一个知识渊博的教授（处理难题快），GPU 像是一群小学生（处理大量简单的加减法快）。

## 2. GPU 硬件架构核心概念

### 2.1 核心组件

- **SP (Streaming Processor)**：
    
    - 也称为 **CUDA Core**。
        
    - GPU 最基本的**运算单元** (ALU)，执行浮点和整数运算。
        
- **SM (Streaming Multiprocessor)**：
    
    - GPU 的核心**功能模块** (类似 CPU 的一个核，但包含很多 ALU)。
        
    - 一个 SM 包含：多个 SP、一组寄存器文件 (Register File)、共享内存 (Shared Memory/L1 Cache)、Warp 调度器等。
        
    - **映射关系**：一个 CUDA **Block** (线程块) 必须被调度到同一个 **SM** 上执行。
        

### 2.2 Warp (线程束) 与 Warp Divergence (分支发散)

- **Warp**：
    
    - **定义**：SM 中指令执行的**基本单位**。
        
    - **大小**：通常为 **32** 个线程。这 32 个线程**同时执行同一条指令** (SIMT)。
        
- **Warp Divergence (分支发散)**：
    
    - **现象**：当一个 Warp 内的线程遇到 `if-else` 分支时，如果一部分线程走 `if`，另一部分走 `else`。
        
    - **后果**：硬件会**串行化**执行。先让满足 `if` 的线程执行（此时走 `else` 的线程挂起），再让走 `else` 的线程执行。
        
    - **性能影响**：严重降低并行效率。
        
    - **优化**：尽量避免 Warp 内线程出现控制流分歧。
        

### 2.3 Occupancy (占用率)

- **定义**：SM 中**实际激活的 Warp 数量**与 **SM 支持的最大 Warp 数量**的比值。
    
- **意义**：Occupancy 越高，SM 就有越多的备选 Warp 可以切换，从而更好地**隐藏内存访问延迟**。
    
- **限制因素**：寄存器数量限制、Shared Memory 大小限制。
    

## 3. GPU 内存层次 (Memory Hierarchy) —— 重中之重

按照速度从快到慢排列：

|存储器类型|作用域|生命周期|速度|特点与优化关键|
|---|---|---|---|---|
|**Register (寄存器)**|Thread|Thread|最快|数量有限。用多了会发生 Register Spill (溢出到 Local Memory)，导致变慢。|
|**Shared Memory (共享内存)**|**Block**|Block|极快 (接近寄存器)|**用户可控的 L1 Cache**。用于 Block 内线程通信。需防 **Bank Conflict**。|
|**Local Memory (局部内存)**|Thread|Thread|慢 (存放在显存中)|名字叫 Local 但其实很慢！用于存放寄存器放不下的变量。|
|**Global Memory (全局内存)**|Application|Application|最慢 (高延迟)|容量最大。需防非合并访问 (**Coalesced Access**)。|

## 4. 内存访问优化 (两大杀手锏)

### 4.1 共享内存 Bank Conflict (存储体冲突)

- **机制**：Shared Memory 被划分为多个 **Bank** (通常 32 个，对应 Warp 的 32 个线程)。每个 Bank 每个周期只能服务一个地址请求。
    
- **冲突 (Conflict)**：当 Warp 内的多个线程尝试同时访问**同一个 Bank 的不同地址**时，访问必须串行化。
    
- **广播 (Broadcast)**：如果多个线程访问**同一个 Bank 的同一个地址**，不会冲突，而是广播数据。
    
- **解决**：通过改变数据布局（如 Padding）让线程访问错开 Bank。
    

### 4.2 全局内存 Coalesced Memory Access (合并访问)

- **定义**：当一个 Warp 内的 32 个线程访问 Global Memory 时，如果它们访问的地址是**连续且对齐**的，硬件可以将这 32 次访问合并为**最少数量** (如 1 次或 2 次) 的内存事务。
    
- **未合并 (Uncoalesced)**：如果线程访问地址是乱序或跨步很大的 (Strided)，硬件必须发起多次内存事务，导致带宽利用率极低。
    
- **优化法则**：确保 `Thread ID` 相邻的线程，访问的 `内存地址` 也是相邻的 (即 **SoA** 布局)。

# GPU 和 CUDA 编程 (Part 2: 编程与调试)

## 1. CUDA 线程层次结构 (Thread Hierarchy)

CUDA 采用三层结构来组织线程，这对应了硬件的 GPU -> SM -> SP 结构。

### 1.1 核心概念

- **Grid (网格)**：
    
    - 一次 Kernel 函数调用产生的所有线程的集合。
        
    - Grid 包含多个 Block。
        
- **Block (线程块)**：
    
    - Grid 的子集。
        
    - Block 包含多个 Thread。
        
    - **关键特性**：同一个 Block 内的线程可以**通过共享内存 (Shared Memory) 通信**，也可以通过 `__syncthreads()` 进行**同步**。不同 Block 之间的线程通常无法直接协作（除非通过全局内存原子操作，效率较低）。
        
- **Thread (线程)**：
    
    - 执行计算的最小单位。
        

### 1.2 内置变量与索引计算 (必考)

在 Kernel 函数中，可以通过以下内置变量获取当前线程的位置：

- `threadIdx.x/y/z`：线程在 Block 内的索引。
    
- `blockIdx.x/y/z`：Block 在 Grid 内的索引。
    
- `blockDim.x/y/z`：Block 的维度（包含多少个线程）。
    
- `gridDim.x/y/z`：Grid 的维度（包含多少个 Block）。
    

**全局索引计算公式 (1D)** —— _背下来，代码填空必用_：

```c
// 假设是 1D Grid 和 1D Block
int tid = blockIdx.x * blockDim.x + threadIdx.x;
if (tid < N) { ... }
```

## 2. 函数修饰符 (Qualifiers)

用于区分函数是在 CPU 上跑还是在 GPU 上跑，以及谁可以调用谁。

|修饰符|调用者 (Caller)|执行位置 (Executor)|用途|
|---|---|---|---|
|**`__global__`**|**Host (CPU)**|**Device (GPU)**|**核函数 (Kernel)** 入口。必须返回 `void`。调用是异步的。|
|**`__device__`**|Device (GPU)|Device (GPU)|GPU 内部的辅助函数。|
|**`__host__`**|Host (CPU)|Host (CPU)|普通的 C++ 函数（默认就是这个）。|
|`__host__ __device__`|Host 或 Device|Host 或 Device|该函数代码会生成两份，既能在 CPU 跑也能在 GPU 跑。|

## 3. 常用 CUDA 内存管理接口

注意：CUDA API 大多返回 `cudaError_t` 状态码，操作的指针是 `void**` 或 `void*`。

### 3.1 内存分配与释放

- **`cudaMalloc(void **devPtr, size_t size)`**
    
    - 在设备端（Global Memory）分配内存。
        
    - _示例_：`int *d_a; cudaMalloc((void**)&d_a, N * sizeof(int));`
        
- **`cudaFree(void *devPtr)`**
    
    - 释放设备端内存。
        

### 3.2 内存拷贝

- **`cudaMemcpy(void *dst, const void *src, size_t count, cudaMemcpyKind kind)`**
    
    - 这是同步拷贝（会阻塞主机直到拷贝完成）。
        
    - **`kind` (方向)** 是关键：
        
        - `cudaMemcpyHostToDevice` (CPU -> GPU)
            
        - `cudaMemcpyDeviceToHost` (GPU -> CPU)
            
        - `cudaMemcpyDeviceToDevice` (GPU -> GPU)
            

## 4. 共享内存 (Shared Memory) 的使用

共享内存是 Block 内线程通信的桥梁，速度极快。

### 4.1 静态分配 (Static Allocation)

- **时机**：编译时知道数组大小。
    
- **语法**：
    
    ```c
    __global__ void myKernel() {
        // 必须加 __shared__ 关键字
        __shared__ int s_data[256]; 
        // ... 使用 s_data
    }
    ```
    

### 4.2 动态分配 (Dynamic Allocation)

- **时机**：编译时不知道大小，由 Host 端在 Kernel 启动时指定。
    
- **语法**：
    
    1. **Kernel 定义**：使用 `extern` 关键字，不指定大小。
        
        ```c
        __global__ void myKernel() {
            extern __shared__ int s_data[]; // 它是空的，像个指针
            // ...
        }
        ```
        
    2. **Kernel 启动**：在 `<<<...>>>` 的**第三个参数**指定字节数。
        
        ```c
        // Grid, Block, SharedMemSize (Bytes)
        myKernel<<<grid, block, N * sizeof(int)>>>(...);
        ```
        

## 5. 线程同步 (Synchronization)

### 5.1 Block 内同步

- **API**: **`__syncthreads()`**
    
- **作用**：设置一个栅栏 (Barrier)。同一个 Block 内的所有线程必须都执行到这一行代码，才能继续往下执行。
    
- **场景**：主要用于**共享内存**的数据交换。
    
    - _步骤_：写入 Shared Mem -> `__syncthreads()` -> 读取 Shared Mem。
        
    - _若不加_：可能发生读后写 (WAR) 或写后读 (RAW) 的竞争冒险。
        

### 5.2 Host 端同步

- **API**: **`cudaDeviceSynchronize()`**
    
- **作用**：强制 Host (CPU) 等待，直到 Device (GPU) 上所有之前的任务（包括 Kernel 执行、异步拷贝）都完成。
    
- **场景**：由于 Kernel 启动是异步的，为了准确计时或确保结果已产生，Host 端常需调用此函数。
    

## 6. CUDA 调试工具 (CUDA-MEMCHECK)

根据大纲，重点了解 `cuda-memcheck` 工具集中的四个子工具的功能：

1. **`memcheck`** (Memory Check)
    
    - **功能**：检查内存错误。
        
    - **检测项**：内存越界访问 (Out of bounds)、非法指针访问、双重释放。类似于 CPU 上的 Valgrind。
        
2. **`racecheck`** (Race Check)
    
    - **功能**：检查数据竞争。
        
    - **检测项**：**共享内存 (Shared Memory)** 的数据竞争（写-写竞争，读-写竞争）。
        
    - _注意_：它主要检查 Shared Memory，不检查 Global Memory。
        
3. **`synccheck`** (Synchronization Check)
    
    - **功能**：检查同步错误。
        
    - **检测项**：**Warp 分支发散导致的 `__syncthreads()` 错误**。
        
    - _解释_：如果 `if (threadIdx.x < 16) { __syncthreads(); }`，只有一半线程到了栅栏，另一半没到，会导致死锁或未定义行为。此工具可检测这类问题。
        
4. **`initcheck`** (Initialization Check)
    
    - **功能**：检查未初始化访问。
        
    - **检测项**：读取了未初始化的**全局内存 (Global Memory)** 数据。

## 1. MPI 基础概念

### 1.1 MPI 是什么

- **定义**：MPI (Message Passing Interface) 是一个**消息传递库的标准**，而不是一种编程语言。
    
- **特点**：
    
    - 专为**分布式内存**架构设计（但也支持共享内存）。
        
    - 显式并行：程序员必须显式控制数据传输（发送/接收）。
        
    - SPMD（单程序多数据）模型：所有进程运行相同的可执行文件，但根据进程 ID 执行不同路径。
        

### 1.2 核心概念

- **通信域 (Communicator)**：
    
    - 定义了通信的范围。只有同一个通信域内的进程才能相互通信。
        
    - **`MPI_COMM_WORLD`**：默认的通信域，包含程序启动时的所有进程。
        
- **进程组 (Group)**：
    
    - 通信域背后的一组有序进程的集合。
        
- **秩 (Rank)**：
    
    - 进程在通信域中的唯一标识（ID），从 `0` 到 `N-1`。
        

## 2. MPI 六个基本函数 (必背)

几乎所有的 MPI 程序都必须包含这几个函数。

|函数名|功能描述|典型用法|
|---|---|---|
|**`MPI_Init`**|初始化 MPI 环境。必须是第一个调用的 MPI 函数。|`MPI_Init(&argc, &argv);`|
|**`MPI_Finalize`**|结束 MPI 环境。清理资源，必须是最后一个调用的 MPI 函数。|`MPI_Finalize();`|
|**`MPI_Comm_size`**|获取通信域中**进程的总数**。|`MPI_Comm_size(MPI_COMM_WORLD, &size);`|
|**`MPI_Comm_rank`**|获取当前进程在通信域中的**ID (Rank)**。|`MPI_Comm_rank(MPI_COMM_WORLD, &rank);`|
|**`MPI_Send`**|**发送**消息（阻塞）。|`MPI_Send(buf, count, type, dest, tag, comm);`|
|**`MPI_Recv`**|**接收**消息（阻塞）。|`MPI_Recv(buf, count, type, source, tag, comm, &status);`|

## 3. 点对点通信 (Point-to-Point)

### 3.1 两种通信机制 (Mechanisms)

1. **阻塞通信 (Blocking)**：
    
    - 调用返回时，MPI 库已经完成了缓冲区的处理（对于发送端，意味着发送缓冲区可以安全复用；对于接收端，意味着数据已到达）。
        
    - **风险**：容易导致死锁，CPU 在等待期间可能空转。
        
2. **非阻塞通信 (Non-blocking)**：
    
    - 调用立即返回，不等待通信完成。必须通过额外的检测函数（Wait/Test）来确认完成。
        
    - **优势**：允许**计算与通信重叠** (Overlapping)，提高效率。
        

### 3.2 四种通信模式 (Modes) —— 主要针对发送操作

- **标准模式 (Standard Mode)** - `MPI_Send`
    
    - MPI 自行决定使用哪种协议（通常小消息用 Eager 协议，直接发；大消息用 Rendezvous 协议，协商后再发）。
        
- **缓存模式 (Buffered Mode)** - `MPI_Bsend`
    
    - 用户提供缓冲区 (`MPI_Buffer_attach`)。发送操作将数据拷贝到缓冲区后立即返回，不依赖接收端。
        
- **同步模式 (Synchronous Mode)** - `MPI_Ssend`
    
    - 只有当接收端**开始接收**消息后，发送函数才返回。也就是“握手”成功后才结束。
        
- **就绪模式 (Ready Mode)** - `MPI_Rsend`
    
    - 发送端假设接收端**已经准备好**（已调用 Recv）。如果接收端没准备好，行为未定义（通常报错）。效率最高但最危险。
        

## 4. 非阻塞通信 (Non-blocking Communication)

核心思想：**启动 (Post) -> 计算 (Compute) -> 等待 (Wait)**。

### 4.1 常用函数

- **`MPI_Isend`**：启动非阻塞发送。返回一个 `request` 句柄。
    
- **`MPI_Irecv`**：启动非阻塞接收。返回一个 `request` 句柄。
    
- **`MPI_Wait`**：阻塞等待，直到指定的 request 完成。
    
- **`MPI_Test`**：非阻塞查询，检测 request 是否完成（返回 flag=true/false）。
    

### 4.2 阻塞 vs 非阻塞对比 (考点)
![[{4B528CDA-A54C-4F85-A8F0-BF7D5F0704D1}.png]]

|特性|阻塞通信 (Blocking)|非阻塞通信 (Non-blocking)|
|---|---|---|
|**函数返回时机**|通信完成后返回|启动通信后立即返回|
|**安全性**|发送缓冲区可立即修改|**不可**立即修改缓冲区 (直到 Wait 成功)|
|**计算重叠**|不支持 (CPU 等待网络)|**支持** (在通信期间 CPU 做计算)|
|**死锁风险**|高 (如两个进程互发)|低 (可以通过调整 Wait 顺序避免)|
|**复杂性**|简单|复杂 (需管理 Request 对象)|

## 5. 通信优化与重叠技术

### 5.1 捆绑发送接收 (`MPI_Sendrecv`)

- **问题**：如果进程 A 发给 B，同时 B 发给 A，都用 `MPI_Send` 先发后收，容易死锁。
    
- **解决**：`MPI_Sendrecv` 在一个调用中同时执行发送和接收，由 MPI 系统内部优化调度，**避免死锁**。
    

### 5.2 双缓冲 (Double Buffering)

- **原理**：使用两个缓冲区，一个用于当前的计算，另一个用于与邻居通信传输下一轮的数据。
    
- **目的**：实现**计算与通信的重叠**，隐藏通信延迟。
    

## 6. 集合通信 (Collective Communication)

**特点**：通信域内的**所有**进程都必须参与调用，否则会死锁。通常隐含了同步操作。

### 6.1 分类

- **从功能上**：
    
    1. **数据移动**：广播、散播、收集。
        
    2. **全局计算 (归约)**：求和、最大值等。
        
    3. **同步**：栅栏。
        
- **从通信方向上**：
    
    1. **一对多 (One-to-All)**：Bcast, Scatter。
        
    2. **多对一 (All-to-One)**：Gather, Reduce。
        
    3. **多对多 (All-to-All)**：Allgather, Allreduce, Alltoall。
        

### 6.2 常用函数 (看图记忆)

- **`MPI_Bcast`** (Broadcast)：根进程将一份数据**复制**给所有进程。
    
- **`MPI_Scatter`** (Scatter)：根进程将数组**切分**，分发给不同进程（每人拿一份）。
    
- **`MPI_Gather`** (Gather)：各进程的数据**收集**到根进程，拼接成一个数组。
    
- **`MPI_Reduce`** (Reduce)：各进程的数据进行**运算**（如求和 Sum），结果存放在根进程。
    
- **`MPI_Allgather`**：收集，但结果**分发给所有人**（= Gather + Bcast）。
    
- **`MPI_Allreduce`**：归约，但结果**分发给所有人**（= Reduce + Bcast）。
    
- **`MPI_Barrier`**：**同步栅栏**。所有进程到达此处后才能继续。
    

### 6.3 进程组与通信域管理

- **通信域分裂 (`MPI_Comm_split`)**：
    
    - 将一个大通信域（如 COMM_WORLD）切分成多个互不重叠的小通信域。
        
    - _典型场景_：将矩阵网格中的进程按“行”或“列”分组，以便在行内或列内进行集合通信。
        
- **分组求和示例**：先调用 `MPI_Comm_split` 按颜色（color）分组，然后在新的子通信域中调用 `MPI_Reduce`。
    

## 7. 用户自定义派生类型 (Derived Datatypes)

**目的**：一次性发送内存中**不连续**的数据，减少通信次数（降低延迟），提高带宽利用率。

### 7.1 连续数据类型 (Contiguous)

- **函数**：`MPI_Type_contiguous`
    
- **场景**：复制旧类型 `n` 次。本质上还是连续的，但可以把一个数组当做一个大对象发。
    

### 7.2 向量数据类型 (Vector) —— 重点

- **场景**：数据在内存中是等间隔分布的（例如发送矩阵的一**列**，而在 C 语言中矩阵是按行存储的）。
    
- **函数**：`MPI_Type_vector` / `MPI_Type_create_hvector` (以字节为单位)。
    
- **关键参数**：
    
    - `count`：块的数量。
        
    - `blocklength`：每个块包含的元素个数。
        
    - `stride`：块之间的步长（跨度）。
        

### 7.3 索引数据类型 (Indexed)

- **场景**：数据块的长度相同，但位置是任意的（不规则间隔）。
    
    - **函数**：`MPI_Type_create_indexed_block`
        
- **场景**：数据块的长度不同，位置也是任意的（最通用，最不规则）。
    
    - **函数**：`MPI_Type_indexed`
        
- **参数**：需要提供两个数组，分别指定每个块的**长度**和**位移 (Displacement)**。
    

**复习建议：**

1. **区分 Scatter 和 Bcast**：Scatter 是“分蛋糕”（每人一块），Bcast 是“发传单”（每人一张一样的）。
    
2. **区分 Gather 和 Reduce**：Gather 是“拼图”（数据量变大），Reduce 是“浓缩”（数据量变小，变成一个值）。
    
3. **填空题预测**：可能会让你填 `MPI_Init` 的参数，或者是写出计算全局 Rank 的公式。
