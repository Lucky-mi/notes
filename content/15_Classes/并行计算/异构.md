## 1. 异构计算的起源与动机

### 1.1 应用特性的复杂性 (为什么需要异构?)
现实应用通常由性质迥异的部分组成，单一类型的处理器无法在所有环节都达到最优：
- **并行性**: 易并行 vs 难并行 (串行)
- **访存模式**: 可预测 (规则) vs 不可预测 (随机)
- **任务类型**: 数据密集型 vs 计算密集型
- **通信需求**: 高带宽需求 vs 低带宽需求

> **核心逻辑**: "针对不同的应用特性配置不同的系统资源，用合适的工具做合适的事。"

### 1.2 资源管理的挑战
- **共享资源**: Cores, Caches, Interconnects, Memory, Power.
- **核心难点**: "What should be executed where with what resources?" (什么任务用什么资源在哪执行?)
- **解决之道**: 引入**异构并行编程模型**。
    - 目标: 自动管理资源，最大化运行效率。
    - 意义: **降低程序员的负担**。

## 2. 异构系统架构核心：CPU vs GPU

### 2.1 为什么选择异构？
- [cite_start]**同构痛点**: "一刀切"的硬件无法在所有任务上实现最优能效比 (Power/Performance) 。
- [cite_start]**异构优势**: **"专人专事"**。代码在最适合的硬件上运行 (e.g., 逻辑给 CPU，计算给 GPU) 。
- **系统特征**: 
    - 核心不对称 (Asymmetric Cores)
    - [cite_start]内存层次不对称 (Asymmetric Memory) [cite: 92, 114]

### 2.2 CPU 与 GPU 的架构对比 (必考)

| 维度       | CPU (Central Processing Unit)                               | GPU (Graphics Processing Unit)                                                   |
| :------- | :---------------------------------------------------------- | :------------------------------------------------------------------------------- |
| **定位**   | **延迟导向 (Latency Oriented)**                                 | **吞吐量导向 (Throughput Oriented)**                                                  |
| **擅长任务** | 复杂逻辑控制、分支跳转、操作系统调度                                          | 大规模数据并行计算、图形渲染                                                                   |
| **核心设计** | **Few Complex Cores**<br>- 强控制逻辑 (分支预测)<br>- 大缓存 (L3 Cache) | [cite_start]**Many Simple Cores**<br>- 弱控制逻辑<br>- 大量 ALU (计算单元) [cite: 220, 223] |
| **并行方式** | MIMD (多指令多数据)                                               | [cite_start]SIMD/SIMT (单指令多数据/多线程)                                               |
| **连接方式** | 内部直连内存                                                      | 通过 **PCIe** 连接主机，通常拥有独立显存                                                        |

> **关键概念**: **SIMD (Single Instruction Multiple Data)**
> 一个指令同时作用于多个数据点。例如，对一张图片的 100 万个像素点同时加 1，CPU 可能要循环 100 万次，GPU 可能只需几千个周期。

### 2.3 典型协作模式 (Offloading Model)
1. **CPU (Host)**: 执行串行代码，准备数据。
2. **Data Transfer**: 通过 PCIe 将数据从 CPU 内存拷贝到 GPU 显存。
3.**GPU (Device)**: 执行计算密集型内核 (Kernel) 。
3. **Data Transfer**: 将结果拷回 CPU。

## 3. 异构计算硬件对比 (四大金刚)

### 3.1 核心对比表 (Exam Priority: High)

| 维度 | **CPU** | **GPU** | **FPGA** (半定制) | **ASIC** (全定制) |
| :--- | :--- | :--- | :--- | :--- |
| **全称** | Central Processing Unit | Graphics Processing Unit | Field Programmable Gate Array | Application Specific Integrated Circuit |
| **灵活性** | 软件灵活，硬件固定 | 软件灵活 (并行)，硬件固定 | **硬件可重构** (高) | **无** (硬件完全固定) |
| **能效比** | 低 | 中 (适合并行) | 高 | **极高 (最优)** |
| **开发成本** | 低 (一次性编程) | 中 | 高 | **极高** (掩膜/流片成本) |
| **适用场景** | 逻辑控制、OS | 图像处理、深度学习训练 | 原型验证、低延迟通信 | 手机基带、专用算法加速 |

### 3.2 性能-开发难度光谱 (Ranking)

> **规律**: 效率越高，开发越难，灵活性越差。

- **编程容易度 (由易到难)**:
  1. CPU
  2. GPU
  3. DSP
  4. FPGA
  5. ASIC

- **性能/能效 (由高到低)**:
  1. ASIC (王者)
  2. FPGA
  3. DSP
  4. GPU
  5. CPU

### 3.3 异构设计的挑战
- **硬件层**: 资源选择与配置、异构资源衔接、管理配置。
- **软件层**: **"软硬件协同设计 (Co-design)"** 变得重要。
    - 难点: 任务划分、调度同步、代码移植与维护。

### 🎯 期末考题预测 (重点：对比与排序)

- **【填空/排序题】（必考）**
    
    - **题目**：请将以下处理器按**能效比（Energy Efficiency）**从高到低排序：CPU, GPU, ASIC, FPGA。
        
    - **答案**：ASIC > FPGA > GPU > CPU
        
    - **变体**：按**编程灵活性**从高到低排序？
        
    - **答案**：CPU > GPU > FPGA > ASIC （注：这里指软件开发的灵活性，FPGA 虽硬件可变，但开发门槛极高，通用软件编程灵活性不如 CPU/GPU）。
        
- **【简答题】**
    
    - **题目**：简述 FPGA 与 ASIC 的主要区别。
        
    - **答案**：
        
        1. **可重构性**：FPGA 是“现场可编程”的，硬件逻辑可以在制造后通过编程重新配置；ASIC 是“专用集成电路”，设计完成后电路即固定，无法更改。
            
        2. **成本**：FPGA 适合小批量生产或原型验证，单片成本较高；ASIC 前期设计（NRE）成本极高，但适合大批量生产，量产后单片成本低。
            
        3. **上市时间**：FPGA 无需流片，上市时间短；ASIC 设计周期长。
            
        4. **性能/功耗**：同等工艺下，ASIC 的性能和功耗通常优于 FPGA。

### 🎯 期末考题预测 (重点：系统比较)

根据你的考纲“比较异构系统”，这类题目通常是**大题**或**多选题**。

- **【简答/分析题】（五星重点）**
    
    - **题目**：从硬件架构的角度，分析 CPU 和 GPU 的主要区别，并说明为什么 GPU 更适合进行大规模并行计算？
        
    - **解题思路**：
        
        1. **定位不同**：CPU 是低延迟导向，GPU 是高吞吐量导向。
            
        2. **晶体管分配**：CPU 大量晶体管用于**控制逻辑（Control）和缓存（Cache）**，用于优化单线程性能；GPU 大量晶体管用于**计算单元（ALU）**，用于并行处理 。
            
        3. **并行模式**：GPU 采用 **SIMD** 架构，能够在一个指令周期内处理大量数据，非常适合图像处理、矩阵运算等数据密集型任务。
            
        4. **核心数量**：GPU 拥有成百上千个流处理器核心，而 CPU 核心较少。
            
- **【填空题】**
    
    - **题目**：在典型的异构系统中，CPU 和独立 GPU 之间通常通过 \__________ 总线连接。由于两者拥有独立的存储空间，编程时通常需要进行 \__________ 。
        
    - **答案**：PCIe ；数据拷贝（或显式内存传输）

## 4. 异构编程模型基础与 CUDA

### 4.1 编程模型的作用
异构系统极为复杂，编程模型作为**App**与**Hardware**之间的**桥梁**，主要解决以下痛点：
1. **提供接口**: 让程序员无需关注底层硬件细节 (Hardware Abstraction)。
2. **管理资源**: 自动处理**任务划分**、**调度**、**数据分布**、**同步与通信**。

### 4.2 常见模型一览
- **CUDA**: NVIDIA 专用，性能最好，生态最全。
- **OpenCL**: 开放标准 (Apple, Intel, AMD, NVIDIA)，通用性强但代码繁琐。
- **OpenMP / OpenACC**: 基于编译指导语句 (Directives)，简单易用。
- **ROCm**: AMD 的开源平台，对标 CUDA。

### 4.3 CUDA (Compute Unified Device Architecture)
- **厂商**: NVIDIA。
- **语言**: C/C++ 的扩展。
- **架构**:
    - **Host (主机/CPU)**: 处理串行逻辑。
    - **Device (设备/GPU)**: 处理并行计算。
- **编程模式**: **SIMT (单指令多线程)**。

### 4.4 CUDA 程序的标准生命周期 (代码题考点)
记忆口诀：**申 -> 搬 -> 算 -> 搬 -> 释**

1. **申请显存**: `cudaMalloc((void**)&d_ptr, size)`
2. **H2D 拷贝**: `cudaMemcpy(d_ptr, h_ptr, size, cudaMemcpyHostToDevice)`
3. **Kernel**: `func<<<blocks, threads>>>(args)`  <-- **最显著特征**
4. **D2H 拷贝**: `cudaMemcpy(h_ptr, d_ptr, size, cudaMemcpyDeviceToHost)`
5. **释放显存**: `cudaFree(d_ptr)`

- **【选择题】**
    
    - **题目**：以下哪项不是异构并行编程模型的主要功能？ A. 任务划分与调度 B. 硬件电路的物理设计 C. 数据分布管理 D. 同步与通信机制
        
    - **答案**：B（那是 ASIC 设计师的事）
        
- **【代码填空/分析题】（五星重点）**
    
    - **题目**：阅读以下 CUDA 伪代码，补充完整：
        ```c
        float *h_A, *d_A; // h_A 是主机指针，d_A 是设备指针
        // 1. 在 GPU 上分配内存
        _________((void**)&d_A, size); 
        // 2. 将数据从主机拷贝到设备
        cudaMemcpy(d_A, h_A, size, _________);
        // 3. 启动内核函数 vecAdd，使用 N 个线程
        vecAdd<<<1, N>>>(d_A, ...);
        ```
        
    - **答案**：`cudaMalloc`；`cudaMemcpyHostToDevice`
        
- **【简答题】**
    
    - **题目**：简述在 CUDA 编程模型中，Host 和 Device 分别指什么？它们如何分工？
        
    - **答案**：Host 指 CPU 及其内存，Device 指 GPU 及其显存。Host 负责复杂的串行逻辑控制、I/O 操作以及初始化工作；Device 负责执行高密集度的数据并行计算任务（Kernel）。
