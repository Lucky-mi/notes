# 任务划分
### **🎓 期末考题预测**

根据这一页的内容，考题通常考察你对划分策略的理解和辨析。

#### **题型 1：概念辨析（选择/填空）**

- **题目**：在设计并行程序时，将计算工作划分给多个任务的两种基本方法是 ________ 和 ________。
    
- **答案**：域分解（Domain Decomposition）、功能分解（Functional Decomposition）。
    
- **题目**：如果一个并行任务是将 1000x1000 的图像进行灰度化处理，将图像切割成 4 个 500x500 的子区域分别处理，这种划分方法属于 ________。
    
- **答案**：域分解（或数据分解）。
    

#### **题型 2：分析与简答（重点）**

- **题目**：请简述 **Block（块状）划分** 与 **Cyclic（循环）划分** 的区别，并说明在什么情况下 Cyclic 划分比 Block 划分更有优势？
    
- **参考答案**：
    
    - **区别**：Block 划分是将连续的数据块分配给任务；Cyclic 划分是将数据按照固定的步长（如轮询）交错分配给任务。
        
    - **Cyclic 的优势场景**：当数据各部分的计算负载**不均匀**（即有的数据处理起来快，有的慢），且这种负载分布具有局部聚集性时，Block 划分可能导致某些任务很快做完，某些任务很久做不完（负载不均衡）。而 Cyclic 划分可以将重负载和轻负载的数据分散给不同的任务，从而实现更好的**负载均衡**。
### **任务划分（三）—— 依赖关系**

这一页主要讲我们在划分任务时要遵循的原则，以及什么东西会阻碍我们随意划分。

#### **1. 快速过一遍的原则（略讲）**

这些是设计并行程序的“经验之谈”：

- **动静结合**：任务划分不一定是写代码时（静态）定死的，程序跑起来时（动态）也可以产生新任务 。
    
- **多多益善**：尽量把问题切得碎一点，任务数量最好多于处理器核心数，这样方便调度器做负载均衡 。
    
- **混合双打**：有时候既要用域分解，又要用功能分解 。
    
- **权衡（Trade-off）**：切得太细，管理任务的开销（创建、调度）就大了；切得太粗，并行度又不够。要找平衡点 。
    

#### **2. 核心难点与考点：数据依赖 (Data Dependencies)** 🌟🌟🌟

这是本页的**绝对重点**。任务能不能并行，全看它们之间有没有“关系”。 PPT 提到了三种最经典的数据依赖 ，这在考研 408 计算机组成原理或体系结构中也是必考内容：

我们可以把“存储单元”想象成一个**黑板**，两个任务（A 和 B，假设 A 在前，B 在后）都要去操作这个黑板。

1. **RAW (Read After Write) —— 写后读**
    
    - **也就是**：A 先写，B 再读。
        
    - **情况**：A 计算出一个结果，B 需要用这个结果继续算。
        
    - **例子**：
        ```c
        A: x = 10;
        B: y = x + 5; // B必须等A写完x才能读
        ```
        
    - **后果**：这是**真依赖 (True Dependence)**。B 必须等 A 做完。**无法并行**（除非有数据转发等硬件技术，但在软件层面必须同步）。
        
2. **WAR (Write After Read) —— 读后写**
    
    - **也就是**：A 先读，B 再写。
        
    - **情况**：A 需要读旧值，B 紧接着要更新这个值。
        
    - **例子**：
        
        ```c
        A: y = x + 5; // A需要读旧的x
        B: x = 20;    // B要写新的x
        ```
        
    - **后果**：这是**反依赖 (Anti-Dependence)**。如果 B 跑得太快，在 A 还没读之前就把 `x` 改成了 20，A 就读错了。
        
    - **破解**：这通常是因为复用了变量名。如果把 B 里的 `x` 改名叫 `x_new`，这种依赖就消失了（重命名技术）。
        
3. **WAW (Write After Write) —— 写后写**
    
    - **也就是**：A 先写，B 再写。
        
    - **情况**：A 和 B 都要往同一个地方写数据。
        
    - **例子**：

        ```c
        A: x = 10;
        B: x = 20;
        ```
        
    - **后果**：这是**输出依赖 (Output Dependence)**。最后 `x` 的值必须是 20（B 的结果）。如果 B 先写了，A 后写，最后 `x` 变成了 10，程序逻辑就错了。
        
    - **破解**：同样可以通过变量重命名来解决。
        

> **总结**：只有 **RAW** 是真正的逻辑依赖，这也是限制并行的最大瓶颈。WAR 和 WAW 通常是由于“抢占存储空间（名字）”引起的，可以通过技术手段（如变量重命名、私有化）消除。

#### **题型 1：代码分析题（必考）**

- **题目**：分析以下代码片段中指令 S1 和 S2 之间存在哪种数据依赖？
    ```c
    S1: A = B + C;
    S2: C = A * 2;
    ```
    
- **答案**：**RAW (写后读) / 真依赖**。
    
    - _解析_：S1 写入 `A`，S2 读取 `A`。S2 必须等 S1 完成。
        

#### **题型 2：多选/辨析题**

- **题目**：在并行程序设计中，以下哪种数据依赖通常被称为“真依赖”，且无法通过简单的变量重命名来消除？ A. WAR (读后写) B. WAW (写后写) C. RAW (写后读) D. RAR (读后读)
    
- **答案**：**C**。
    
    - _解析_：RAW 传递了数据流，是逻辑上的必需。WAR 和 WAW 是名字冲突。RAR（两个都读）不冲突，可以完美并行。
### **任务划分（四）—— 自动划分与循环依赖**

#### 1.谁来进行任务划分？

- **主流现状**：大多数情况下由 **程序员** 手动进行。
    
- **理想情况**：希望由 **编译器** 自动进行（但非常难）。
    

#### 2.自动并行化（编译器）面临的挑战

编译器想要自动把串行代码变成并行代码，必须精准识别所有依赖。这很难，原因如下：

- **复杂分析**：必须正确分析程序，识别所有潜在的依赖关系。
    
- **运行时依赖**：有些依赖在写代码时（编译时）看不出来，只有程序跑起来（运行时）才知道。
    
    - _例如_：`A[i] = A[j]`，如果 `i` 和 `j` 的值是用户输入的，编译器就不知道它们会不会指向同一个位置（指针别名问题）。
        

#### 3.核心考点：循环依赖分析 (Loop Dependence)

这是期末和考研最喜欢考的代码分析题。编译器目前研究最多的是对**循环**的识别。

- **类型一：DOALL Loop (完全并行循环)**
    
    - **特征**：循环的每一次迭代（Iteration）都是**完全独立**的，互不干扰。
        
    - **数据依赖**：不存在跨迭代的数据依赖。
        
    - **处理**：可以直接并行化，分配给不同的核同时跑。
        
    - **代码示例**：

        ```c
        // 这里的 i 只跟自己有关，a[i] 的计算不依赖其他位置
        for (i=0; i<n; i++) {
            a[i] = b[i] + c[i];
        }
        ```
        
    - **结论**：这是最完美的并行场景。
        
- **类型二：DOACROSS Loop (跨迭代依赖循环)**
    
    - **特征**：当前的迭代**依赖于**之前的迭代产生的结果。
        
    - **数据依赖**：存在**循环携带依赖 (Loop-carried Dependence)**，通常是 RAW（写后读）。
        
    - **处理**：**不能**直接简单并行，需要同步机制或者只能串行执行。
        
    - **代码示例**：
        
        ```c
        // 计算 a[i] 需要用到 a[i-1]，必须等上一轮算完
        for (i=1; i<n; i++) { // 注意通常从1开始，防越界
            a[i] = a[i-1] + b[i] + 1;
        }
        ```
        
    - **结论**：这是并行的“杀手”，通常导致流水线停顿或无法并行。

### **🎓 期末考题预测**

这一页的考题非常直观，就是给你一段循环代码，让你判断能不能并行。

#### **题型：代码分析（必考）**

- **题目**：请分析下列两个循环片段，指出哪一个可以标记为 `DOALL` 并行执行，哪一个属于 `DOACROSS`，并说明理由。
    
    - **代码 A**：

        ```c
        for(int i=1; i<N; i++)
            A[i] = A[i] + B[i];
        ```
        
    - **代码 B**：

        ```c
        for(int i=1; i<N; i++)
            A[i] = A[i-1] + B[i];
        ```
        
- **参考答案**：
    
    - **代码 A 是 DOALL**。
        
        - _理由_：第 `i` 次迭代只读写 `A[i]` 和 `B[i]`，与其他迭代（如 `i-1` 或 `i+1`）没有任何数据交叉，无数据依赖。
            
    - **代码 B 是 DOACROSS**。
        
        - _理由_：第 `i` 次迭代在计算 `A[i]` 时，需要读取 `A[i-1]` 的值。而 `A[i-1]` 是上一次迭代（第 `i-1` 次）刚刚写入的。存在 **RAW（写后读）** 依赖，且该依赖跨越了循环迭代（Loop-carried dependence），因此无法直接并行。

# 调度
### **调度 (Scheduling) —— 概念篇 (PPT 8-10)**

#### 1.什么是调度？

- **定义**：决定哪个**任务 (Task)** 运行在哪个 **硬件处理单元 (PE/Core)** 上。
    
- **核心流程**：这是一个两层的映射过程：
    
    1. **Assignment (分配)**：把这一大堆“任务 (Tasks)”分配给若干个“软件线程 (Threads/Workers)”。
        
    2. **Mapping (映射)**：把这些“软件线程”分配给具体的“硬件处理单元 (Cores/PEs)”。
        

#### 2.调度的终极目标

- **两大目标**：
    
    1. **最小化**程序执行时间。
        
    2. **最大化**资源（CPU）利用率。
        
- **关键抓手**（怎么做才能达成目标？）：
    
    - **负载均衡 (Load Balance)**：让大家都有活干，别忙的忙死，闲的闲死。
        
    - **局部性 (Locality)**：尽量让任务访问本地内存，减少去远处搬运数据的开销。
        
    - **减少通信与同步开销**：少说话，多干活。
        

#### 3.谁来负责调度？

- **程序员**：负责“任务划分”（怎么切蛋糕）。
    
- **运行时系统 (Runtime System)**：负责“任务调度”（怎么分蛋糕）。比如 OpenMP、Cilk 这些框架的底层系统。
    
    - _注_：这也是为什么我们写 OpenMP 时只需要写 `#pragma omp parallel`，具体的线程分配是库函数帮我们做好的。

## **调度与硬件映射 (PPT 11-12)**

这两页的核心从软件层面的“任务”下沉到了硬件层面的“拓扑结构”。
### **1. 核心概念：映射 (Mapping)**

- **定义**：将 **软件线程 (Threads)** 分配给具体的 **硬件处理单元 (PEs/Cores)** 的过程。
    
- **通俗理解**：公司招来了 4 个实习生（线程），现在要给他们安排具体的工位（硬件核心）。
    

### **2. 关键考点：CPU 亲和性 (CPU Affinity)**

这是一个非常重要的概念，请务必在笔记中高亮。

- **定义**：允许操作系统将某个特定的软件线程（或进程）**绑定 (Bind/Pin)** 到一个或一组特定的硬件核心上，不让它乱跑。
    
- **为什么要设置亲和性？（两大理由）**
    
    1. **避免缓存失效 (Cache Locality)**
        
        - _现象_：如果没有亲和性，操作系统调度器可能会让线程一会儿在 Core 0 上跑，一会儿迁移（Migrate）到 Core 1 上跑。
            
        - _后果_：线程在 Core 0 上跑热乎的数据（在 L1/L2 Cache 里），迁移到 Core 1 后就全没了（Cache Miss），必须重新从内存拉取，导致性能断崖式下跌。
            
        - _口诀_：**线程乱跑，缓存白搞。**
            
    2. **NUMA 架构优化**
        
        - _现象_：在 NUMA（非一致性内存访问）系统中，内存是分块管理的。
            
        - _优化_：将线程“钉”在某个 NUMA 节点内，让它只访问这个节点“本地”的内存。
            
        - _原理_：**访问本地内存速度 >> 访问远程内存速度**。
            

### **3. 硬件架构解析：NUMA 拓扑图**

PPT 11 是示意图，PPT 12 是真实服务器（通过 `lstopo` 命令生成）的拓扑图。我们需要读懂这种层级关系：

> [!NOTE] **层级结构 (Hierarchy)**
> 
> - **Machine**: 整个服务器（例如 PPT 中总共有 503GB 内存）。
>     
> - **Package (Socket)**: 物理 CPU 插槽（比如你是双路服务器，就有 Package 0 和 Package 1）。
>     
> - **NUMA Node**: 逻辑上的内存节点。通常一个 Package 对应一个或多个 NUMA Node。
>     
>     - _关键点_：每个 Node 有自己**私有**的一块内存（例如 Node P#0 有 251GB）。
>         
> - **Core**: 物理核心。
>     
> - **PU (Processing Unit)**: 逻辑处理单元（通常指超线程 Hyperthread）。
>     
>     - _例子_：PPT 11 中，`Core P#0` 下面有 `PU P#0` 和 `PU P#64`。这意味着开启了超线程，这俩逻辑核共享同一个物理核的运算资源。
>         

- **图示分析 (PPT 12 详解)**
    
    - 你看那张复杂的绿图，它展示了更真实的物理连接。
        
    - **PCI 设备绑定**：注意看网卡（`Net eno1`）是挂在 `NUMA Node P#0` 下面的。
        
    - **实战意义**：如果你的程序是处理网络包的，你的线程最好绑定在 `NUMA Node P#0` 的 CPU 核上。为什么？因为网卡数据直接进这块内存，CPU 读取最快。如果你绑到了 `Node P#1`，数据就要跨 CPU 传输（QPI/UPI 总线），延迟大大增加。

### **🎓 期末考题预测**

这一块是体系结构和操作系统的交叉点，题目通常比较灵活。

#### **题型 1：名词解释 / 简答（必背）**

- **题目**：什么是 **CPU 亲和性 (CPU Affinity)**？在并行计算中设置 CPU 亲和性有什么好处？
    
- **参考答案**：
    
    - **定义**：CPU 亲和性是指将特定的进程或线程绑定到特定的 CPU 核心或核心集合上，使其仅在指定的硬件单元上运行。
        
    - **好处**：
        
        1. **提高缓存命中率**：防止线程在不同核心间迁移导致 L1/L2 缓存失效。
            
        2. **优化 NUMA 性能**：保证线程优先访问本地内存节点，减少跨节点的远程内存访问延迟。
            

#### **题型 2：分析题（高分题）**

- **题目**：在一个双路 CPU 服务器（NUMA 架构）上，网卡连接在 CPU 0 上。某网络密集型并行程序启动了 4 个线程进行数据包处理。
    
    - (1) 如果不进行任何设置，可能会出现什么性能问题？
        
    - (2) 为了达到最佳性能，应如何进行线程调度映射？
        
- **参考答案**：
    
    - (1) **问题**：操作系统可能会将线程调度到 CPU 1 上。此时，线程需要处理的数据在 CPU 0 的内存/缓存中（因为网卡在 CPU 0），导致大量的跨 CPU 远程内存访问（Remote Memory Access），增加延迟，降低吞吐量。同时，线程迁移也会导致 Cache 抖动。
        
    - (2) **优化**：利用 CPU 亲和性技术，将这 4 个线程**绑定（Pin）** 到 CPU 0 的物理核心上，确保“计算紧随数据”（Compute follows Data），实现本地内存访问和缓存复用。
## **调度策略与负载均衡 (PPT 13-15)**

### **PPT 13：谁来决定线程分配？ (Mapping)**

线程分配（Mapping）不仅仅是操作系统的事，不同层级都在尝试接管这个权力，有时甚至会“打架”。

#### 1.分配的执行者

- **程序员**：通过代码手动管理。
    
    - _手段_：使用 `numactl` 或 `taskset` 等工具，或者在代码中设置亲和性 。
        
- **操作系统 (OS)**：最底层的默认分配者 。
    
- **编译器**：在编译阶段分析代码并生成分配指令 。
    
- **硬件**：例如 GPU 中，硬件调度器决定 CUDA 线程块映射到哪个 SM（流多处理器）上 。
    

#### 2.策略冲突 (Trade-off)

这是设计的难点，存在两种截然相反的优化思路：

- **思路 A：把“相关”的线程放在一起**
    
    - _目的_：利用数据共享，提高缓存命中率，减少通信延迟。
        
- **思路 B：把“不相关”的线程放在一起**
    
    - _目的_：如果几个线程都在抢同一个资源（如浮点运算单元），不如把它们拆开，分别和做整数运算的线程放在一起，提高处理器硬件的利用率（掩盖延迟）。
        

> **结论**：调度是一个 **NP-完全问题 (NP-Complete)** ，数学上无法找到完美的最优解，只能找近似解。

### **PPT 14：负载均衡 (Load Balance)**

#### 1.定义

- **目标**：将工作大致相等地分配给所有处理单元（PE）。
    
- **核心指标**：让所有处理器始终保持忙碌，**最小化空闲时间**。
    

#### 2.完美的代价

- **悖论**：想要达到“绝对完美的负载均衡”，往往需要极高频的任务调度和状态同步。
    
- **代价**：**同步开销 (Synchronization Overhead)** 会变得巨大。有时候稍微不均衡一点，比为了均衡而频繁通信反而跑得更快。
    

#### 3.负载不均衡 (Load Imbalance) 的后果

- **木桶效应**：并行程序的总执行时间取决于**最慢**的那个线程。
    
- **串行瓶颈**：慢线程导致其他快线程都在空转（Idle），严重拖累整体性能。

### **PPT 15：调度算法分类体系**

这一页是后续内容的**总纲**，非常重要，请务必记住这张分类图 。

#### 1.负载不均衡的原因

- **任务本身**：有的任务本来就难算（如图像里有的地方纹理复杂），或者任务量是动态变化的。
    
- **任务间关系**：复杂的依赖、通信同步导致等待。
    
- **硬件环境**：其他程序抢占资源、缓存未命中导致访存延迟波动。
    

#### **2. 调度算法分类 (Taxonomy)**

- **静态调度 (Static Scheduling)**：
    
    - 运行前就把活分好了，运行中不再变。
        
    - _适用_：任务量已知且固定的场景。
        
- **动态调度 (Dynamic Scheduling)**：
    
    - 运行过程中根据忙闲程度实时分配。
        
    - _细分_：
        
        1. **自调度 (Self-Scheduling)**：大家去公共池子里抢活干。
            
        2. **工作窃取 (Work-Stealing)**：忙的人做完了，去偷闲的人（或者反过来）的活。
            
        3. **工作共享 (Work-Sharing)**：集中的任务分发。

- **题目**：在进行线程映射时，为什么有时候需要将“相关的线程”放在一起，有时候又需要将“不相关的线程”放在一起？

## **静态调度 (PPT 16-18)**

### **1. 静态调度 (Static Scheduling) 定义**

- **核心逻辑**：在程序运行之前（或者循环开始之前），就把任务平均分配好了。
    
- **分配原则**：为每个线程 (Worker) 分配相同数量的工作。
    
- **优点**：
    
    - **简单**：逻辑非常直观。
        
    - **零开销**：运行时不需要额外的调度计算，也没有抢占锁的开销。
        
- **缺点**：如果任务有些难算、有些好算（执行时间不同），会导致负载不均衡。
    
- **适用场景**：任务数量已知，且每个任务的执行时间是**可预测的**（即大家干活速度一样）。
    

### **2. 半静态调度 (Semi-static Scheduling)**

- 这是一类特殊的静态调度。
    
- **场景**：虽然不知道任务具体多重，但因为任务是重复执行的（比如视频处理每一帧的逻辑差不多），我们可以“预测”。
    
- **方法**：**Profiling（性能分析）**。先跑一次记录一下各部分的时间，下一次运行时根据上次的记录来调整分配比例。

### **3. 代码实例与块 (Chunk) 的概念 (PPT 17-18)**

这里出现了一个非常关键的 OpenMP 语法和概念：**Chunk (块)**。

- **代码示例**：
    
    ```c
    #pragma omp for schedule(static, 5)
    ```
    
    - `static`: 指定使用静态调度。
        
    - `5`: **Chunk Size (块大小)**。表示每次一口气给线程分 5 个循环迭代。
        
- **调度演示**：
    
    - **场景**：有 2 个处理器核心（Core 0, Core 1），共 30 次循环迭代（Index 0-29）。
        
    - **分配逻辑 (Round-Robin 轮询)**：
        
        - **Core 0**: 拿第 1 块 (0-4), 第 3 块 (10-14), 第 5 块 (20-24)...
            
        - **Core 1**: 拿第 2 块 (5-9), 第 4 块 (15-19), 第 6 块 (25-29)...
            
    - **问题展现 (PPT 18 图示)**：
        
        - PPT 18 的图展示了一个典型的**负载不均衡**。
            
        - 假设偶数块的任务特别重（耗时），奇数块的任务特别轻。
            
        - 如果运气不好，Core 0 分到的全是大任务，Core 1 分到的全是小任务。
            
        - **结果**：Core 1 早就干完了在**空等 (Idle)**，Core 0 还在拼命干。这就是静态调度的死穴——**对不均匀任务适应性差**。

#### **题型 1：分配计算题（必会）**

- **题目**：假设有 4 个线程（T0, T1, T2, T3）和 20 个循环迭代（0-19）。使用 `schedule(static, 2)` 策略，请写出线程 T1 将会处理哪些迭代索引？
    
- **分析步骤**：
    
    1. **确定块大小**：Chunk = 2。
        
    2. **划分块**：
        
        - Block 0: [0, 1] -> T0
            
        - Block 1: [2, 3] -> **T1**
            
        - Block 2: [4, 5] -> T2
            
        - Block 3: [6, 7] -> T3
            
        - Block 4: [8, 9] -> T0 (轮回到 T0)
            
        - Block 5: [10, 11] -> **T1**
            
        - ...以此类推。
            
- **答案**：T1 将处理 **[2, 3]** 和 **[10, 11]** 以及 **[18, 19]**。
    

#### **题型 2：分析题**

- **题目**：在某些情况下，为什么将 Chunk Size 设置为 1（即 `schedule(static, 1)`，也称为 Cyclic 调度）可能比设置较大的 Chunk Size 具有更好的负载均衡效果？但同时会带来什么负面影响？
    
- **参考答案**：
    
    - **负载均衡**：当循环迭代的计算量变化很大且没有规律时，Chunk=1 可以像发牌一样把任务打散，最大概率地让每个线程分到的总工作量趋于平均。
        
    - **负面影响**：Chunk=1 破坏了数据的**空间局部性 (Spatial Locality)**，因为线程访问的数据在内存中可能是不连续的，会导致缓存命中率下降；同时如果任务粒度太小，可能导致伪共享 (False Sharing) 问题。

## **动态调度算法进阶 (PPT 19-21)**

动态调度的核心思想是：**“能者多劳”**。谁跑得快，谁就多干点，不用像静态调度那样死板地平均分。

### **1. 基础自调度 (Self Scheduling) [PPT 19]**

1

- **机制**：维护一个**共享的任务队列**。
    
- **流程**：
    
    - 所有处理器 (Workers) 只要空闲了，就去队列里**取一个**任务来执行。
        
    - 如果有新任务生成，也放进这个队列。
        
- **缺点**：**锁竞争 (Locking)**。
    
    - _比喻_：就像食堂只有一个打饭窗口（任务队列），如果你一次只领一粒米（一个任务），那你大部分时间都在排队（抢锁），而不是在吃饭（执行任务）。
        
    - _后果_：调度开销极大，可能得不偿失。
        

### **2. 改进：基于块的自调度 (Chunk-based) [PPT 20]**

2

- **策略**：为了减少排队次数，咱们一次领一碗饭，而不是一粒米。
    
- **做法**：每次给空闲处理器分配**固定大小 (Fixed Size)** 的块（Chunk）。
    
- **权衡**：
    
    - 块太大 $\rightarrow$ 容易负载不均衡（回到静态调度的问题）。
        
    - 块太小 $\rightarrow$ 抢锁太频繁（回到基础自调度的问题）。
        

### **3. 高级算法一：指导性自调度 (GSS, Guided Self Scheduling) [PPT 20]** 🌟

这是一个非常聪明的算法，采用了**“先大后小”**的策略。

- **核心逻辑**：刚开始任务多，大家都很饿，为了减少抢锁次数，每人发一大包任务；等到最后任务所剩无几，为了防止有人闲着，每人发一小点任务。
    
- 公式（必背）：
    
    $$K_i = \lceil R_i / p \rceil$$
    
    - $K_i$：第 $i$ 次分配的任务数量（块大小）。
        
    - $R_i$：当前**剩余**的任务总数。
        
    - $p$：处理器 (PE) 的个数。
        
    - $\lceil \dots \rceil$：向上取整 (Ceiling)。
        
- **计算演示**（假设 $N=1000$ 个任务，$P=4$ 个处理器）：
    
    1. **第一次分配**：剩余 1000，分配 $1000/4 = 250$ 个。
        
    2. **第二次分配**：剩余 $1000 - 250 = 750$，分配 $\lceil 750/4 \rceil = 188$ 个。
        
    3. **第三次分配**：剩余 $750 - 188 = 562$，分配 $\lceil 562/4 \rceil = 141$ 个。
        
    
    - _特点_：块大小呈**指数级衰减**。
        

### **4. 高级算法二：因子自调度 (FSS, Factoring Self-Scheduling) [PPT 21]**

4

- **逻辑**：GSS 衰减得太快了（一开始分太大），FSS 试图把任务分成若干个“批次 (Batch)”，每一批次里，大家平分一部分任务。
    
- 公式：
    
    $$K_i = \frac{R_i}{\alpha \times P}$$
    
    - 通常 $\alpha = 2$。
        
    - 意味着每次把剩余任务的一半拿出来，平分给 $P$ 个处理器。
        
- **计算演示**（$N=1000, P=4, \alpha=2$）：
    
    1. **第一批**：拿出一半 ($500$)，大家平分。每个 Chunk = $500/4 = 125$。所有处理器都领 125 个。
        
    2. **第二批**：剩下 500，再拿出一半 ($250$)，大家平分。每个 Chunk = $250/4 = 62$（取整）。
        

### **5. 高级算法三：梯形自调度 (TSS, Trapezoid Self-Scheduling) [PPT 21]**

5

- **逻辑**：让块大小**线性减少**，而不是指数级减少。这就像画一个梯形。
    
- **公式**：
    
    - 设定**首项** $F$（第一次分多少）和 **末项** $L$（最后一次分多少）。
        
    - 计算分配次数（高度）$H = \frac{2 \times N}{F+L}$。
        
    - 计算步长（斜率）$\alpha = \frac{F-L}{H-1}$。
        
    - 每次分配：$K_i = K_{i-1} - \alpha$。

### **🎓 期末考题预测**

这里最容易出**计算题**，必须掌握 GSS 的计算过程。

#### **题型 1：算法计算题（五星重点）**

- **题目**：假设有一个并行循环共有 100 个迭代任务（$N=100$），系统有 4 个处理器（$P=4$）。请使用 **指导性自调度 (GSS)** 算法，计算前三次任务分配的块大小（Chunk Size）分别是多少？
    
- **解答**：
    
    1. **第一次分配**：
        
        - 剩余 $R_1 = 100$。
            
        - $K_1 = \lceil 100 / 4 \rceil = 25$。
            
    2. **第二次分配**：
        
        - 剩余 $R_2 = 100 - 25 = 75$。
            
        - $K_2 = \lceil 75 / 4 \rceil = \lceil 18.75 \rceil = 19$。
            
    3. **第三次分配**：
        
        - 剩余 $R_3 = 75 - 19 = 56$。
            
        - $K_3 = \lceil 56 / 4 \rceil = 14$。
            
    
    - **答案**：25, 19, 14。
        

#### **题型 2：简答/比较题**

- **题目**：比较 **GSS (指导性自调度)** 和 **TSS (梯形自调度)** 在块大小变化上的主要区别。
    
- **答案**：
    
    - **GSS** 的块大小随分配次数呈**指数级衰减**（一开始很大，迅速变小），能够快速减少调度开销，但在某些极端负载不均下可能因为初始块太大导致不平衡。
        
    - **TSS** 的块大小呈**线性递减**（均匀变小），变化更加平缓，容易控制，适合循环迭代计算量变化比较规律的场景。

## **工作窃取与工作共享 (PPT 22-24)**

这两种策略主要解决的问题是：当某些处理器忙得不可开交，而另一些处理器闲得发慌时，如何动态地平衡负载。

### **1. 工作窃取 (Work-Stealing) [PPT 22]**

这是目前最主流的动态负载均衡策略之一（Java 的 `ForkJoinPool` 就用的这个）。

- **核心结构**：**分布式任务队列**。
    
    - 每个处理器（线程）都有自己**独立**的本地任务队列（Deque，双端队列）。
        
    - **不像**自调度那样大家抢一个公共池子，而是各管各的。
        
- **运作机制**：
    
    1. **自产自销**：当一个处理器生成新任务时，它把任务压入**自己**队列的**底部**（Bottom）。
        
    2. **正常工作**：处理器从**自己**队列的**底部**取出任务执行（LIFO，后进先出，利于缓存局部性）。
        
    3. **窃取发生**：当一个处理器（比如 T2）自己的队列空了，它变成了“窃贼”，去随机找另一个处理器（比如 T1），从 T1 队列的**顶部**（Top）“偷”一个任务来做。
        
- **关键设计问题**：
    
    - **从哪里窃取？** 通常是**随机选择**一个受害者。
        
    - **窃取多少？** 通常偷一个，或者偷一半（Steal-half）。
        
    - **何时结束？** 只有当**所有**处理器的队列都空了，程序才算结束。
        
- **优点**：
    
    - **减少竞争**：大部分时间大家都在访问自己的队列底部，互不干扰，锁竞争非常少。
        
    - **通信开销低**：只有在实在没活干的时候才去骚扰别人。
        

### **2. 工作共享 (Work-Sharing) [PPT 23]**

这是一种更“中央集权”或“混合”的策略。

- **核心结构**：**集中式任务队列 + 本地任务队列**。
    
    - 有一个公共的“大池子”（Global Queue）。
        
    - 每个处理器也有自己的“小池子”（Local Queue）。
        
- **运作机制**：
    
    1. **任务生成**：当处理器生成新任务时，先看自己的小池子满没满。
        
        - 没满：放自己这儿。
            
        - 满/超过阈值：为了防止自己累死，把多出来的任务“扔”到**公共大池子**里（Offload）。
            
    2. **任务获取**：
        
        - 优先做自己小池子里的。
            
        - 自己空了，就去公共大池子里取。
            
- **调度时机**：通常在**生成新任务**时进行决策（是留给自己还是扔出去）。
    

> **💡 一句话区分**：
> 
> - **工作窃取**：我闲了，我主动去**偷**你。（Receiver-initiated，接收者主动）
>     
> - **工作共享**：我忙了，我主动**分**出去。（Sender-initiated，发送者主动）
>     

### **3. 有依赖关系的任务调度 (Task Graph) [PPT 24]**

前面讲的调度大多假设任务是独立的（如循环迭代）。但如果任务之间有先后顺序怎么办？

- **依赖图 (DAG)**：任务之间的依赖关系可以用一个**有向无环图**来表示。
    
    - 图示中，箭头 $T1 \rightarrow T2$ 表示 T1 必须先做完，T2 才能开始。
        
- **调度原则**：调度器必须维护任务的状态。只有当一个任务的所有**前驱任务 (Predecessors)** 都执行完毕后，调度器才会把这个任务加入到“可执行队列”中，分配给工作线程。
    
- **实现**：工作线程在提交新任务时，必须明确告知系统这个任务依赖谁。

#### **题型 1：简答/对比题（高频）**

- **题目**：请简述 **工作窃取 (Work-Stealing)** 和 **工作共享 (Work-Sharing)** 的主要区别，并说明工作窃取为何在现代并行框架中更受欢迎？
    
- **参考答案**：
    
    - **区别**：
        
        1. **发起方不同**：工作窃取是由**空闲**的处理器发起的（我没活了去偷）；工作共享通常是由**繁忙**的处理器发起的（我活太多了分出去）。
            
        2. **队列结构**：工作窃取使用分布式队列（无中心瓶颈）；工作共享通常依赖一个集中式队列。
            
    - **工作窃取受欢迎的原因**：
        
        - 它极大地减少了**锁竞争**。在负载较重时（大家都忙），工作窃取几乎不需要通信（各干各的），只有在负载不均时才有开销；而工作共享在负载重时反而频繁访问全局队列，容易造成瓶颈。
            
        - 它具有更好的**数据局部性**（自己产生的子任务自己优先处理）。

- **题目**：在工作窃取算法中，为了减少同步开销并保持数据局部性，本地线程通常从双端队列的 ______ 存取任务，而窃取者通常从双端队列的 ______ 窃取任务。
    
- **答案**：底部 (Bottom/Tail)、顶部 (Top/Head)。

## **数据分布与内存布局 (PPT 25-27)**

并行编程不仅仅是分派任务，更重要的是**数据放在哪里**以及**怎么放**。

### **1. 核心目标：局部性 (Locality) [PPT 26]**

这是所有性能优化的“第一性原理”。

- **空间局部性 (Spatial Locality)**：如果你访问了数据 A，那么你很可能马上访问 A 旁边的数据 B。
    
    - _应用_：数组在内存中是连续的，访问 `A[0]` 后访问 `A[1]` 极快。
        
- **时间局部性 (Temporal Locality)**：如果你刚才访问了数据 A，那么你很可能过一会又要访问 A。
    
    - _应用_：缓存（Cache）机制就是基于此设计的。
        

### **2. 数据分布的关键问题 [PPT 26]**

- **放在哪？** 集中存储还是分散在各节点的内存里？
    
- **怎么动？** 运行时数据需要在节点间传输（通信），这会有开销。
    
- **长啥样？（布局 Layout）** 数据以什么格式存储最合适？这是本章的重点。
    

### **3. 重难点：AoS vs. SoA [PPT 27]**

这是图形学、高性能计算中经典的面试题。PPT 给出了一个处理像素（Pixel）的例子。

#### **(1) 结构的数组 (AoS - Array of Structures)**

- **定义**：一个大数组，数组里的每个元素是一个结构体。
    
- **代码示例**：

    ```c
    struct Pixel {
        float r, g, b; // 红绿蓝紧挨着
    };
    Pixel image_AoS[480][640]; // 数组里存的是Pixel结构体
    ```
    
- **内存视图**：`RGB RGB RGB RGB ...`
    
- **优点**：**空间局部性好（针对单个对象）**。如果你需要同时读取一个像素的 R、G、B 分量（比如计算亮度），它们在内存里是挨着的，读一次 Cache Line 可能就全拿到了。
    
- **缺点**：不利于向量化（SIMD）。
    

#### **(2) 数组的结构 (SoA - Structure of Arrays)**

- **定义**：一个大结构体，结构体里包含多个数组（每个属性一个数组）。
    
- **代码示例**：
    ```c
    struct Image {
        float R[480][640]; // 所有的红色分量在一起
        float G[480][640]; // 所有的绿色分量在一起
        float B[480][640]; // 所有的蓝色分量在一起
    };
    Image image_SoA;
    ```
    
- **内存视图**：`RRRR... GGGG... BBBB...`
    
- **优点**：**利于向量化 (Vectorization)**。如果你要“把整张图变红一点”（所有 R 分量 + 10），CPU 可以使用向量指令（AVX/SSE）一次性加载 8 个 R 分量进行加法，效率极高。
    
- **缺点**：如果你要随机访问某个像素的完整 RGB，需要跳跃访问三块内存，Cache 命中率低。

### **🎓 期末考题预测**

这一块是“数据结构”与“体系结构”的结合点，必考 AoS 和 SoA 的选择。

#### **题型 1：代码分析与选择（五星重点）**

- **题目**：假设你正在编写一个粒子系统模拟程序，每个粒子包含 `(x, y, z)` 坐标和 `mass` 质量。
    
    - **场景 A**：你需要频繁计算每个粒子的位移，计算公式为 `x = x + v_x`，`y` 和 `z` 同理。你会选择 AoS 还是 SoA？
        
    - **场景 B**：你需要频繁随机读取某个粒子的所有属性并打印出来。你会选择 AoS 还是 SoA？
        
- **参考答案**：
    
    - **场景 A 选择 SoA**。
        
        - _理由_：计算 `x` 的更新只涉及 `x` 分量。SoA 将所有 `x` 连续存储，允许 CPU 使用 SIMD 指令（如 AVX）一次加载多个 `x` 进行并行加法，且缓存中全是有用的 `x` 数据，无浪费。
            
    - **场景 B 选择 AoS**。
        
        - _理由_：打印单个粒子需要同时访问 `x, y, z, mass`。AoS 将它们紧挨着存储，符合空间局部性，一次访存即可取出所有属性。
            

#### **题型 2：简答题**

- **题目**：简述 **AoS** 和 **SoA** 的区别，并说明为什么现代 GPU 和 CPU 向量编程通常更倾向于使用 SoA？
    
- **答案**：
    
    - AoS 是“结构体的数组”（RGB RGB），适合对象整体访问；SoA 是“数组的结构”（RRR GGG），适合分量批量处理。
        
    - 向量编程倾向于 SoA，是因为它保证了**内存访问的连续性 (Memory Coalescing)**。当对某种属性（如颜色 R）进行批量相同时，SoA 允许硬件一次性加载连续的多个数据到向量寄存器中，极大提升吞吐量。
        

---

**学习小结**：

- **AoS** = 传统的面向对象思维（每个对象是个整体）。
    
- **SoA** = 面向数据/性能的思维（把属性拆开存）。

### **💡 什么是向量化 (Vectorization)？**

**向量化**，在计算机里通常指利用 **SIMD（单指令多数据）** 技术来加速计算。

#### **1. 通俗比喻：搬砖**

- **标量处理 (Scalar)**：
    
    - 就像你一只手一次只能搬 **1** 块砖。
        
    - 如果要搬 8 块砖，你得跑 8 趟。
        
    - 代码逻辑：`for (i=0; i<8; i++) A[i] = B[i] + C[i];` （CPU 要执行 8 次加法指令）
        
- **向量化处理 (Vector/SIMD)**：
    
    - 就像你有了一个**大铲车**（向量寄存器），一次能铲起来 **8** 块砖。
        
    - 如果要搬 8 块砖，铲车 **1** 趟就搞定了。
        
    - 代码逻辑：`Vector_Add(A[0...7], B[0...7], C[0...7]);` （CPU 只要执行 1 次加法指令）
        

#### **2. 为什么 SoA 更适合向量化？**

- **铲车的限制**：铲车很宽，但它要求地上的砖块必须是**整整齐齐挨在一起**的（连续内存），它才能一铲子铲起来。
    
- **SoA (结构数组)**：所有的“红色分量 R”都挨在一起存。铲车一铲子下去，铲起来的全是 R，正好拿去算。
    
- **AoS (数组结构)**：内存里是 `R G B R G B`。铲车一铲子下去，铲起来的是 `R G B R...`。如果你只想算 R 加法，这铲子里混进了 G 和 B，就没法算了。
    
## **数据重组的基础操作**

我们之前的背景知识是：为了利用 CPU 的向量化（SIMD，一次处理多个数据）能力，我们需要数据在内存里是**连续、整齐**的。 如果数据不整齐怎么办？就需要用下面这些操作把它们“搬运”到整齐的地方。

#### **PPT 28：聚合 (Gather) —— “隔空取物”**

**1. 这一页讲什么？** Gather 是并行编程中最基础的**读数据**操作。 它的核心任务是：从一个**稀疏**或**乱序**的大数组中，按照我们指定的**索引**，把需要的数据“抓”出来，紧凑地放在一个新的数组里。

**2. 详细图解分析：** PPT 上的图展示了这个过程：

- **源数据 (Source)**：上面那个五颜六色的长条，里面有 `A, B, C, D, E, F, G, H`。
    
- **索引数组 (Indices/Offsets)**：右边的那个数组 `[1, 5, 0, 2, 2, 4]`。它告诉计算机：“我要取第1个、第5个、第0个...”
    
- **操作过程**：
    
    - 读索引 `1` -> 去源数组找下标 1 的元素 -> 拿到 `B` -> 放进结果数组第 0 位。
        
    - 读索引 `5` -> 去源数组找下标 5 的元素 -> 拿到 `F` -> 放进结果数组第 1 位。
        
    - 读索引 `0` -> 去源数组找下标 0 的元素 -> 拿到 `A` -> 放进结果数组第 2 位。
        
    - ...以此类推。
        
- **结果 (Destination)**：下面那个紧凑的数组 `[B, F, A, C, C, E]`。
    

**3. 关键细节与考点：**

- **数据类型**：输出的数据类型和输入是一样的（都是字母/浮点数）。
    
- **大小**：输出数组的大小 **等于** 索引数组的大小。你想要几个，最后就得到几个。
    
- **重复访问**：注意索引数组里的 `2, 2`。这意味着源数组里的 `C` 被读取了两次。Gather 是允许重复读取同一个位置的，**不会有冲突**（因为只是读，大家都能读）。
    

---

#### **PPT 29：移位 (Shifts) —— “整体平移”**

**1. 这一页讲什么？** Shift 是 Gather 的一种**特殊情况**。 它的特点是：我们不需要一个复杂的索引数组来告诉每个数去哪，而是所有数据都按照**固定的距离**移动。

**2. 详细分析：**

- **场景**：PPT 下方的图展示了圆圈（数据）整体向左或向右移动。
    
- **左移/右移**：比如 `A[i] = A[i+1]`。每个位置都去读它右边邻居的数据。
    
- **循环移位 (Circular Shift)**：队伍头的人跑到队伍尾巴去，形成一个环。
    
- **边界处理 (Boundary)**：这是考点。
    
    - 如果是普通移位，最边上的数据移走了，空出来的位置填什么？（通常填 0 或保持不变）。
        
    - 如果是循环移位，就不存在边界问题。
        

**3. 为什么它很重要？（局部性）** PPT 专门提到了 **“良好的局部性”**。

- 因为 Shift 访问的内存地址是固定的偏移量（比如 `i` 和 `i+1`），它们在内存里挨得非常近。这意味它们很可能已经在同一个 **Cache Line（缓存行）** 里了。
    
- **应用例子**：图像处理中的“边缘检测”或“高斯模糊”。算一个像素的值，需要用到它上下左右像素的值。这就是典型的 Shift 操作。
    

---

#### **PPT 30：拉合 (Zip) 与 拉拆 (Unzip) —— “洗牌与拆牌”**

**1. 这一页讲什么？** 这一页专门解决我们在 PPT 27 讲过的 **AoS（结构体数组）** 和 **SoA（数组结构体）** 之间的转换问题。

**2. 拉合 (Zip) 详解：**

- **动作**：想象拉拉链。左边一排牙齿，右边一排牙齿，拉链一拉，它们就**交错 (Interleave)** 咬合在一起了。
    
- **PPT 图示**：
    
    - 输入：两个数组，一个是实部 `(Real Part)`，一个是虚部 `(Imaginary Part)`。这是 SoA 格式。
        
    - 操作：Zip。
        
    - 输出：一个混合数组。`[实1, 虚1, 实2, 虚2, ...]`。这变成了 AoS 格式（复数结构体）。
        
- **推广**：不仅可以是 2 个数组，也可以把 3 个数组（R, G, B）Zip 成一个 `RGB, RGB...` 的数组。
    

**3. 拉拆 (Unzip) 详解：**

- **动作**：Zip 的逆操作。把混在一起的数据拆开。
    
- **操作**：从 AoS 中提取数据。比如每隔 2 个数取 1 个，就能把所有的“实部”都提取出来还原成一个纯数组。
    

**4. 考点总结：** 如果题目问：“如何利用向量化指令处理 AoS 格式的数据？”，标准答案通常是：“先用 **Unzip** 将其转换为 SoA 格式进行计算，计算完后再用 **Zip** 转换回 AoS 格式。”

---

#### **PPT 31：散发 (Scatter) —— “精准投递”**

**1. 这一页讲什么？** 这是这一部分的**难点**。Scatter 是 Gather 的**完全逆操作**。 Gather 是“读进来”，Scatter 是“写回去”。

**2. 详细图解分析：**

- **输入数据**：左上角的数组 `[A, B, C, D, E, F]`。这是我们手头计算好的数据。
    
- **写入位置 (索引)**：下面的数字 `[1, 5, 0, 2, 2, 4]`。这告诉我们每个数据应该去哪。
    
- **操作过程**：
    
    - 把 `A` 写入位置 `1`。
        
    - 把 `B` 写入位置 `5`。
        
    - 把 `C` 写入位置 `0`。
        
    - **关键点来了**：
        
        - 要把 `D` 写入位置 `2`。
            
        - 要把 `E` 写入位置 `2`。
            
- **结果**：右边的长条数组。
    
    - 位置 0 是 C，位置 1 是 A，位置 5 是 B...
        
    - **位置 2 是什么？** PPT 上画了一个大大的 **❌ (Collision)**。
        

**3. 核心难点：冲突 (Collisions)** 这是 Scatter 和 Gather 最大的区别。

- **Gather**：多个人读同一个地址，没问题。
    
- **Scatter**：多个人（线程）要往同一个地址（位置 2）**写**数据。
    
    - 是写 D 进去？
        
    - 还是写 E 进去？
        
    - 还是它俩加起来？
        
    - 这就是 **写冲突**。如果不处理，数据就乱了。

### **Scatter 的四种冲突处理策略 (PPT 32-35)**

#### **1. 原子散发 (Atomic Scatter) [PPT 32]**

这是最基础、最“暴力”的解决方案。

- **核心逻辑**：**“排队进，谁最后谁赢，但不确定是谁”**。
    
    - 利用硬件提供的“原子操作”（Atomic Operation）机制。
        
    - 当两个线程（比如 T1 和 T2）都要写位置 2 时，硬件会强行让它们排队。T1 写完了 T2 再写（或者反过来）。
        
    - **关键点**：虽然保证了不会写出乱码（比如写了一半 T1 一半 T2 的数据），但是 **最终保留的是谁的数据是不确定的**（Non-deterministic）。
        
- **PPT 图解分析** ：
    
    - 输入：`[A, B, C, D, E, F]`
        
    - 冲突点：`D` 和 `E` 都要写到目标位置 `2`。
        
    - **结果**：PPT 给出了两种可能的结果（`or`）：
        
        - 结果可以是 `... D ...` （E 先写，D 后写覆盖了 E）
            
        - 结果也可以是 `... E ...` （D 先写，E 后写覆盖了 D）
            
- **优缺点**：
    
    - 优点：实现简单，只要硬件支持原子锁就行。
        
    - 缺点：结果不可预测，除非你不在乎最后保留的是谁。
        

#### **2. 排列散发 (Permutation Scatter) [PPT 33]**

这是最“理想”的情况，也是性能最好的。

- **核心逻辑**：**“程序员担保无冲突”**。
    
    - 这种模式要求：**索引数组 (Index Array) 中绝对没有重复的值**。
        
    - 也就是说，每个人写入的位置都是独一无二的，根本不会发生冲突。
        
- **PPT 图解分析** ：
    
    - 输入：`[A, B, C, D, E, F]`
        
    - 索引：`[1, 5, 0, 2, 3, 4]` （注意看，这里的索引分别是 1,5,0,2,3,4，**完全没有重复**！）
        
    - **结果**：`[C, A, D, E, F, B]`。
        
    - 因为没有冲突，大家各回各家，速度极快。
        
- **应用场景**：当你很确定你的算法逻辑（比如矩阵转置）是一对一映射时使用。
    

#### **3. 归并散发 (Merge Scatter) [PPT 34]**

这是科学计算（如直方图统计）中最常用的策略。

- **核心逻辑**：**“冲突了别打架，合作吧”**。
    
    - 当多个数据要写入同一个位置时，不是覆盖，而是**运算**（比如相加、取最大值、逻辑或）。
        
- **PPT 图解分析** ：
    
    - 输入：`[2, 3, 1, 1, 5, 6]`（注意这里是数字了，方便做加法）
        
    - 冲突点：假设索引数组导致源数据中的 `1` (来自索引3) 和 `5` (来自索引4) 都要去目标位置 `2`。
        
    - **结果**：目标位置 `2` 的值变成了 **6**。
        
    - **计算过程**：`1 + 5 = 6`。它把冲突的两个数加起来了。
        
- **重点**：这种操作在并行编程中通常被称为 **Reduction (归约)** 类型的 Scatter。
    

#### **4. 优先散发 (Priority Scatter) [PPT 35]**

这是为了解决 Atomic Scatter “结果不确定”的问题而生的。

- **核心逻辑**：**“按资排辈，后来者居上”**。
    
    - 当发生冲突时，根据某种**确定性的规则**（Priority）来决定谁留下来。
        
    - **最常用的规则**：源数组中**索引更大**（靠后）的元素优先级更高，会覆盖索引小（靠前）的元素。这模拟了串行程序从头跑到尾的行为（后面的总会覆盖前面的）。
        
- **PPT 图解分析** ：
    
    - 输入：`[A, B, C, D, E, F]` (源索引分别是 0, 1, 2, 3, 4, 5)
        
    - 冲突点：`D` (源索引3) 和 `E` (源索引4) 都要去目标位置 `2`。
        
    - **结果**：目标位置 `2` 是 **E**。
        
    - **原因**：因为 `E` 的源索引 (4) > `D` 的源索引 (3)，所以 `E` 赢了，覆盖了 `D`。结果是确定的（Deterministic）。

### **🎓 期末考题预测 (重点来了！)**

这一部分非常适合出**计算题**或**填空题**，考察你对规则的理解。

#### **题型 1：给定输入求输出（必考题型）**

- **题目**： 设有源数组 `Source = [10, 20, 30, 40]`， 目标索引数组 `Index = [1, 2, 2, 1]`。 请分别写出使用以下三种 Scatter 策略后，目标数组（假设初始全0，长度为3）的内容：
    
    1. **Merge Scatter (Sum)**
        
    2. **Priority Scatter (源索引大的覆盖小的)**
        
    3. **Permutation Scatter**
        
- **解析与答案**：
    
    - **分析写入行为**：
        
        - `Source[0]=10` -> 写位置 `1`
            
        - `Source[1]=20` -> 写位置 `2`
            
        - `Source[2]=30` -> 写位置 `2` (与 20 冲突)
            
        - `Source[3]=40` -> 写位置 `1` (与 10 冲突)
            
    - **答案 1 (Merge Scatter)**：
        
        - 位置 1：`10 + 40 = 50`
            
        - 位置 2：`20 + 30 = 50`
            
        - **结果**：`[0, 50, 50]`
            
    - **答案 2 (Priority Scatter)**：
        
        - 位置 1：`40` 覆盖 `10`（因为下标3 > 下标0）
            
        - 位置 2：`30` 覆盖 `20`（因为下标2 > 下标1）
            
        - **结果**：`[0, 40, 30]`
            
    - **答案 3 (Permutation Scatter)**：
        
        - **结果**：**非法 / 错误**。
            
        - **理由**：题目中的索引数组 `[1, 2, 2, 1]` 包含重复值，不满足 Permutation Scatter 的“无冲突”前提条件。
            

#### **题型 2：简答题**

- **题目**：在并行直方图统计（Histogram）算法中，多个线程需要同时更新同一个直方图柱子（Bucket）的计数值。请问这属于哪种 Scatter 操作？为什么不能使用 Permutation Scatter？
    
- **答案**：
    
    - 这属于 **Merge Scatter**（操作是加法）。
        
    - 不能使用 Permutation Scatter，因为在统计直方图时，大量不同的输入数据可能会落入同一个柱子（Bucket）中，这意味着索引数组必然会有大量的**重复/冲突**，违反了 Permutation Scatter 的无冲突假设。
        

---

**学习小结**：

- **Atomic** = 听天由命（不确定）。
    
- **Permutation** = 完美主义（绝无冲突）。
    
- **Merge** = 合作共赢（加起来）。
    
- **Priority** = 长幼有序（后面的盖前面的）。

## **高级数据重组操作 (PPT 36-39)**

这几页介绍的操作，本质上都是在**调整数据的位置**，以便于并行计算能更高效地跑起来（减少无用计算，提高连续性）。

### **PPT 36: 打包 (Pack) —— “过滤与压缩”**

**1. 这一页讲什么？**

- **核心功能**：**消除无效元素** 。
    
    - 想象你有一个数组，里面有很多数据，其中一些是你不要的（比如值为 0，或者不满足条件的）。
        
    - Pack 操作就是把那些“有用”的元素挑出来，**紧凑地、连续地**排在一起，剩下的扔掉。
        
- **目的**：重组剩余元素，使其在内存中保持连续，提高后续处理的效率（空间局部性） 。
    

**2. 它是怎么实现的？（核心难点）** PPT 中给出了一个非常经典的并行实现算法，包含两步 ：

- **第一步：生成掩码并计算前缀和 (Prefix Sum)**
    
    - 假设源数据是 `[A, B, C, D, E, F, G, H]`。
        
    - 我们只想要 `C, D, E, G, H`（标记为 1），不要 `A, B, F`（标记为 0）。
        
    - **位掩码 (Bitmask)**：`[0, 0, 1, 1, 1, 0, 1, 1]`。
        
    - **前缀和 (Prefix Sum)**：对掩码做累加。
        
        - `0, 0, 1, 2, 3, 3, 4, 5`
            
    - _这个前缀和有什么用？_ **它就是目标数组的索引！**
        
        - 比如 `C` 对应的掩码是 `1`，前缀和是 `1`（代表它是第 1 个有效元素，放位置 0）。
            
        - `D` 对应的掩码是 `1`，前缀和是 `2`（代表它是第 2 个有效元素，放位置 1）。
            
- **第二步：散发 (Scatter)**
    
    - 利用算好的索引，把数据写到目标数组里。
        

3. 图解分析

- 输入：`[A, B, C, D, E, F, G, H]`
    
- 掩码：`[0, 0, 1, 1, 1, 0, 1, 1]` （不要 A,B,F）
    
- **结果**：`[C, D, E, G, H]` （紧凑排列，没有空隙）
    

---

### **PPT 37: 拆分 (Split) —— “二元分类”**

**1. 这一页讲什么？**

- **定义**：Pack 的推广 。
    
- **Pack** 是“留下一部分，丢掉一部分”。
    
- **Split** 是“这部分放左边，那部分放右边”。**没有数据被丢弃**，只是根据条件分成了两堆。
    

2. 图解分析

- **输入**：`[A, B, C, D, E, F, G, H]`
    
- **条件**：假设掩码为 `1` 的放下面（Target 1），为 `0` 的放上面（Target 2）。
    
    - 掩码 `1` (True): `A, D, E, H`
        
    - 掩码 `0` (False): `B, C, F, G`
        
- **操作**：
    
    - 下面的数组收纳 `A, D, E, H`。
        
    - 上面的数组收纳 `B, C, F, G`。
        
- **整合 (Unsplit)**：Split 的逆操作，把两堆数据按原来的规则还原回去 。
    

**3. 实现技术** PPT 特别提到，拆分和整合常用 **向量指令 (Vector Instructions)** 实现 。这在处理条件分支（If-Else）的向量化时非常有用：把走 `if` 的数据归一堆，走 `else` 的归一堆，然后分别用向量指令批量处理。

### **PPT 38：分箱 (Bin) —— “多选一的归宿”**

**1. 核心概念** 你之前听懂了 **Split (拆分)**，Split 是把数据分成 **两堆**（True/False，左/右）。 **Bin (分箱)** 其实就是 Split 的升级版——把它变成 **N 堆**。

- **场景**：假设你有一堆学生的成绩（0-100分），你想把他们分到不同的分数段里：
    
    - 桶 0：不及格 (<60)
        
    - 桶 1：及格 (60-80)
        
    - 桶 2：优秀 (>80)
        
- **输入**：一堆乱序的数据。
    
- **输出**：按类别排好序的数据块。
    

**2. 并行实现逻辑 (怎么做？)** 这也需要用到**前缀和 (Prefix Sum)**，但比 Split 复杂一点。

- **第一步：计算索引 (Index)**
    
    - 这次不是生成 0/1 掩码了，而是生成一个**类别数组**。
        
    - 输入数据：`[A, B, C, D, E]`
        
    - 类别判定：`[2, 0, 1, 2, 0]` （A属于桶2，B属于桶0...）
        
- **第二步：计算偏移量 (Offset)**
    
    - 这里的难点是：**B 知道自己要去桶 0，但它怎么知道自己是桶 0 里的第几个？**
        
    - 解决方法：对**每一个桶**分别做一次计数/前缀和。
        
        - 比如专门算“属于桶 0 的元素”的前缀和。
            
- **第三步：散发 (Scatter)**
    
    - 大家拿着算好的位置，分别跳进自己的桶里。
        

**3. 实际应用**

- **基数排序 (Radix Sort)**：这是最快的整数排序算法之一，核心就是不断地做 Bin 操作（先按个位分桶，再按十位分桶...）。
    
- **粒子模拟**：把空间切成网格（桶），把粒子按坐标扔进对应的网格里。

### **PPT 39：几何分解 (Geometry Decomposition) —— “切蛋糕的艺术”**

这一页非常重要，它是科学计算（如天气预报、流体模拟）中最主流的数据分布方式。

**1. 核心概念**

- **定义**：为了让多个处理器并行计算，我们将整个物理空间（比如一个地球的大气层，或者一块金属板）切分成很多小块，每个处理器负责算一块。
    
- **区别于普通分块**：
    
    - 普通分块（Partitioning）：切开了就老死不相往来。
        
    - **几何分解**：**藕断丝连**。因为物理世界是连续的，你计算这一块边缘的温度时，需要知道隔壁那一块边缘的温度。
        

**2. 关键难点：幽灵区 / 光环 (Ghost Zone / Halo)** 这是考点！PPT 图中那些红色的边框往往暗示的就是这个概念。

- **问题**：
    
    - 假设处理器 A 负责计算中间的区域 `(x, y)`。
        
    - 计算公式可能需要用到左边的点 `(x-1, y)`。
        
    - 但 `(x-1, y)` 归处理器 B 管理，在 B 的内存里。
        
    - 如果每次算都去问 B 要数据，通信太慢了。
        
- **解决方案 (Halo)**：
    
    - 处理器 A 在自己的内存里，多存一圈**边缘数据**（来自 B 的副本）。
        
    - 这圈数据就像“幽灵”一样，它是 B 的影子。
        
    - **通信模式**：每算完一步，A 和 B 就互相**交换一次边缘数据**（更新 Halo），然后各自闷头算自己的内部，不用再通信了。
        

**3. 图示详解**

- **1D 分解**：像切法棍面包一样，切成一段段。每个任务只和左邻右舍通信。
    
- **2D 分解**：像切棋盘一样。中间的任务可能有 4 个邻居（上下左右），甚至 8 个邻居（加上对角线）。
    
- **3D 分解**：切豆腐块。邻居就更多了。

### **🎓 期末考题预测**

这一部分的考题侧重于算法逻辑和应用场景。

#### **题型 1：算法填空题（难点）**

- **题目**：在并行实现 **Pack (打包)** 操作时，为了确定每个保留元素在目标数组中的写入位置，通常需要对掩码数组（Mask Array）执行 ________ 算法。
    
- **答案**：前缀和 (Prefix Sum / Scan)。
    
- **解析**：这是 Pack 能并行化的关键。不做前缀和，你就不知道你是第几个被保留的元素，就没法并行地往目标数组里写。
    

#### **题型 2：场景选择题**

- **题目**：以下哪种数据重组操作最适合用于实现“快速排序 (QuickSort)”中的分区（Partition）步骤（即将小于 Pivot 的放左边，大于 Pivot 的放右边）？ A. Gather B. Split C. Bin D. Zip
    
- **答案**：**B. Split**。
    
    - **解析**：快速排序的分区本质上就是把数据按条件（< Pivot 或 > Pivot）分成两堆，这正是 Split 的定义。如果有多个 Pivot 分成多段，那就是 Bin。
        

#### **题型 3：简答题**

- **题目**：请简述 **几何分解 (Geometry Decomposition)** 中“分区 (Partitioning)”与普通分解的主要区别。
    
- **答案**：
    
    - 严格意义上的“分区 (Partitioning)”通常指数据划分是不重叠的（Disjoint），每个数据元素只属于一个任务。
        
    - 而广义的“几何分解”往往涉及**数据重叠**，例如在处理边界条件时，任务需要复制相邻任务边缘的数据（称为 Ghost Zone 或 Halo），以便在计算时不需要频繁通信。
### **🔍 场景设定**

假设源数组 `Src = [A, B, C, D, E, F]` 我们想把 **元音字母** (`A`, `E`) 分到一堆（True 堆），**辅音字母** (`B`, `C`, `D`, `F`) 分到另一堆（False 堆）。

---

### **第一步：生成掩码 (Mask)**

所有线程并行检查自己负责的元素，生成一个由 0 和 1 组成的数组。

- 符合条件（元音）标为 **1**。
    
- 不符合条件（辅音）标为 **0**。
    

`Src`: `[A, B, C, D, E, F]` `Mask`: `[1, 0, 0, 0, 1, 0]`

---

### **第二步：计算“True 堆”的写入位置 (重点！)**

这就回答了你“怎么知道具体顺序”的问题。 我们对 `Mask` 做一次 **前缀和 (Prefix Sum)** 计算（也叫 Scan）。前缀和的值，就是该元素在“True 堆”里的**排名（索引）**。

`Mask`: `[1, 0, 0, 0, 1, 0]` `True_Pos`: `[0, 1, 1, 1, 1, 2]` (这是 Exclusive Scan，即当前位置之前有多少个 1)

**解读 `True_Pos`：**

- **A (索引0)**：对应 Mask 是 1，`True_Pos` 是 **0**。说明 A 是第 0 个元音，写入 True 堆的 `index[0]`。
    
- **E (索引4)**：对应 Mask 是 1，`True_Pos` 是 **1**。说明 E 之前已经有 1 个元音了（是A），所以 E 写入 True 堆的 `index[1]`。
    

---

### **第三步：计算“False 堆”的写入位置 (难点！)**

那辅音字母（Mask 为 0 的）怎么知道自己去哪呢？ 我们需要算一下：**“在我之前，有多少个 0 ？”**

计算公式是：**当前索引 - (在我之前的 1 的个数)** 即：`False_Pos[i] = i - True_Pos[i]`

我们来看每个辅音字母的计算：

- **B (索引1)**: `i=1`。`True_Pos[1]=1` (B之前有1个元音)。
    
    - `False_Pos = 1 - 1 = 0`。B 去 False 堆的 `index[0]`。
        
- **C (索引2)**: `i=2`。`True_Pos[2]=1` (C之前有1个元音)。
    
    - `False_Pos = 2 - 1 = 1`。C 去 False 堆的 `index[1]`。
        
- **D (索引3)**: `i=3`。`True_Pos[3]=1`。
    
    - `False_Pos = 3 - 1 = 2`。D 去 False 堆的 `index[2]`。
        
- **F (索引5)**: `i=5`。`True_Pos[5]=2` (F之前有2个元音 A,E)。
    
    - `False_Pos = 5 - 2 = 3`。F 去 False 堆的 `index[3]`。
        

---

### **第四步：并行写入 (Scatter)**

现在，每个元素都知道了自己的“新家”在哪，所有线程可以同时动手了（Scatter）：

- **如果 Mask 是 1**：把数据写到 `Target_True` 数组的 `True_Pos` 位置。
    
- **如果 Mask 是 0**：把数据写到 `Target_False` 数组的 `False_Pos` 位置。
    

**最终结果：**

- `Target_True`: `[A, E]`
    
- `Target_False`: `[B, C, D, F]`
    

---

### **总结回答你的问题**

1. **怎么分成两堆？**
    
    - 物理上，通常是准备两块内存区域（或者把一个大数组从中间劈开，左边存 True，右边存 False）。
        
    - 逻辑上，通过 `Mask`（条件掩码）来区分去哪一堆。
        
2. **怎么知道具体顺序？**
    
    - **靠“前缀和” (Prefix Sum)**。
        
    - `A` 为什么在 `E` 前面？因为在原始数组里，`A` 的索引比 `E` 小。前缀和计算会保留这种**相对顺序**。这种特性在算法里叫 **“稳定性” (Stability)**。
        
    - Split 操作通常是**稳定**的：即原本在前面的元素，分堆后依然在前面。
        

**至于“整合 (Unsplit)”：** 就是反过来。如果我们保留了刚才计算的 `True_Pos` 和 `False_Pos`，或者保留了 `Mask`，我们就可以算出每个元素应该回到原数组的哪个位置，然后再做一个 Scatter 把它们放回去。

## **复习笔记：同步的基础概念 (PPT 42-43)**

### **1. 为什么要进行同步？ [PPT 43]**

并行程序里，多个线程（Thread）或者进程（Process）是同时跑的。但它们不是生活在真空中，它们之间有两种关系需要“协调”：

1. **有依赖关系 (Dependencies)**：
    
    - 比如任务 B 必须等任务 A 算完了才能开始（A 是 B 的前驱）。如果不这同步，B 抢跑了，结果就错了。
        
2. **抢资源 (Shared Resources)**：
    
    - 多个线程要同时访问同一个东西（比如同一个变量、同一个文件、同一个打印机）。
        
    - 这块被共享访问的代码区域，有一个专业术语，叫 **临界区 (Critical Section)** 。
        

### **2. 缺少同步会发生什么？（三大灾难） [PPT 43]**

PPT 列举了三种后果，每一条都是考试的**核心名词解释**。

#### **(1) 程序逻辑错误 (Logic Error)**

- 比如 B 在 A 还没把数据准备好之前就去读，读到了脏数据。
    

**(2) 数据竞争 (Data Race) —— 必考！**

- **定义**：当两个或多个线程同时访问同一个内存位置，且至少有一个是**写操作**，并且没有同步机制保护时，就会发生数据竞争。
    
- **PPT 图解分析 (赛车图)**：
    
    - **场景**：
        
        - 线程 1 想做 `x++`（把 x 加 1）。
            
        - 线程 2 想做 `print x`（打印 x）。
            
    - **问题**：`x++` 其实分三步（读x -> 加1 -> 写回x）。如果线程 2 在线程 1 “刚读完但在写回之前”就把 `x` 打印出来了，那它打印的是旧值。如果它在写回之后打印，就是新值。
        
    - **结果**：**程序的输出是不确定的（Non-deterministic）**，完全看运气。这就是数据竞争。
        

**(3) 死锁 (Deadlock) —— 必考！**

- **定义**：两个或多个线程互相等待对方释放资源，导致谁也动不了，程序永久卡死。
    
- **PPT 图解分析 (堵车图)**：
    
    - 十字路口堵死了。
        
    - 红色车想往前走，被蓝色车挡住了。
        
    - 蓝色车想往前走，被银色车挡住了。
        
    - ...转一圈，大家都在等别人让路，结果谁也让不了。
        
- **口诀**：**“你等我，我等你，等到地老天荒。”**

#### **题型 1：名词解释（五星重点）**

- **题目**：什么是 **数据竞争 (Data Race)**？它发生的三要素是什么？
    
- **参考答案**：
    
    - **定义**：指在多线程程序中，多个线程在没有同步机制保护的情况下，并发访问同一个内存地址，且由于执行顺序的不确定性导致结果不可预测的现象。
        
    - **三要素**：
        
        1. 至少有两个线程并发访问同一块内存。

- **答案**：
    
    - 死锁通常需要满足四个条件（Coffman 条件）：
        
        1. **互斥**：资源（路口空间）一次只能被一辆车占用。
            
        2. **持有并等待**：车子占着当前的位置，同时在等前面的位置空出来。
            
        3. **不可剥夺**：交警不能强行把车吊走（资源不能被强行抢占）。
            
        4. **循环等待**：车 A 等 车 B，车 B 等 车 C ... 车 Z 等 车 A，形成一个闭环。
## **同步原语 —— 栅栏 (Barrier) (PPT 44-45)**

### **1. 同步操作的“武器库” (PPT 44)**

1

在并行编程中，我们主要用四种工具来解决竞争和协作问题：

1. **栅栏 (Barrier)**：大家一起等（本页重点）。
    
2. **锁 (Lock)**：我用着，你别动（互斥）。
    
3. **信号量 (Semaphore)**：控制同时访问的人数（流量控制）。
    
4. **同步通信**：发消息的人和收消息的人要对上暗号。
    

### **2. 栅栏 (Barrier) 详解 (PPT 45)**

2

这是并行计算（特别是科学计算）中最经典的同步方式。

#### **(1) 核心概念**

- **通俗比喻**：**“导游的小旗子”**。
    
    - 想象一个旅游团（并行程序）有 10 个游客（线程）。
        
    - 导游在景点门口举着旗子说：“大家自由活动（计算），半小时后在这里集合（Barrier）。**人齐了再一起去下一个景点**。”
        
    - 跑得快的游客到了集合点，必须**停下来等**。
        
    - 跑得慢的游客还在路上，大家就得等他。
        
    - 只有当**最后一个人**到达集合点，栅栏打开，所有人同时进入下一阶段。
        

#### **(2) 运作机制 (PPT 上半部分图解)**

- 图中 $P_0$ 到 $P_{n-1}$ 是并行的进程。
    
- 蓝色框是 **活动 (Activity/Computation)**：大家各自埋头算题。
    
- 绿色箭头是 **等待 (Wait)**：算完了的人，在红线（障碍点）前空转或休眠。
    
- **关键点**：**同步点是所有人的起跑线，也是终点线。**
    

#### **(3) 超级步 (Superstep) 与 BSP 模型 (PPT 下半部分图解)** 🌟🌟

3

这张图非常重要，它展示了著名的 **BSP (Bulk Synchronous Parallel，整体同步并行)** 模型。这是 Google MapReduce、Hadoop、Spark 等大数据框架背后的理论基础。

- **一个超级步 (Superstep) 的生命周期**：
    
    1. **Computation (计算)**：每个处理器只算自己内存里的数据，互不干扰。
        
    2. **Communication (通信)**：算完了，大家互相交换数据（你需要我的结果，我需要你的结果）。
        
    3. **Synchronization (同步/栅栏)**：这是最重要的！**在所有人交换完数据之前，谁也不许进入下一轮计算**。
        
        - _为什么？_ 如果没有这道栅栏，P1 可能在 P2 还没把数据发过来之前就开始算下一轮，结果算出来的就是错的。

### **🎓 期末考题预测**

这一页是并行算法设计的核心，考题通常围绕 BSP 模型出。

#### **题型 1：名词解释（必背）**

- **题目**：什么是 **栅栏 (Barrier)** 同步？
    
- **参考答案**：
    
    - 栅栏是一种全局同步机制。它在程序中设定一个同步点，要求所有参与的线程或进程在到达该点时必须**暂停等待**，直到**所有**线程都到达该点后，才能继续执行后面的代码。这确保了所有线程在进入下一阶段前都完成了当前阶段的工作。
        

#### **题型 2：填空/简答**

- **题目**：在 **BSP (整体同步并行)** 模型中，一个“超级步 (Superstep)”通常包含哪三个有序的阶段？
    
- **答案**：局部计算 (Computation)、全局通信 (Communication)、栅栏同步 (Barrier Synchronization)。
    

#### **题型 3：分析题**

- **题目**：在使用 Barrier 同步时，如果有一个线程因为死循环永远无法到达 Barrier 点，会发生什么后果？
    
- **答案**：**死锁 (Deadlock)**。
    
    - _解析_：因为 Barrier 的规则是“不见不散”。只要有一个人不到，其他人就得永远等下去，导致整个并行程序卡死。
## **互斥锁 (Lock) (PPT 46-48)**

### **1. 什么是锁？为什么要用锁？ (PPT 46)**

- **核心场景**：**临界区 (Critical Section)**。
    
    - 还记得刚才那个“十字路口”的例子吗？临界区就是那个“路口中心”，一次只能有一辆车（线程）经过。
        
    - 如果大家不管不顾一起冲进去，就会撞车（数据竞争）。
        
- **解决方案**：**互斥 (Mutual Exclusion, Mutex)**。
    
    - 我们在路口装一个“锁”。
        
    - **规则**：
        
        1. **加锁 (Lock/Acquire)**：想进临界区，先拿锁。如果锁被别人拿了，你就得等（Blocked）。
            
        2. **执行 (Execute)**：拿到锁的人，独享临界区，想怎么改数据都行，没人打扰。
            
        3. **解锁 (Unlock/Release)**：完事了，把锁交出来，唤醒正在等锁的人。
            
- **图解分析** ：
    
    - 图中 **Thread 1** 先抢到了锁 (`acquired`)，变成了红色状态（持有锁），正在舒舒服服地运行临界区代码。
        
    - **Thread 2** 晚了一步，去请求锁 (`request`)，结果发现锁被占了，于是被迫进入 **Blocked (阻塞)** 状态（紫色部分），在那干等 (`No progress`)。
        
    - 直到 Thread 1 释放锁 (`released`)，Thread 2 才能拿到锁继续运行。
        

### **2. 锁是怎么实现的？ (PPT 47)**

你可能会问：_“锁本身也是一个变量（比如 `int lock_flag = 0`），那谁来保护锁这个变量不被争抢呢？”_ 这就涉及到了**套娃**的问题。最终的解决方案必须依靠**硬件**。

- **硬件支持 (Hardware Support)**：
    
    - CPU 提供了一些特殊的指令，这些指令是 **原子 (Atomic)** 的。
        
    - **原子性**：意味着这个操作要么全做完，要么一点都不做，中间绝对**不能被打断**。哪怕天塌下来，CPU 也要把这条指令执行完。
        
- **常见的原子指令（必考名词）**：
    
    1. **TSL (Test and Set Lock)**：读一个值，并把它设为 1。这两步是一气呵成的。
        
    2. **CAS (Compare and Swap / 比较并交换)**：这是 Java并发包 (JUC) 和无锁编程的基石。
        
        - 逻辑：“如果内存里的值是我预期的旧值 A，那就把它改成新值 B；否则啥也不做。”
            
    3. **LL/SC (Load-linked / Store-Conditional)**：这是 RISC 架构（如 ARM, MIPS）常用的实现方式。
        

### **3. 锁的五花八门分类 (PPT 48)**

锁有很多种“性格”，根据不同的维度可以分成不同类别：

- **按“等锁时的表现”分（最重要）**：
    
    - **阻塞锁 (Blocking Lock)**：抢不到锁？那我就去**睡觉**（让出 CPU 给别人用）。等锁好了你叫醒我。
        
        - _优点_：省电，不浪费 CPU。_缺点_：睡下和醒来（上下文切换）很慢。
            
    - **自旋锁 (Spin Lock)**：抢不到锁？那我就**死等**（在一个 `while` 循环里一直问：好了没？好了没？）。
        
        - _优点_：反应快，不用切换线程。_缺点_：极其浪费 CPU（空转）。
            
        - _适用_：临界区很短，锁很快就能释放的场景。
            
- **按“能不能重复拿”分**：
    
    - **可重入锁 (Reentrant Lock)**：同一个线程拿了锁之后，还可以再次拿这把锁（比如递归调用）。
        
    - **不可重入锁**：自己拿了锁，再拿一次就把自己锁死了。
        
- **按“读写权限”分**：
    
    - **互斥锁 (Mutex)**：防君子也防小人。读写都得排队。
        
    - **读写锁 (Read-Write Lock)**：**读共享，写独占**。允许多个人同时读（因为读不改数据，没危险），但只要有人想写，就必须清场独占。

### **🎓 期末考题预测**

这一块是操作系统和并行计算的重合点，题目非常多。

#### **题型 1：简答/分析题（必考）**

- **题目**：请简述 **自旋锁 (Spin Lock)** 和 **阻塞锁 (Blocking Lock)** 的区别，并说明在什么情况下应该优先选择自旋锁？
    
- **参考答案**：
    
    - **区别**：阻塞锁在获取不到锁时会将线程挂起（睡眠），让出 CPU 资源；而自旋锁在获取不到锁时，线程会处于忙等待（Busy Waiting）状态，在一个循环中不断检查锁的状态，不让出 CPU。
        
    - **选择自旋锁的场景**：
        
        1. **临界区非常短**：线程持有锁的时间很短，等待的时间成本小于线程切换（挂起/唤醒）的开销。
            
        2. **多核处理器**：自旋需要占用一个物理核心空转，如果是单核，自旋会卡死系统。
            

#### **题型 2：填空题**

- **题目**：实现锁机制通常需要硬件提供支持，常见的硬件原子操作指令包括 ________ 和 ________。
    
- **答案**：测试并设置 (TSL)、比较并交换 (CAS)。
    

#### **题型 3：场景选择**

- **题目**：如果你在编写一个数据库系统，其中有一个配置表，几乎每秒钟有 10000 次读取请求，但每天只有 1 次修改请求。为了保证性能和数据安全，你应该使用哪种锁？ A. 互斥锁 (Mutex) B. 自旋锁 (Spin Lock) C. 读写锁 (Read-Write Lock)
    
- **答案**：**C**。
    
    - _解析_：读多写少场景，读写锁允许多个读者并发执行，性能远高于互斥锁。

## **信号量 (Semaphore) (PPT 49)**

### **1. 什么是信号量？**

- **核心定义**：它本质上是一个**计数器 (Counter)**，维护了一个整数值。
    
    - 这个值表示：**“当前还有多少个可用名额？”**
        
    - 取值范围：0 到 指定的最大值。
        

### **2. 两个核心操作：P操作与V操作**

这是操作系统（OS）考研的绝对重点，也是 PV 操作的由来（P 和 V 是荷兰语的首字母，因为发明者 Dijkstra 是荷兰人）。

- **P 操作 (Wait / Acquire)**：**“申请资源”**
    
    - **动作**：线程想进入，先看计数器。
        
    - 如果 `count > 0`：`count = count - 1`，线程继续执行（拿到名额了）。
        
    - 如果 `count == 0`：**阻塞 (Wait)**，线程必须等待，直到有名额空出来。
        
- **V 操作 (Signal / Release)**：**“释放资源”**
    
    - **动作**：线程离开，`count = count + 1`。
        
    - 如果有其他线程正在排队（Wait），这个操作会**唤醒**其中一个。
        

### **3. 信号量的状态**

- **Signaled (有信号)**：`计数值 > 0`。绿灯，可以通过。
    
- **Nonsignaled (无信号)**：`计数值 = 0`。红灯，必须停下。
    

### **4. 典型应用场景**

1. **资源限流**：
    
    - _例子_：只有 5 个打印机，但有 100 个线程要打印。
        
    - 设置 `Semaphore = 5`。前 5 个人能直接进（P操作），第 6 个人就得等（被阻塞），直到有人用完释放（V操作）。
        
2. **二进制信号量 (Binary Semaphore)**：
    
    - _定义_：最大值只设为 **1** 的信号量。
        
    - _等价于_：**互斥锁 (Mutex)**。因为名额只有一个，要么你用，要么我用，这就是互斥。

### **🎓 期末考题预测**

这一块常考计算题（PV操作）和概念辨析。

#### **题型 1：概念辨析（必考）**

- **题目**：请简述 **互斥锁 (Mutex)** 和 **信号量 (Semaphore)** 的主要区别。
    
- **参考答案**：
    
    - **数量限制**：Mutex 相当于计数为 1 的 Semaphore，只允许一个线程访问临界区（独占）；Semaphore 可以允许 N 个线程同时访问（共享，但限制并发数）。
        
    - **所有权**：Mutex 通常具有**所有权**概念，谁加锁必须由谁解锁；Semaphore 通常没有所有权，一个线程执行 P 操作（等待），可以由另一个线程执行 V 操作（释放/唤醒），这常用于线程间的**同步通知**（A 线程做完某事通知 B 线程）。
        

#### **题型 2：填空题**

- **题目**：在操作系统中，信号量的 P 操作对应于 ________，V 操作对应于 ________。当信号量的计数值为 0 时，执行 P 操作的线程将进入 ________ 状态。
    
- **答案**：等待 (Wait/Decrement)、发送信号 (Signal/Release/Increment)、阻塞 (Blocked/Waiting)。

## **通信与系统优化 (PPT 50-54)**

### **1. 重新定义计算机系统 (PPT 51)**

1

以前我们学计算机组成原理，可能只关注 CPU（计算）和 内存（存储）。但 PPT 提出了一个现代视角：

- **计算机系统 = 计算 + 存储 + 通信**
    
    - **存储**：对应 **空间域 (Spatial Domain)**。数据存在哪？占多少地？
        
    - **指令流**：对应 **时间域 (Temporal Domain)**。什么时候执行？
        
    - **通信**：连接时空的桥梁。数据从 A 搬到 B，就是在空间上移动；A 算完给 B 接着算，就是在时间上接力。
        

### **2. 通信模式的“黑话”大全 (PPT 52)**

2

这一页全是专业术语，考试特别喜欢考**名词辨析**。我们一个个拆解：

#### **(1) 传统通信分类**

- **同步 vs. 异步 (Synchronous / Asynchronous)**：
    
    - _同步_：打电话。我说话时你得听，实时在线。
        
    - _异步_：发微信/邮件。我发完了去干别的，你啥时候看都行。
        
- **串行 vs. 并行 (Serial / Parallel)**：
    
    - _串行_：单车道，数据一位一位传（如 USB）。
        
    - _并行_：多车道，数据多位一起传（如老式打印机并口）。
        
- **单工 vs. 双工 (Simplex / Duplex)**：
    
    - _单工_：收音机。只能听，不能回嘴。
        
    - _双工_：电话。双方都能说能听。
        
- **单播、组播、广播 (Unicast / Multicast / Broadcast)**：
    
    - _单播_：私聊（一对一）。
        
    - _组播_：群聊（一对多，但限于特定群组成员）。
        
    - _广播_：村口大喇叭（一对所有）。
        

#### **(2) 任务间通信模式**

- **点对点 (Point-to-Point)**：最基础的 `Send` / `Recv`。
    
- **一对多 (One-to-Many)**：比如 `Scatter`（分发任务）。
    
- **多对一 (Many-to-One)**：比如 `Gather`（收集结果）或 `Reduce`（归约求和）。
    

### **3. 核心考点：如何优化通信？ (PPT 53)** 🌟🌟🌟

3

通信通常是并行程序中最慢的环节（瓶颈）。PPT 给了三大优化方向，这是**简答题/分析题的满分答案模板**。

#### **策略一：减少通信量 (Reduce Volume)**

- **优化算法**：换个思路，少传点数据。
    
- **负载均衡**：别让某个人累死，导致大家都在等他，浪费通信带宽。
    
- **数据冗余 (Data Redundancy)**：
    
    - _核心逻辑_：**“多存一份，少跑一趟”**。
        
    - 还记得 **Ghost Zone (幽灵区)** 吗？这就是典型的数据冗余。为了不每次都问邻居要数据，我干脆在本地存一份副本。虽然浪费了存储空间，但省下了宝贵的通信时间。
        

#### **策略二：减少通信开销 (Reduce Overhead)**

- **打包数据 (Packing)**：
    
    - _例子_：你要寄 10 封信给同一个人。
        
    - _笨办法_：跑 10 次邮局，付 10 次邮费（高延迟）。
        
    - _好办法_：把 10 封信塞进一个大包裹，跑 1 次邮局（低延迟）。
        
    - 在 MPI 编程中，这叫 `Pack` / `Unpack`。
        

#### **策略三：通信与计算重叠 (Overlap)**

- **核心逻辑**：**“一心二用”**。
    
- 利用 DMA（直接内存访问）等硬件技术，让 CPU 在等待数据传输的同时，继续算别的东西。别傻等。
    

### **4. 终极哲学：并行性 vs. 局部性 (PPT 54)**

4

这是一个 **Trade-off (权衡)** 的太极图。也是并行编程的“第一性原理”。

- **并行性 (Parallelism)**：希望把任务拆得越细越好，大家一起干。
    
- **局部性 (Locality)**：希望数据都在手边，别老去远处拿。
    
- **矛盾点**：
    
    - 你想提高并行度 $\rightarrow$ 就要把任务切碎分给更多人 $\rightarrow$ 数据就分散了 $\rightarrow$ 通信就多了 $\rightarrow$ **局部性变差**。
        
- **结论**：优秀的架构师（你），就是要在“足够多的并行”和“足够少的通信”之间找到平衡点。

#### **题型 2：分析题**

- **题目**：PPT 54 展示了“并行性”与“局部性”的太极图。请解释为什么增加并行性往往会降低局部性？
    
- **答案**：
    
    - 增加并行性意味着将问题分解为更多的子任务分配给更多的处理器。这会导致数据被切分得更细碎，分布在不同的存储节点上。
        
    - 因此，每个任务需要访问的数据可能更多地位于远程节点（其他处理器的内存），导致**远程内存访问**增加，破坏了数据的**空间局部性**，从而增加了通信开销。
