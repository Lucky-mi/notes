## 一、 实验目的
1. 了解虚拟内存的 Page Fault 异常处理实现。
2. 了解页替换算法在操作系统中的实现。
3. 学会如何通过页表机制和中断异常处理机制，实现从虚拟地址到物理地址的映射，以及页面置换。
## 二、 实验内容与练习
本次实验是在实验二物理内存管理的基础上，实现虚拟内存管理。核心任务包括：完成缺页异常处理（`do_pgfault`）以及基于 FIFO 的页面置换算法。
### 练习 1：给未被映射的地址映射上物理页
#### 1. 设计与实现思路
`do_pgfault` 函数是缺页异常处理的核心。当程序访问一个合法的虚拟地址，但该地址对应的页表项（PTE）不存在或无效（P位为0）时，CPU 会触发 Page Fault，进而调用此函数。
我的实现逻辑如下（位于 `kern/mm/vmm.c`）：
1. **获取页表项 (PTE)**： 使用 `get_pte` 函数根据页目录表 `mm->pgdir` 和出错的线性地址 `addr` 查找对应的页表项。
    - 第三个参数设置为 `1`，表示如果中间的页表不存在，则由 `get_pte` 负责分配并创建。
    - 如果 `get_pte` 失败，说明内存耗尽，返回错误。
2. **判断页面状态**： 检查获取到的页表项内容 `*ptep`。
    - **情况 A：`*ptep == 0`**。说明该虚拟地址从未被映射过物理页。
        - 调用 `pgdir_alloc_page` 分配一个新的物理页。
        - 该函数内部会调用 `alloc_page` 分配物理内存，并使用 `page_insert` 建立虚拟地址与物理页的映射关系。
    - **情况 B：`*ptep != 0`**。说明该页表项存在，但 P 位为 0。这意味着该页面之前存在于内存中，但后来被置换到了磁盘交换区（Swap）。
        - 这属于练习 2 的内容（详见下文）。
**代码片段：**
```c
    // 尝试获取页表项，如果页表页不存在则创建
    if ((ptep = get_pte(mm->pgdir, addr, 1)) == NULL) {
        cprintf("get_pte in do_pgfault failed\n");
        goto failed;
    }
    
    // 如果页表项全为0，说明是全新的映射请求
    if (*ptep == 0) {
        if (pgdir_alloc_page(mm->pgdir, addr, perm) == NULL) {
            cprintf("pgdir_alloc_page in do_pgfault failed\n");
            goto failed;
        }
    }
    // ... else 分支处理 swap_in
```
#### 2. 问题回答
**问题 1：请描述页目录项（Page Directory Entry）和页表项（Page Table Entry）中组成部分对 ucore 实现页替换算法的潜在用处。**
- **Present (P) 位**：
    - **作用**：标记该页是否存在于物理内存中。
    - **用处**：这是实现虚拟内存的基础。如果 P=0，CPU 触发缺页异常，OS 借此机会将数据从磁盘换入内存。
- **Accessed (A) 位**：
    - **作用**：当该页被访问（读或写）时，硬件自动将此位置 1。
    - **用处**：对于实现 **Clock (时钟)** 或 **LRU (最近最少使用)** 算法至关重要。算法可以通过检查 A 位来判断该页最近是否被使用过。如果 A=1，说明是“热页”，暂不换出；如果 A=0，说明是“冷页”，可以作为换出候选。
- **Dirty (D) 位**：
    - **作用**：当该页被写入数据时，硬件自动将此位置 1。
    - **用处**：优化置换过程。在换出页面时，如果 D=1，说明内存中的数据比磁盘新，必须写回磁盘；如果 D=0，说明数据未被修改，直接释放物理页即可，无需写磁盘 IO，提高了效率。
- **Avail 位**：
    - **作用**：硬件保留给软件使用的位。
    - **用处**：当 P=0 时，页表项的高 24 位被 ucore 用来存储 `swap_entry_t`，即该页在磁盘 swap 文件中的扇区偏移量，从而找到该页在磁盘的位置。
**问题 2：如果 ucore 的缺页服务例程在执行过程中访问内存，出现了页访问异常，请问硬件要做哪些事情？**
这通常被称为**双重错误 (Double Fault)** 或嵌套异常。硬件流程如下：
1. **保存现场**：将当前的寄存器状态（EFLAGS, CS, EIP）压入内核栈。如果有错误码，也会压入。
2. **更新寄存器**：将引起异常的线性地址存入 **CR2** 寄存器。
3. **中断跳转**：查找中断描述符表 (IDT)，根据异常号跳转到对应的中断处理入口。
4. **注意**：如果在处理缺页异常时（内核态）再次发生无法修复的缺页异常，且导致堆栈溢出或无法执行处理程序，通常会导致系统崩溃（Triple Fault -> Reset）。但在 ucore 实验环境中，如果内核栈足够大且逻辑正确，嵌套的缺页可能会被递归处理（前提是内核自身的内存映射是静态锁定的，通常内核代码段不会缺页）。

### 练习 2：补充完成基于 FIFO 的页面替换算法

#### 1. 设计与实现思路
FIFO 算法的核心是维护一个记录所有可交换页面的链表，按照“先进先出”的原则进行替换。
**Part A: 完善 `do_pgfault` (vmm.c)** 处理 `*ptep != 0` 的情况，即**缺页换入 (Swap In)**：
1. **`swap_in`**：根据页表项中的 swap entry，从磁盘将数据读入到一个新的物理页。
2. **`page_insert`**：将这个物理页与出错的虚拟地址建立映射，并更新页表项（P=1）。
3. **`swap_map_swappable`**：将这个新换入的页加入到 FIFO 的置换队列中。
4. **`page->pra_vaddr = addr`**：**关键步骤**。设置页面的 `pra_vaddr` 属性，建立物理页到虚拟地址的反向映射。这是为了将来通过 `page` 结构体能找到其对应的 PTE，从而在换出时修改 PTE。

**Part B: 完善 FIFO 管理器 (swap_fifo.c)** 利用双向链表 `pra_list_head` 管理页面。
- **`_fifo_map_swappable` (入队)**：
    - 当页面加入管理时，使用 `list_add(head, entry)` 将其插入到链表头部（Head）。
    - 这意味着：**最新**进入的页面在 **Head**。
- **`_fifo_swap_out_victim` (出队)**：
    - FIFO 要求淘汰最早进入的页面。既然最新在 Head，那么最早的就在 **Tail**。
    - 通过 `head->prev` 获取链表尾部元素。
    - 调用 `list_del` 将其移除，并将该页面指针赋值给 `ptr_page` 返回。
#### 2. 问题回答
**问题：如果要在 ucore 上实现 "extended clock 页替换算法" 请给你的设计方案，现有的 swap_manager 框架是否足以支持？**
**设计方案：** Extended Clock (改进的时钟算法) 结合了 **Access (A)** 和 **Dirty (D)** 位来决定淘汰顺序，优先级从高到低（越容易被淘汰越好）：
1. (A=0, D=0): 最近未访问，且未修改（最佳 victim）。
2. (A=0, D=1): 最近未访问，但被修改过。
3. (A=1, D=0): 最近被访问，但未修改。
4. (A=1, D=1): 最近被访问，且被修改过。

**算法流程：**
1. 维护一个环形链表（Clock 指针）。
2. **第一轮扫描**：寻找 (A=0, D=0) 的页。不修改任何标志位。如果找到，淘汰之。
3. **第二轮扫描**：如果第一轮没找到，寻找 (A=0, D=1) 的页。在扫描过程中，将遇到的所有 A=1 的页的 A 位清零（给它一次机会）。如果找到 (A=0, D=1)，淘汰之。
4. 如果第二轮还没找到（此时所有 A 都变成了 0），回到第一步重复（实际上一定会找到）。
**是否足以支持？**
- **支持**。现有的 `swap_manager` 框架提供了 `map_swappable` (加入链表), `swap_out_victim` (寻找牺牲者), `tick_event` (时钟中断，虽 Clock 算法非必需但可辅助) 等接口。
- **需要被换出的页的特征**：根据上述优先级，首选 `(A=0, D=0)`，次选 `(A=0, D=1)`。
- **在 ucore 中如何判断？**
    - 利用 `pte_t *ptep = get_pte(...)` 获取页表项。
    - 检查 `*ptep & PTE_A` (Access) 和 `*ptep & PTE_D` (Dirty)。
- **何时进行换入和换出？**
    - **换出**：当 `alloc_pages` 发现物理内存不足时，调用 `swap_out`，进而触发 `swap_out_victim` 执行上述扫描逻辑。
    - **换入**：当发生缺页异常且页面在磁盘时 (`do_pgfault`)。

## 四、 实验总结与知识点

**本实验重要的知识点：**
1. **缺页异常处理流程**：CPU 硬件触发 -> 保存现场 -> 内核 `do_pgfault` -> 查页表 -> 分配页/换入 -> 建立映射 -> 恢复执行。
2. **页表项标志位**：PTE_P (Present), PTE_W (Writable), PTE_U (User), 以及 A/D 位在置换算法中的作用。
3. **页面置换机制**：
    - **Swap Entry**：当页被换出时，PTE 不再指向物理地址，而是存储磁盘扇区索引。
    - **FIFO 算法**：最简单的置换策略，但在特定序列下可能出现 Belady 现象（页框增加反而缺页增加）。
4. **物理页与虚拟页的联系**：
    - `struct Page` 中的 `pra_vaddr` 建立了物理页到虚拟地址的映射，这在置换算法选择 victim 后，反查并修改 PTE 时必不可少。

**OS 原理中重要但在本实验未涉及的知识点：**
1. **TLB 管理**：实验中调用了 `tlb_invalidate`，但没有深入涉及 TLB 的硬件工作细节及多核下的 TLB Shootdown。
2. **工作集 (Working Set) 模型**：实验仅实现了局部置换算法，没有涉及防止系统抖动（Thrashing）的全局页面分配策略。
3. **写时复制 (Copy On Write)**：这是现代 OS 进程创建（fork）时的核心优化，本实验尚未实现。
4. **更高级的置换算法**：如 LRU（需要硬件时间戳支持或复杂软件模拟）、LFU 等。

#### 扩展练习 Challenge 1：实现识别 dirty bit 的 extended clock 页替换算法

**1. 设计方案与原理** Extended Clock 算法是在传统的 Clock 算法基础上，引入了页表项中的 `PTE_D` (Dirty Bit) 作为置换优先级的考量依据。

- **硬件依据**：ucore 利用 x86 页表项的 `PTE_A` (Accessed) 表示页面最近是否被读取，利用 `PTE_D` (Dirty) 表示页面最近是否被写入。
    
- **算法目标**：优先淘汰未被修改过的页面（D=0），因为这些页面可以直接释放而无需写回磁盘（Swap Out IO操作），从而提高系统效率。
    

**2. 具体的置换策略** 在 `swap_out_victim` 函数中，我实现了一个类似于环形链表的扫描逻辑，通过指针 `curr_ptr` 遍历 `pra_list_head`。算法分为四轮查找，直到找到牺牲页：

- **第一轮**：查找 `(A=0, D=0)` 的页面。这是最佳牺牲页，既没被访问也没被修改。
    
- **第二轮**：查找 `(A=0, D=1)` 的页面。如果这一轮没找到，**需要将所有扫描过的页面的 A 位清零**（给予第二次机会）。这是为了让刚才还是 (1, 0) 或 (1, 1) 的页面在下一轮变成 (0, 0) 或 (0, 1)。
    
- **第三轮**：再次查找 `(A=0, D=0)` 的页面。由于第二轮清除了 A 位，原先 (1, 0) 的页面现在变成了 (0, 0)，可以被选中。
    
- **第四轮**：再次查找 `(A=0, D=1)` 的页面。同理，原先 (1, 1) 的页面现在变成了 (0, 1)。
    

**3. 与原 Clock 算法的区别** 原 Clock 算法只看 A 位，如果 A=1 则清零并跳过，如果 A=0 则淘汰。Extended Clock 算法在 A 位的基础上增加了 D 位的权重，使得“脏页”在内存中停留的时间更长，减少了磁盘写操作的频率。

#### 扩展练习 Challenge 2：实现不考虑实现开销和效率的 LRU 页替换算法

**1. 设计方案与原理** LRU (Least Recently Used) 算法的核心思想是：如果数据最近被访问过，那么将来被访问的几率也更高。反之，最久未被访问的数据应该被淘汰。

**2. 实现细节** 我利用了 ucore 的 `swap_manager` 框架中的 `map_swappable` 函数来模拟 LRU 的核心逻辑。虽然在真实的硬件 LRU 中需要耗费巨大的硬件开销来记录时间戳或堆栈，但在本实验中，我们可以利用链表操作简化实现：

- **数据结构**：使用双向链表 `pra_list_head`。
    
- **页面访问 (`map_swappable`)**：每当页面被访问（或发生缺页换入）时，系统调用此函数。我在代码中先执行 `list_del(entry)` 将页面从链表当前位置移除，然后执行 `list_add(head, entry)` 将其重新插入到链表头部。这样保证了链表头部始终是“最近使用”的页面。
    
- **页面置换 (`swap_out_victim`)**：由于链表头是最近使用的，那么链表尾部（`head->prev`）自然就是最久未被使用的页面。因此，直接选择链表尾部的页面作为 Victim 进行换出。
    

**3. 相比 FIFO 的优势** FIFO 算法可能遭遇 Belady 现象（物理页增加反而缺页次数增加），且它完全忽略了程序的局部性原理（Locality Principle）。LRU 算法通过将热点数据保留在链表前端，极大地契合了程序的时间局部性，通常能获得比 FIFO 更好的性能。

**4. 潜在的开销** 虽然本实验实现了 LRU，但在实际 OS 中，每次内存访问都修改链表（修改指针）会带来巨大的开销，且如果不借助硬件（如 TLB 访问位），软件层面很难捕获每一次“读”操作。因此实际系统常用 Clock 算法作为 LRU 的近似实现。
