**SNMP** 是 **Simple Network Management Protocol**（简单网络管理协议）的缩写。

简单来说，它是**网络世界的“体检医生”和“遥控器”**。它是一种标准化的通信协议，用于让网络管理员监控、组织和修改网络设备（如路由器、交换机、服务器、打印机等）的配置和状态。

它是 TCP/IP 协议簇中**应用层**的协议（通常基于 **UDP** 传输）。

---

### 1. 核心概念：SNMP 的“三剑客”

要理解 SNMP，只需要理解这三个角色的关系：

1. **管理站 (Manager / NMS)**：
    
    - **角色**：老板、监控中心。
        
    - **功能**：运行在管理员电脑或服务器上的软件（如 Zabbix, Prometheus, SolarWinds）。它负责向设备发号施令或查询状态。
        
2. **代理 (Agent)**：
    
    - **角色**：员工、设备内的间谍。
        
    - **功能**：运行在被管理设备（如路由器）上的一个小程序。它负责收集设备信息，回答 Manager 的提问，或者在出事时主动汇报。
        
3. **管理信息库 (MIB - Management Information Base)**：
    
    - **角色**：字典、账本。
        
    - **功能**：一个树状结构的数据库，定义了设备里有哪些信息可以被查询。
        
    - _注_：MIB 使用 **OID** (Object Identifier) 来唯一标识每一个变量（例如，`1.3.6.1.2.1.1.1` 可能代表设备的系统描述）。
        

---

### 2. 工作原理：它是怎么聊天的？

SNMP 的交互主要有两种模式：**“一问一答”** 和 **“主动告警”**。

#### A. 一问一答 (Request / Response)

这是最常见的模式，由 Manager 发起。

- **Get-Request**: Manager 问 Agent：“你现在的 CPU 使用率是多少？”
    
- **Get-Next-Request**: Manager 问：“在这个列表里，下一条数据是什么？”（用于遍历表格）。
    
- **Set-Request**: Manager 命令 Agent：“把你 2 号端口关掉！”（修改配置）。
    
- **Response**: Agent 回复：“CPU 使用率是 45%” 或 “好的，已关闭”。
    

> **技术细节**：默认使用 UDP **161** 端口。

#### B. 主动告警 (Trap)

这是由 Agent 主动发起的（通常是出事了）。

- **Trap**: Agent 突然喊：“不好了！电源模块坏了！”或者“有人试图暴力破解密码！”
    
- Manager 收到后会触发报警（发邮件、短信等）。
    

> **技术细节**：Trap 发送给 Manager 的 UDP **162** 端口。

### 3. SNMP 的三个主要版本 (考研/面试重点)

随着时间推移，SNMP 经历了三个版本的迭代，安全性逐渐增强：

|**版本**|**特点**|**安全性**|**备注**|
|---|---|---|---|
|**SNMP v1**|最早版本，功能简单。|**极差**。使用明文的“Community String”（团体名）作为密码（通常默认是 `public`）。抓包即可看到。|已淘汰，但老设备仍有兼容。|
|**SNMP v2c**|目前最常用。增加了 `GetBulk` 操作（一次取多条数据），性能更好。|**差**。依然使用明文的 Community String。|内网监控的主流选择。|
|**SNMP v3**|最新标准。|**高**。支持身份验证（MD5/SHA）和加密（DES/AES）。|公网或高安全需求环境必须使用。|

---

### 4. 为什么 SNMP 如此重要？

1. **统一语言**：无论你是 Cisco 的路由器、Linux 的服务器，还是 HP 的打印机，只要支持 SNMP，管理员就可以用同一套软件监控它们。
    
2. **轻量级**：使用 UDP 协议，对网络带宽和设备性能的占用非常小。
    
3. **广泛支持**：几乎所有企业级网络设备出厂都默认支持。
