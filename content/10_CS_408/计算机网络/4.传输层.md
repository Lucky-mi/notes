  ### 一、 核心定位：从“主机”到“进程”

这是运输层最本质的功能，也是它和网络层最大的区别（考研常考辨析）。

- **网络层 (Network Layer)**：提供 **主机到主机 (Host-to-Host)** 的通信。
    
    - _类比_：邮递员只负责把包裹送到“北京市海淀区xx小区3号楼”（IP地址），他不管这包裹是给爸爸的、妈妈的还是儿子的。
        
- **运输层 (Transport Layer)**：提供 **进程到进程 (Process-to-Process)** 的通信。
    
    - _类比_：家里的管家（运输层）接过包裹，看到上面写着“王小明收”（端口号），于是把包裹准确地交到了正在打游戏的王小明（进程）手里。
        

##### **关键概念：复用与分用 (Multiplexing & Demultiplexing)**

- **复用**：发送方不同的应用进程都可以使用同一个运输层协议传送数据。
    
- **分用**：接收方的运输层在剥去报文首部后，能够把数据正确交付给目的应用进程。
    
- **实现工具**：**端口号 (Port)**。
    
这两个概念通常出现在**计算机网络**的**传输层**（Transport Layer）中。

简单来说，这是解决**“一台电脑上同时运行很多个联网软件（如微信、浏览器、游戏），但只有一根网线（或一个 IP 地址）”**这个问题的机制。

我们可以把它们看作是**打包**和**分发**的过程：

1. 复用 (Multiplexing) —— 发送方

**方向：从上往下（应用层 -> 传输层 -> 网络层）**

- **含义**：指发送方的不同的应用进程（如微信发消息、浏览器访问网页）都可以使用同一个传输层协议（TCP 或 UDP）传送数据。
    
- **动作**：传输层收集不同应用程序发来的数据块，给它们分别加上**头部信息**（Header），在这个头部里最关键的就是**源端口号**。
    
- **目的**：把来自不同“房间”（进程）的数据汇聚到同一个“出口”（IP层/网卡）发送出去。
    

> **一句话总结**：多股车流汇入主干道。

2. 分用 (Demultiplexing) —— 接收方

**方向：从下往上（网络层 -> 传输层 -> 应用层）**

- **含义**：指接收方的传输层在收到数据后，能够把数据正确地交付给对应的应用进程。
    
- **动作**：传输层收到网络层交上来的数据包，检查**头部信息**（主要是**目的端口号**），根据这个号码，把数据准确地丢给正在等待的那个应用程序（如微信收到的给微信，浏览器的给浏览器）。
    
- **目的**：从同一个“入口”进来的数据，准确分发到不同的“房间”（进程）。
    

> **一句话总结**：快递员根据门牌号把包裹送到不同住户手中。

---

3. 核心关键：端口号 (Port)

这两个过程能实现，全靠**端口号**。

- **复用时**：打上“我是谁”（源端口）和“我要找谁”（目的端口）的标记。
    
- **分用时**：读取“你要找谁”（目的端口）的标记。
    

---

 4. 生活中的例子：公司收发室

为了方便记忆，你可以想象一家公司（一台电脑）：

- 复用（寄信）：
    
    公司的员工 A（微信）和员工 B（浏览器）都要寄信。他们把信丢进楼下的同一个邮筒（传输层）。邮筒把所有的信统一收集起来，交给邮递员（IP 层）发往世界各地。
    
    这就是复用：大家共用一个发信渠道。
    
- 分用（收信）：
    
    邮递员把一大袋信送到公司前台。前台（传输层）拿起每一封信，看信封上的名字（端口号）：
    
    - “这封是给员工 A 的。” -> 送到 A 的桌子上。
        
    - “这封是给员工 B 的。” -> 送到 B 的桌子上。
        
        这就是分用：根据标记把混在一起的数据分开给不同的人。
        

---

 总结对比

|**概念**|**英文**|**发生位置**|**动作**|**关键依据**|
|---|---|---|---|---|
|**复用**|Multiplexing|发送方|多对一 (封装)|源端口号|
|**分用**|Demultiplexing|接收方|一对多 (分发)|目的端口号|

**(如果是考研/408复习，请注意：UDP 是基于“目的IP+目的端口”分用；而 TCP 是基于“源IP+源端口+目的IP+目的端口”四元组进行分用。)**

### 二、 两个主角：UDP vs TCP

运输层只有两个主要协议，但它们的性格截然不同。考研中对这两者的对比考察非常细致。

#### 1. [[UDP]] (用户数据报协议) —— “直爽的莽夫”

- **特点**：
    
    - **无连接**：发数据之前不需要建立连接，想发就发。
        
    - **尽最大努力交付**：不保证可靠（可能会丢包、乱序），也不重传。
        
    - **面向报文**：应用层给多长，我就发多长，不拆分也不合并。
        
    - **首部开销小**：只有 **8个字节**（源端口、目的端口、长度、检验和）。
        
- **适用场景**：视频会议、IP电话、流媒体（允许丢几帧，但不能卡顿）、DNS（查询速度要快）。
    

#### 2. [[TCP]](传输控制协议) —— “严谨的管家”

- **特点**：
    
    - **面向连接**：通信前必须先“三次握手”建立连接。
        
    - **可靠交付**：无差错、不丢失、不重复、按序到达。
        
    - **面向字节流**：它把数据看成一连串无结构的字节流，不保证接收方收到的数据块大小与发送方一次发送的一样（可能会拆包或粘包）。
        
    - **首部开销大**：最小 **20个字节**。
        
    - **全双工通信**：连接的两端都可以同时发送和接收数据。
        
- **适用场景**：文件传输 (FTP)、网页浏览 (HTTP)、邮件 (SMTP)，任何不允许数据出错的场景。
    

---

### 三、 TCP 的三大核心机制（408 命题重灾区）

为了在不可靠的 IP 网络上实现可靠的传输，TCP 引入了极其复杂的控制机制。这部分是你在复习时需要**重点攻克**的堡垒：

1. **可靠传输机制 (Reliable Transmission)**
    
    - **原理**：怎么知道数据丢没丢？丢了怎么办？
        
    - **关键词**：停止等待协议、ARQ (自动重传请求)、滑动窗口、超时重传、累计确认。
        
    - _考点_：给你发包的时间图，让你算吞吐量或信道利用率。
        
2. **流量控制 (Flow Control)**
    
    - **目的**：**点对点**的控制。防止发送方发太快，接收方来不及收。
        
    - **手段**：**滑动窗口 (Sliding Window)**。接收方会在确认报文中告诉发送方：“我的缓存还能装多少数据（rwnd）”，发送方据此调整发送速度。
        
3. **拥塞控制 (Congestion Control)**
    
    - **目的**：**全局**的控制。防止过多的数据注入到网络中，导致网络路由器过载。
        
    - **算法**：慢开始 (Slow Start)、拥塞避免 (Congestion Avoidance)、快重传 (Fast Retransmit)、快恢复 (Fast Recovery)。
        
    - _考点_：**拥塞窗口 (cwnd) 的变化曲线图**。这是每年的必考题，通常结合具体轮次让你算当前的窗口大小。

## 协议简介
### 第一阵营：路由协议（互联网的导航员）

这三个是考研的**重中之重**，必须分清它们的区别。

**1. RIP (Routing Information Protocol)**

- **一句话介绍**：最简单的“数数”协议。
    
- **核心机制**：**距离矢量算法**。它认为“距离”就是“跳数”（经过路由器的数量）。
    
- **考点**：
    
    - **限制**：最大只能跳 **15** 次，16 次就被视为不可达（只适合小网络）。
        
    - **特点**：“好消息传得快，坏消息传得慢”（收敛慢，容易产生路由环路）。
        
    - **周期性**：每 30 秒广播一次整个路由表。
        

**2. OSPF (Open Shortest Path First)**

- **一句话介绍**：精明的“画地图”协议。
    
- **核心机制**：**链路状态算法**。每个路由器都向全网广播自己的链路状态，最后大家手里都有一张完整的全网拓扑图，然后用 **Dijkstra 算法**算出最短路径。
    
- **考点**：
    
    - 收敛速度快，适合大网络。
        
    - **区域划分**：为了减少广播流量，把网络切分成很多区域（Area），核心是骨干区域（Area 0）。
        
    - **封装**：它很傲娇，直接封装在 IP 包里（协议号 89）。
        

**3. BGP (Border Gateway Protocol)**

- **一句话介绍**：国家与国家（AS与AS）之间的外交官。
    
- **核心机制**：**路径矢量算法**。
    
- **考点**：
    
    - 它不追求“最快”到达，而是追求“**最佳策略**”（比如我不走那个国家的路由，因为关系不好）。
        
    - 因为环境复杂且危险，所以它选择 **TCP** 连接来保证消息一定送到。
        
    - 它只交换**发生变化**的路由信息。
        

---

### 第二阵营：万维网与传输（互联网的脸面）

**4. HTTP (HyperText Transfer Protocol)**

- **一句话介绍**：浏览器向服务器要网页的规则。
    
- **考点**：
    
    - **无状态**：服务器记不住你是谁，每次请求都是独立的（所以需要 Cookie/Session 来帮忙记录登录状态）。
        
    - **持久连接 (Keep-alive)**：HTTP/1.1 默认开启，建立一次 TCP 连接后，可以传多个图片和文件，不用每次都握手。
        

**5. HTTPS**

- **一句话介绍**：穿了防弹衣的 HTTP。
    
- **考点**：在 HTTP 和 TCP 之间加了一层 **SSL/TLS** 协议，通过证书和加密技术，防止数据被窃听或篡改。
    

**6. FTP (File Transfer Protocol)**

- **一句话介绍**：古老且复杂的搬运工。
    
- **考点**：**带外传送**。哪怕你不传文件，只要连着 FTP，控制连接（端口21）就一直断着；只有传文件的那一瞬间，数据连接（端口20）才会被建立。
    

**7. TFTP (Trivial FTP)**

- **一句话介绍**：极简版的 FTP。
    
- **考点**：因为它用 **UDP**，代码非常小。常用于**无盘工作站**启动——因为电脑刚启动时还没有复杂的 TCP 协议栈，只能用这个简单的协议去服务器拉取操作系统镜像。
    

---

### 第三阵营：电子邮件（信息的投递员）

**8. SMTP (Simple Mail Transfer Protocol)**

- **一句话介绍**：只管**发**，不管收。
    
- **考点**：
    
    - 它是“**推 (Push)**”协议。你发给邮件服务器，或者邮件服务器发给另一个邮件服务器，都是他在主动“推”。
        
    - 早期的 SMTP 只能传 ASCII 码（纯文本），传图片要用 **MIME** 扩展。
        

**9. POP3 (Post Office Protocol v3)**

- **一句话介绍**：把信拿回家读。
    
- **考点**：它是“**拉 (Pull)**”协议。默认情况下，你把邮件下载到本地电脑后，服务器上就删除了（虽然现在的软件可以设置保留，但协议原生设计如此）。
    

**10. IMAP (Internet Message Access Protocol)**

- **一句话介绍**：在服务器上直接读信。
    
- **考点**：也是“**拉**”协议。但它让本地电脑和服务器保持**同步**。你在手机上把邮件标为“已读”，服务器上也会变成“已读”，回家用电脑看也是“已读”。
    

---

### 第四阵营：基础设施与管理（幕后的英雄）

**11. DNS (Domain Name System)**

- **一句话介绍**：互联网的电话本。
    
- **考点**：
    
    - **递归查询**：你问根服务器，根服务器帮你去问别人，最后把结果给你（靠谱的管家）。
        
    - **迭代查询**：根服务器告诉你“我不知道，你去问 .com 服务器吧”，你自己跑断腿（踢皮球）。
        
    - **根域名服务器**：全球共有 13 套（注意是套，不是台）。
        

**12. DHCP (Dynamic Host Configuration Protocol)**

- **一句话介绍**：自动发 IP 的网管。
    
- **考点**：**即插即用**。新电脑加入网络，通过 4 步广播（发现、提供、请求、确认）自动获取 IP 地址、子网掩码、网关和 DNS 地址。
    

**13. SNMP (Simple Network Management Protocol)**

- **一句话介绍**：网络医生的听诊器。
    
- **考点**：
    
    - **管理站**（医生）和 **代理**（病人/路由器）。
        
    - 通常是医生问（轮询），病人答。
        
    - **Trap (陷阱)**：病人病情恶化（出故障）时，主动报警给医生，不用等医生来问。
        

**14. TELNET**

- **一句话介绍**：早期的远程控制。
    
- **考点**：**裸奔**。你的用户名和密码在网络上是**明文**传输的，黑客抓个包就能看清。现在基本淘汰。
    

**15. SSH (Secure Shell)**

- **一句话介绍**：安全的远程控制。
    
- **考点**：它替代了 TELNET，所有数据都经过**加密**。现在程序员连服务器（比如你以后去字节跳动连 Linux 开发机）用的都是这个。
