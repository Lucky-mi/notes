无线局域网（WLAN，即 Wi-Fi，标准代号 802.11）是绝对的高潮部分。

因为在这里，之前学的 CSMA/CD 被**彻底抛弃**了，换成了一个更小心翼翼的协议 —— **CSMA/CA**。

要挖透它，我们得先解决三个核心问题：

1. 为什么不能用 CSMA/CD？（为什么要换？）
    
2. **隐蔽站**和**暴露站**问题是什么？（无线特有的坑）
    
3. **RTS/CTS** 握手协议是如何填坑的？（天才的设计）
    

---

### 第一部分：为什么 CSMA/CD 在无线局域网里“废了”？

在有线网络（以太网）里，我们可以“边说边听”（碰撞检测 CD）。但在无线环境里，这招行不通，主要有两个物理原因：

1. **听不见（信号强度悬殊）：**
    
    - 当你自己发射无线信号时，你的功率很大；而远方传来的信号衰减得很厉害，功率极小。
        
    - 如果你“边说边听”，你自己巨大的发射功率会彻底淹没远处的信号。
        
    - **比喻：** 就像你在摇滚音乐节上对着麦克风大吼，你怎么可能听到台下几百米外有人在跟你说话？
        
2. **听到了也没用（隐蔽站问题）：**
    
    - 有线网络里，大家都在一根线上，我说话大家都能听到。
        
    - 无线网络里，**A 能听到 B，B 能听到 C，但 A 听不到 C！**
        

所以，无线局域网被迫放弃了“检测 (Detection)”，改成了 **“避免 (Avoidance)”** —— **CSMA/CA**。

---

### 第二部分：无线局域网的两大死穴

#### 1. 隐蔽站问题 (Hidden Station Problem)

**场景：** A —— B —— C

- A 和 C 分别在 B 的左右两边。
    
- A 的信号能覆盖 B，C 的信号也能覆盖 B。
    
- **但是：A 和 C 互相听不见（距离太远或有障碍物）。**
    

**悲剧发生：**

1. A 监听信道，发现没人说话（因为听不到 C），于是 A 开始给 B 发数据。
    
2. C 同时也监听信道，也发现没人说话（因为听不到 A），于是 C 也开始给 B 发数据。
    
3. **结果：** A 和 C 的信号在 B 处**猛烈撞车**。
    
4. **关键：** A 和 C 甚至都不知道撞车了，只有 B 知道，但 B 此时没法说话。
    

#### 2. 暴露站问题 (Exposed Station Problem)

**场景：** B —— A —— C —— D

- A 正在给 B 发数据。
    
- C 听到了 A 的信号，认为信道“忙”。
    
- C 实际上想给 D 发数据（D 在更远的地方，不受 A 干扰）。
    
- **悲剧：** C 仅仅因为听到了 A 的声音，就傻傻地不敢给 D 发数据，实际上 C 发给 D 根本不会影响 A 发给 B。
    
- **后果：** 浪费了宝贵的带宽。
    

---

### 第三部分：CSMA/CA 的大招 —— RTS/CTS 握手

为了解决上述问题（尤其是隐蔽站），802.11 引入了一个**“预约机制”。

既然我听不准，那我就让基站（AP）帮我昭告天下**。

这包含四个关键步骤：**RTS -> CTS -> DATA -> ACK**

#### 1. RTS (Request To Send，请求发送)

- **A 想发数据给 B。**
    
- A 先发一个小小的控制帧叫 **RTS**。
    
- **内容：** “B 你好，我想给你发数据，大概需要占用信道 **10毫秒**，可以吗？”
    

#### 2. CTS (Clear To Send，允许发送)

- **B 收到 RTS 后**，如果同意，就广播一个 **CTS** 帧。
    
- **内容：** “A 你好，我准了！你可以发，时长 **10毫秒**。”
    
- **最精妙的地方来了：**
    
    - 这个 CTS 是广播出去的。
        
    - **隐蔽站 C** 虽然听不到 A 的 RTS，但它**一定能听到 B 的 CTS**！
        
    - C 一听到 CTS，解读出“有人要占用 10毫秒”，于是 C 默默拿出一个闹钟（叫 **NAV**，网络分配矢量），定好 10ms 的倒计时，期间闭嘴，绝不捣乱。
        

> **解决隐蔽站：** C 通过听 B 的宣告（CTS），知道了 A 的存在。

#### 3. DATA (发送数据)

- A 收到 CTS 后，知道大家都闭嘴了，开始放心地发真正的数据帧。
    

#### 4. ACK (确认)

- 无线传输很不可靠（微波炉开一下都可能干扰信号）。
    
- 所以，B 收到数据且校验无误后，必须回传一个 **ACK** 帧。
    
- A 只有收到了 ACK，才算发送成功；否则会重传。

### 第四部分：各种“等待” (IFS - InterFrame Space)

CSMA/CA 还有一个很有趣的细节：不仅要等，还要分等级地等。

如果你去查书，会看到 SIFS, DIFS 这种词，其实很好理解：

**规则：谁更重要，谁等待的时间就越短（越能抢到机会）。**

1. **SIFS (Short IFS，短帧间间隔)：**
    
    - **最短！** 优先级最高。
        
    - **谁用？** 处理 **ACK**、**CTS** 这种必须立即回复的帧。
        
    - **逻辑：** 别人发给我数据，我回 ACK 必须是第一优先级的，别人都得给我让路。
        
2. **DIFS (Distributed IFS，分布式帧间间隔)：**
    
    - **较长。**
        
    - **谁用？** 普通的数据帧。
        
    - **逻辑：** 我想发新数据？那我得先乖乖等一会儿（DIFS），确定真的没人用 SIFS 在插队，我才能开始竞争。

### 总结：无线 vs 有线

|**特性**|**有线以太网 (802.3)**|**无线局域网 (802.11)**|
|---|---|---|
|**协议**|CSMA/CD (碰撞检测)|CSMA/CA (碰撞避免)|
|**检测方式**|边听边说，电压变化|**ACK 确认** (没收到ACK=撞车)|
|**能否全双工**|能 (现在的交换机网络)|**不能** (无线是半双工，同一频率同一时间只能单向)|
|**核心困境**|信号冲突|隐蔽站、暴露站、信号衰减|
|**解决大招**|最小帧长、指数退避|**RTS/CTS 握手**、NAV倒计时|

**一句话总结 Wi-Fi 的传输逻辑：**

> “我想发？先不管三七二十一等个 DIFS。然后发个申请单 RTS。基站广播批准 CTS，顺便让周围隐形的“敌人”闭嘴 (NAV)。然后我发数据，收到 ACK 才算完事。这一套流程走下来，尽量避免撞车。”
