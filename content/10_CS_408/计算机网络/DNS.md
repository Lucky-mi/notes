### 一、 DNS 的核心架构：分布式与层次化

互联网上的主机太多了，如果用一台服务器记录所有 `域名 <-> IP` 的映射，这台服务器一旦挂掉，全球断网。因此，DNS 设计成了**联机分布式数据库系统**。

#### 1. 层次树状结构

DNS 的域名空间是从“根”开始划分的，倒过来看像一棵树：

1. **根域名 (Root Domain)**：虽然我们平时看不到，但在所有域名最后都有一个点（例如 `www.baidu.com.`）。
    
    - 全球有 **13组** 根域名服务器（逻辑上的13个，物理上通过任播技术分布在全球几百个地点）。
        
    - 名字从 `a.root-servers.net` 到 `m.root-servers.net`。
        
2. **顶级域名 (TLD, Top-Level Domain)**：
    
    - **通用顶级域名 (gTLD)**：`.com`, `.org`, `.net`, `.edu` 等。
        
    - **国家/地区顶级域名 (ccTLD)**：`.cn` (中国), `.jp` (日本), `.uk` (英国)。
        
3. **二级域名**：如 `baidu.com`，`bnu.edu.cn` 中的 `bnu`。这是企业或组织注册的。
    
4. **三级域名/主机名**：如 `www.bnu.edu.cn` 中的 `www`，或者 `mail.bnu.edu.cn` 中的 `mail`。
    

#### 2. 核心服务器类型 (考点：谁存了什么？)

- **根域名服务器**：它不知道具体的IP，但它知道“`.cn` 归谁管”，能把查询请求转发给 TLD 服务器。
    
- **顶级域名服务器 (TLD Server)**：管理该顶级域名下的注册信息，它知道“`bnu.edu.cn` 归谁管”。
    
- **权限域名服务器 (Authoritative Server)**：这是**真正拥有**域名解析记录的地方。比如北师大的网络中心维护着一台服务器，里面记录了 `www.bnu.edu.cn` 对应的 IP 是多少。
    
- **本地域名服务器 (Local DNS / Recursive Resolver)**：**这是重点！**
    
    - 当你联网时，ISP（电信/联通）或学校网关会给你分配一个 DNS（如 `8.8.8.8` 或学校的 DNS）。
        
    - 它充当**代理人**，你只管问它，它负责跑腿去问根、问TLD、问权限服务器，最后把结果给你。

### 二、 DNS 解析流程 (重中之重)

这里涉及两个关键概念：**递归查询 (Recursive)** 和 **迭代查询 (Iterative)**。

#### 场景模拟

假设你要访问 `www.example.com`，你的电脑（主机 A）和本地域名服务器（Local DNS）之间发生的故事：

1. **主机 -> 本地域名服务器**：**递归查询**。
    
    - 主机问 Local DNS：“你知道 `www.example.com` 的 IP 吗？**一定要给我个确切结果**（要么是IP，要么报错）。”
        
2. **本地域名服务器 -> 互联网**：**迭代查询**。
    
    - Local DNS 先问 **根服务器**：“你知道 `www.example.com` 吗？”
        
    - 根服务器回答：“我不知道，但 `.com` 归 **TLD服务器A** 管，你去问它。IP是 x.x.x.x。”
        
    - Local DNS 再问 **TLD服务器A**：“你知道 `www.example.com` 吗？”
        
    - TLD服务器A 回答：“我不知道，但 `example.com` 归 **权限服务器B** 管，你去问它。IP是 y.y.y.y。”
        
    - Local DNS 最后问 **权限服务器B**：“你知道 `www.example.com` 吗？”
        
    - 权限服务器B 回答：“知道！IP 是 `93.184.216.34`。”
        
3. **本地域名服务器 -> 主机**：
    
    - Local DNS 拿到 IP 后，**存入缓存**，然后把 IP 告诉主机。
        

> **🔍 细节总结**：
> 
> - 主机主要进行**递归**查询。
>     
> - 本地域名服务器主要进行**迭代**查询（替你跑腿）。
>

### 三、 DNS 协议的技术细节 (硬核考点)

#### 1. 传输层协议：UDP 还是 TCP？

这是面试和考研最爱问的坑。**答案是：主要用 UDP，特殊情况用 TCP。** 端口都是 **53**。

- **普通查询 (UDP)**：
    
    - 绝大多数域名解析使用 UDP。
        
    - **原因**：速度快，开销小。DNS请求报文很短，丢了重发即可，不需要TCP的三次握手开销。
        
    - **限制**：UDP报文最长通常限制在 512 字节（传统限制）。如果响应太长被截断，会切换到 TCP。
        
- **区域传送 (Zone Transfer) (TCP)**：
    
    - 主域名服务器 (Master) 和 辅助域名服务器 (Slave) 之间同步数据时。
        
    - **原因**：数据量大，且必须保证数据的准确性（不能丢包），所以必须用可靠的 TCP。
        

#### 2. 高速缓存 (Caching) 与 TTL

为了减少网络流量，DNS 解析的每个环节（浏览器、操作系统、Local DNS）都有缓存。

- **TTL (Time To Live)**：每条 DNS 记录都有一个生存时间（如 600秒）。
    
- **考点**：如果你修改了网站的 IP，用户可能不会立刻生效，因为 Local DNS 里的旧缓存还没过期（TTL 还没减到 0）。

### 四、 关键资源记录类型 (RR, Resource Records)

DNS 数据库里存的不仅仅是 IP，还有很多类型。你需要记住这几个：

|**类型**|**英文全称**|**作用**|**例子**|
|---|---|---|---|
|**A**|Address|**域名 -> IPv4 地址** (最常用)|`www.bnu.edu.cn` -> `202.112.xx.xx`|
|**AAAA**|Address v6|**域名 -> IPv6 地址**|`www.google.com` -> `2404:6800:...`|
|**CNAME**|Canonical Name|**别名 -> 真名** (规范名)|`mail.google.com` 其实是 `googlemail.l.google.com` 的别名|
|**NS**|Name Server|**域名 -> 负责该域名的服务器名字**|`bnu.edu.cn` 的解析由 `dns.bnu.edu.cn` 负责|
|**MX**|Mail Exchange|**邮件服务器** (发邮件用)|发给 `@163.com` 的邮件，请找 `mx.163.com`|
|**PTR**|Pointer|**IP -> 域名** (反向解析)|查这个 IP 属于哪个域名|

### 五、 一个完整的访问流程 (细节串联)

当你在浏览器输入 `www.bnu.edu.cn` 时，真正的查找顺序是：

1. **浏览器缓存**：Chrome 自己先看刚才是不是访问过。
    
2. **OS 缓存 (Hosts 文件)**：系统看 `/etc/hosts` (Linux/Mac) 或 `C:\Windows\System32\drivers\etc\hosts` (Windows) 里面有没有写死。
    
3. **Local DNS 缓存**：如果有，直接返回。
    
4. **Local DNS 递归/迭代解析**：(如上文所述，问根、问TLD、问权限)。
    
5. **ARP 协议**：拿到 IP 后，还需要用 ARP 获取下一跳的 MAC 地址才能发包（这是网络层/链路层的事了）。

### 六、 常见考题陷阱 (Self-Check)

1. **问：DNS 使用什么端口？**
    
    - 答：53。
        
2. **问：本地域名服务器向根域名服务器查询时，通常采用什么方式？**
    
    - 答：迭代查询（避免根服务器压力过大）。
        
3. **问：为了提高可靠性，DNS 使用了什么技术？**
    
    - 答：主从服务器复制（Replication）和 分布式集群。
        
4. **问：什么命令可以查看 DNS 解析过程？**
    
    - 答：`nslookup` (简单) 或 `dig +trace` (详细，Linux/Mac下推荐)。
