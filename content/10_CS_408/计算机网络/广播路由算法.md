## 分类
### 1. 泛洪 (Flooding) —— 最简单粗暴

这是广播的最基础形式，也是所有其他算法想要优化的对象。

- **原理**：路由器从某个接口收到一个包，提取出来，向**除了接收接口之外的所有其他接口**转发出去。
    
- **问题**：
    
    - **广播风暴**：如果网络有环路，数据包会无限转圈，直到链路拥塞挂掉。
        
    - **极度浪费**：一个节点会从多个邻居收到一模一样的包。
        
- **改进版（受控泛洪）**：
    
    - **序号控制 (Sequence Number)**：源节点给每个广播包打上 `(源IP, 序号)`。每个路由器记录通过的序号列表，如果看到重复的序号，直接丢弃，不转发。
        
    - **跳数控制 (TTL)**：设置生存时间，跳数归零就丢弃。
        

### 2. 多目的地路由 (Multi-destination Routing) —— 给包贴满标签

- **原理**：发送方在数据包的头部放一个**目的地列表**（比如包含网络里所有路由器的 IP）。
    
- **转发**：路由器收到包后，根据路由表判断：
    
    - 如果要把包发给列表里的某些人，需要走接口 A，就把这些人的 IP 放到一个新包里，从接口 A 发出去。
        
    - 如果要给另一些人，需要走接口 B，就再分出一个包从接口 B 发出去。
        
- **考点评价**：
    
    - **缺点**：太笨重！如果网络有 1000 个节点，包头得写 1000 个 IP 地址，还没发数据呢，包头就把带宽占满了。只适合极小型的网络。
        

### 3. 生成树 / 汇集树 (Spanning Tree / Sink Tree) —— 理想状态

这就是你刚才做题遇到的算法 **(b)**。

- **原理**：它是泛洪的终极进化版。通过数学方法在图中画出一棵树，覆盖所有点且没环。广播包只在树枝上传播。
    
- **考点评价**：
    
    - **优点**：**带宽利用率最高**（没有废包）。
        
    - **缺点**：**维护困难**。需要全网路由器对拓扑结构有完全一致的认知（比如运行 STP 协议）。如果网络经常变动，树就得经常重修，开销很大。
        

### 4. 逆向路径转发 (RPF) —— 聪明的近似

这就是你刚才做题遇到的算法 **(a)**。

- **地位**：它是对“泛洪”的改良，试图在**不需要全网构建生成树**的前提下，达到接近生成树的效果。
    
- **考点评价**：它是**现实中应用最广**的组播/广播基础逻辑（比如在组播路由协议 PIM-DM 中就用到了 RPF 检查）。
## 详解
### 一、 逆向路径转发 (Reverse Path Forwarding, RPF)

公式：$Total = \text{Degree}(Source) + \sum (\text{Degree}(Node_i) - 1)$

**一句话核心**：“我不关心你去哪（反正你要去所有人那），我只关心你**从哪来**。如果你不是从‘正道’来的，我就把你丢掉。”

#### 1. 为什么要搞这个算法？

最笨的广播是**泛洪 (Flooding)**：收到包就向所有邻居转发。

- **后果**：A 发给 B，B 发给 A，A 又发给 B……这就是“广播风暴”，网络瞬间瘫痪。
    
- **改进**：RPF 就是为了在不记录复杂状态（如“我转发过这个包没？”）的情况下，有效地抑制循环。
    

#### 2. 算法逻辑（详细步骤）

当路由器收到一个源地址为 $S$ 的广播包时，它会进行一次“灵魂拷问” ：

1. **查路由表**：路由器查看自己的路由表，假装自己要**给源 S 发送数据**。
    
2. **判断接口**：去往源 $S$ 的**最佳路径（最短路径）** 是哪个接口？
    
    - 假设最佳接口是 Interface 0。
        
3. **比对**：这个刚收到的广播包，是从 Interface 0 进来的吗？
    
    - **✅ 是 (Valid)**：说明这个包是沿着最短路径从源头飞过来的，是“正版”的第一手消息。
        
        - **动作**：接收它，并向**除了** Interface 0 以外的所有接口转发。
            
    - **❌ 否 (Invalid)**：说明这个包绕远路了，或者是别的路由器转圈转过来的“二手/三手”消息。
        
        - **动作**：直接**丢弃**，不转发。

在你的题目图 (a) 中，假设源是 B。

- **节点 D** 有很多邻居（A, C, G, H）。
    
- 在汇集树（最短路径树）上，B -> A -> D 是最短路径（假设每条线权重一样）。
    
- **情景一**：D 从 **A** 收到了 B 的广播包。
    
    - D 查路由表：去 B 最近的路就是走 A。
        
    - 判断：包从 A 来，匹配成功！
        
    - 结果：D 转发给 C, G, H。
        
- **情景二**：D 从 **C** 收到了 B 的广播包（因为 C 也是 B 的邻居，C 也会转发）。
    
    - D 查路由表：去 B 最近的路是走 A，不是走 C。
        
    - 判断：包从 C 来，这是绕路包！
        
    - 结果：D **丢弃**该包。
        

**RPF 的优缺点：**

- **优点**：不需要路由器记忆“我看过这个包没有”，只需要利用现成的单播路由表，计算简单，无环路。
    
- **缺点**：虽然没有环路，但还是有**浪费**。比如上面情景二，C 发给 D 的那个包，占用了链路带宽，最后却被 D 扔了。这就是为什么题目答案是 38（很多包被扔了）而不是 14。

### 二、 汇集树 / 生成树 (Sink Tree / Spanning Tree)

**一句话核心**：“为了不迷路，我们先修好专门的‘广播高速公路’。所有数据包**只准**在树干上跑，不准走小路。”

#### 1. 概念解析

在图论里，包含图中所有节点且没有环路的子图叫“树”。

- **汇集树 (Sink Tree)**：通常指从所有节点指向同一个目的地（汇集点）的最短路径集合。
    
- **广播生成树**：反过来，从源点出发，沿着最短路径到达所有节点形成的树。
    

在你的题目中，图 (b) 就是以 B 为根的**广播生成树**。

#### 2. 算法逻辑

这个算法要求网络中必须**预先建立**好这棵树（这通常通过生成树协议 [[STP]] 或者链路状态路由算法计算出来）。

当路由器收到广播包时：

1. **判断链路**：这个包是来自汇集树上的“树枝”吗？
    
2. **转发决策**：我只需要把包转发给汇集树上连接的**其他树枝**。
    
    - 那些不在树上的连线（图 b 中被删掉的线），根本不会发送数据包。
        

#### 3. 为什么它是“完美”的？

- **无环路**：树本身就没有环，所以物理上杜绝了死循环。
    
- **无浪费**：每个节点都恰好只有一个“父亲”给它发包。N 个节点的树，永远只有 N-1 条边。数据包刚好走过这 N-1 条边，覆盖所有人，一次不多，一次不少。
    

所以题目答案是 14 (15个节点 - 1)。

## 广播路由算法对比：RPF vs 汇集树

| 特性 | 逆向路径转发 (RPF) | 汇集树 (Sink Tree) |
| :--- | :--- | :--- |
| **核心逻辑** | **校验来源**：只转发从“回源最短路径”发来的包。 | **预先铺路**：只沿预先计算好的“树结构”转发。 |
| **前置条件** | 需要路由器有单播路由表。 | 需要全网知道生成树结构 (计算开销大)。 |
| **转发效率** | **中等**。虽然没有死循环，但会产生重复包（收到非最优路径的包会丢弃，但带宽已消耗）。 | **完美**。每个链路只传一次，总包数最少 ($N-1$)。 |
| **鲁棒性** | 好。单播路由表变了，RPF 自动跟着变。 | 差。网络拓扑一变，整棵树要重新计算。 |
| **现实应用** | **组播 (Multicast)** 中常用（因为它不需要维护全局树状态，只依赖本地路由表）。 | 理论最优，或用于特定的小型网络/生成树协议(STP)。 |
