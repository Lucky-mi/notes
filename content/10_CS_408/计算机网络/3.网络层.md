## IP与MAC
#### 1. 为什么 IP 地址“方便”了？（IP vs MAC）

- **MAC 地址（物理地址/平坦地址）：**
    
    - MAC 是**身份证号**，全球唯一，但它是**杂乱无章**的（Flat Addressing）。你无法通过 MAC 地址判断这台机器是在北京还是在纽约。
        
    - 如果全球路由器只用 MAC 寻址，路由表要有几十亿行（每台设备一行），路由器内存瞬间爆炸，查询速度极慢。
        
- **IP 地址（逻辑地址/层级地址）：**
    
    - IP 是**邮政地址**（如：中国-北京市-海淀区...）。它具有**层级结构（Hierarchical）**。
        
    - **方便之处（关键点）：路由聚合（Route Aggregation/CIDR）**。
        
    - 路由器不需要知道“北师大某台特定电脑”在哪，它只需要知道“172.16.x.x 的包往北师大扔”就行了。一条路由条目可以代表成千上万台主机。这就是 IP 存在的最大意义——**可扩展性**。
        

#### 2. 两者如何协作？

- **IP** 负责**宏观导航**（End-to-End）：从源主机到目的主机，IP 头部几乎不变（TTL 等除外）。
    
- **MAC** 负责**微观跳步**（Hop-by-Hop）：数据包在每一跳（路由器到路由器）之间传输时，MAC 帧头是不断被剥离和重新封装的。

### 一、 IP 数据报格式 (The Header)

这是你必须刻在脑子里的结构，因为所有关于“分片”、“校验和”、“路由转发”的题目都基于此。

**标准长度**：20 字节（固定部分） + 可变部分（很少用）。

#### 1. 结构图解 

|**字段 (位宽)**|**名称**|**核心作用与考点**|
|---|---|---|
|**版本 (4)**|Version|指明是 IPv4 (值为4) 还是 IPv6 (值为6)。|
|**首部长度 (4)**|**IHL**|**重要！** 单位是 **4 字节**。最小值是 5 (即 $5 \times 4 = 20$ 字节)。最大值是 15 (60 字节)。|
|**区分服务 (8)**|TOS|以前叫服务类型，现在用于 QoS (服务质量)，考研基本不考。|
|**总长度 (16)**|Total Length|**首部 + 数据**的总长度。单位是字节。最大 $2^{16}-1 = 65535$ 字节。|
|**标识 (16)**|**Identification**|同一个 IP 数据报的所有分片，这个值必须相同。|
|**标志 (3)**|**Flags**|只有 2 位有意义：<br><br>  <br><br>1. **MF** (More Fragment): 1=后面还有分片; 0=这是最后一个。<br><br>  <br><br>2. **DF** (Don't Fragment): 1=禁止分片。|
|**片偏移 (13)**|**Fragment Offset**|**死穴考点！** 指明该分片在原数据中的位置。**单位是 8 字节**。|
|**生存时间 (8)**|**TTL**|每经过一个路由器 **-1**。减为 0 时丢弃并发送 ICMP 超时。防止环路。|
|**协议 (8)**|Protocol|指出数据部分是什么协议。<br><br>  <br><br>**6 = TCP**, **17 = UDP**, **1 = ICMP** (必背)。|
|**首部校验和 (16)**|Checksum|**只校验首部**，不校验数据部分（数据由 TCP/UDP 自己验）。|
|**源 IP (32)**|Source IP|发送方 IP 地址。|
|**目的 IP (32)**|Dest IP|接收方 IP 地址。|

> **考研避坑指南：**
> 
> - **首部长度单位**：**4 字节**（32位）。如果填 5，代表 $5 \times 4 = 20$ 字节。
>     
> - **片偏移单位**：**8 字节**（64位）。计算时要除以 8。
>     
> - **总长度单位**：**1 字节**。
>

### 二、 IP 分片 (Fragmentation)

当 IP 数据报长度超过链路层的 **MTU (最大传输单元)** 时，必须切碎传输。

#### 1. 核心概念

- **MTU**：以太网通常是 **1500 字节**。
    
- **谁来分片？** 源主机或路径上的路由器。
    
- **谁来重组？** **只在目的主机重组**（中间路由器只管分，不管合，为了效率）。
    

#### 2. 三大关键字段配合

假设原数据报总长度 $L$，数据部分长度 $D$。

1. **标识 (ID)**：所有切片复制原 ID。
    
2. **标志 (MF)**：除了最后一片 MF=0，前面所有片 MF=1。
    
3. **片偏移 (Offset)**：
    
    - 第 1 片：0
        
    - 第 2 片：第 1 片的数据长度 / 8
        
    - 第 3 片：(第 1 片 + 第 2 片的数据长度) / 8
        

> 计算题核心规则：
> 
> 每一片的数据部分长度（除最后一片外），必须是 8 的倍数。

### 三、 IP 编址与子网 (Subnetting)

#### 1. 分类编址 (Classful - 已过时但要懂)

- **A类**：`0` 开头 (1-126)。网络号 8 位。
    
- **B类**：`10` 开头 (128-191)。网络号 16 位。
    
- **C类**：`110` 开头 (192-223)。网络号 24 位。
    
- **D类**：`1110` 开头 (多播)。
    
- **E类**：`1111` 开头 (保留)。
    

> **特殊地址 (不能分配给主机)：**
> 
> - **127.x.x.x**：环回地址 (Loopback)。
>     
> - **主机号全 0**：本网络 (Network Address)。
>     
> - **主机号全 1**：本网络的广播地址 (Broadcast Address)。
>     
> - **0.0.0.0**：本网范围内的主机 (DHCP启动时用)。
>     
> - **255.255.255.255**：受限广播地址。
>     

#### 2. 私有 IP 地址 (Private IP) —— NAT 专用

这些地址在互联网上不路由，只能在局域网内部用。

- **A类**：`10.0.0.0` ~ `10.255.255.255`
    
- **B类**：`172.16.0.0` ~ `172.31.255.255`
    
- **C类**：`192.168.0.0` ~ `192.168.255.255`
    

#### 3. [[CIDR]] (无分类域间路由) —— 现在的考点

记法：`IP地址 / 网络前缀长度` (例如 `192.168.1.0/24`)

**CIDR 的三大法宝计算：**

1. **子网掩码 (Subnet Mask)**：前缀个 1，后面全是 0。
    
    - `/24` -> `255.255.255.0`
        
2. **网络地址** = `IP 地址` **AND** `子网掩码`
    
3. **广播地址** = `网络地址` **OR** `(子网掩码取反)` (即把主机位全变 1)
    

#### 4. 路由聚合 (Supernetting / Route Aggregation)

当路由器要把多个小网段合并成一个大网段写进路由表时，使用 **“最长公共前缀”**。

- _例子_：`192.168.1.0/24` 和 `192.168.2.0/24` 的公共部分，聚合后可能变成 `192.168.0.0/22`。

### 四、 配套协议 (The Helpers)

#### 1.[[NAT]] (网络地址转换)

- **解决什么**：IPv4 地址不够用。
    
- **原理**：
    
    - 内网主机用私有 IP。
        
    - 路由器有一个 **NAT 转换表**：`{私有IP : 端口} <-> {公网IP : 新端口}`。
        
    - 对外完全屏蔽了内部网络结构。
        

#### 2. [[ARP]] (地址解析协议)

- **作用**：**IP $\to$ MAC**。
    
- **层级**：介于网络层和链路层之间（考研通常归为网络层）。
    
- **流程**：
    
    1. 查 ARP 缓存。
        
    2. 没找到 $\to$ 发送 **ARP 请求 (广播 FF-FF...)**：“谁是 192.168.1.1？”
        
    3. 目标主机收到 $\to$ 发送 **ARP 响应 (单播)**：“我是，我的 MAC 是 xx-xx...”。
        
    4. 写入缓存。
        
- **注意**：ARP 只能解析**本局域网**内的 IP。如果是外网 IP，ARP 解析的是**默认网关（路由器）**的 MAC。
    

#### 3. [[ICMP]] (网际控制报文协议)

- **作用**：IP 协议的“报错员”和“探路者”。
    
- **封装**：ICMP 报文是装在 **IP 数据报的数据部分** 里的。
    
- **两大类**：
    
    1. **差错报告报文**：
        
        - 终点不可达 (Host Unreachable)
            
        - 时间超过 (Time Exceeded) -> **TTL=0 时发，Traceroute 利用这个原理。**
            
        - 参数问题
            
        - 改变路由 (Redirect)
            
    2. **询问报文**：
        
        - 回送请求/回答 -> **Ping 利用这个原理。**
            

#### 4. [[DHCP]] (动态主机配置协议)

- **作用**：自动给电脑分 IP、掩码、网关、DNS。
    
- **层级**：**应用层**协议 (基于 **UDP**)。
    
- **流程 (DORA)**：
    
    1. **D**iscover (发现)：主机广播“有没有 DHCP 服务器？”
        
    2. **O**ffer (提供)：服务器回应“我有这个 IP，你要吗？”
        
    3. **R**equest (请求)：主机说“我要用这个 IP。”
        
    4. **A**ck (确认)：服务器确认“好，归你了。”

## 路由选择协议

#### 内部网关协议
- **范围：** 运行在**同一个自治系统 (AS)** 内部的路由协议。
- **目标：** 在 AS 内部尽快找到去往各个网段的最佳路径，实现全网互通。
- **常见协议：** RIP (距离矢量), OSPF (链路状态), IS-IS, EIGRP (思科私有)
[[RIP]]：基于距离向量的路由选择协议
**RIP 知识点 (补漏)**
###### 1. 核心特征
- **“谣言”协议：** 路由器只相信邻居告诉它的信息，自己不验证。
    
- **好消息传得快，坏消息传得慢：** 这是 RIP 最大的缺陷，容易产生路由环路（Count-to-Infinity）。
###### 2. 只有 RIP 关心的防环三板斧

如果考题问到以下名词，**一定是在考 RIP**：

- **水平分割 (Split Horizon)：** 从接口学到的，不回传给该接口。
    
- **毒性逆转 (Poison Reverse)：** 从接口学到的，设为 16 跳回传给该接口。
    
- **抑制计时器 (Hold-down Timer)：** 听到坏消息，先冷静一会儿不信谣。

###### 3. 版本区别 (RIPv1 vs RIPv2)

- **RIPv1：** 有类路由 (Classful)，广播更新，**不支持 VLSM** (子网掩码)，不安全。
    
- **RIPv2：** 无类路由 (Classless)，组播更新 (224.0.0.9)，**支持 VLSM**，支持认证。
    
    - _考研坑点：_ OSPF 默认支持 VLSM，RIP 只有 v2 支持。

[[ospf]]：开放最短路径优先，使用链路状态协议
特点：洪泛法，向本自治系统中所有路由器发送信息，发送信息是与本路由器相邻的所有路由器的链路状态。
所有的路由器最终都能建立起一个链路状态数据库（全网的拓扑结构图），且链路数据库是同步的
##### OSPF 知识点 (补漏)

###### 1. 核心特征

- **“地图”协议：** 每个人都拿着一样的地图 (LSDB)，自己算路。
    
- **层级结构：** 为了减少计算量，引入了 **区域 (Area)** 概念。
    
    - **Area 0 (骨干区域)：** 必须存在，所有其他区域必须连着它。
        
    - **虚链路 (Virtual Link)：** 如果非骨干区域没连着 Area 0，需要用它“搭桥”。
    
###### 2. 五种报文 (必背)

- **Hello：** 发现邻居。
    
- **DBD：** 数据库目录。
    
- **LSR：** 请求缺少的。
    
- **LSU：** 发送详细信息 (最重要)。
    
- **LSAck：** 确认收到。
    
###### 3. 指定路由器 (DR/BDR)

- **目的：** 在广播网络（如以太网）中减少邻居关系数量，减少泛洪流量。
    
- **选举：** 优先级高 > ID 大。**非抢占**。

| **比较维度**         | **RIP (Routing Information Protocol)**           | **OSPF (Open Shortest Path First)**              |
| ---------------- | ------------------------------------------------ | ------------------------------------------------ |
| **协议类型**         | **距离矢量 (Distance Vector)**                       | **链路状态 (Link State)**                            |
| **核心算法**         | **Bellman-Ford** (贝尔曼-福特)                        | **Dijkstra** (SPF 最短路径优先)                        |
| **网络视野**         | **局部** (只知道邻居的情况，“盲人摸象”)                         | **全局** (拥有全网拓扑图 LSDB，“上帝视角”)                     |
| **度量值 (Metric)** | **跳数 (Hop Count)**<br><br>  <br><br>(每经过一个路由器+1) | **开销 (Cost)**<br><br>  <br><br>(基于带宽，100Mbps/带宽) |
| **最佳路径标准**       | 经过路由器数量最少的路                                      | 带宽最高、延迟最低的路                                      |
| **收敛速度**         | **慢** (存在“坏消息传得慢”问题)                             | **快** (触发更新，拓扑变化秒级响应)                            |
| **最大限制**         | 直径不能超过 **15跳** (16不可达)                           | 无严格限制 (适合大型网络)                                   |
| **交换内容**         | 自己的整个**路由表**                                     | **LSA** (链路状态通告，即“地图碎片”)                         |
| **封装方式**         | **UDP** (端口 520)                                 | **IP** (协议号 89)                                  |
| **更新方式**         | 30秒周期性广播 + 触发更新                                  | 主要是触发更新 + 30分钟周期性泛洪 (保活)                         |
| **适用场景**         | 小型网络，简单拓扑                                        | 中大型网络，复杂拓扑                                       |
| **防环机制**         | 水平分割、毒性逆转、最大跳数                                   | **区域划分** (Area 0)、SPF 算法本身无环                     |
- **封装层级不同：**
    
    - **RIP** 用 UDP (应用层) -> 实际上它是应用层协议，但在考研中通常视为网络层控制协议。
        
    - **OSPF** 用 IP (网络层) -> 协议号 89。
        
    - **BGP** 用 TCP (应用层)。
**R**IP (**U**DP) - **R**U ok? | **O**SPF (**I**P) - **O**I! | **B**GP (**T**CP) - **B**T!
- **收敛 (Convergence) 的理解：**
    
    - 题目如果问“哪个协议会导致路由振荡或长时间不收敛？”，选 **RIP**。
        
    - 题目如果问“哪个协议适合网络拓扑频繁变动的环境？”，选 **OSPF** (因为它收敛快)。
        
- **路由表的来源：**
    
    - RIP 的路由表是**直接学来**的。
        
    - OSPF 的路由表是**拿着地图 (LSDB) 自己算出来**的。

#### 外部网关协议
[[BGP]]:eBGP与iBGP

他俩分工极其明确，缺一不可：

|**维度**|**IGP (OSPF/RIP)**|**BGP**|
|---|---|---|
|**主要任务**|**修路、导航**|**指路、通商**|
|**关注点**|**速度、质量** (带宽、延迟)|**策略、可达性** (经过哪些AS、走哪条线便宜)|
|**作用范围**|**微观** (AS 内部，路由器到路由器)|**宏观** (AS 之间，系统到系统)|
|**数据量**|处理几千条路由 (多了算不过来)|承载 90万+ 路由 (只记路标，不算细节)|
|**关系**|**地基** (提供 TCP 连接的基础)|**上层建筑** (利用 IGP 的路来传数据)|

> **一句话总结：** BGP 决定“要去哪个国家”，IGP 负责“把包裹送到那个国家的航班上”。

**Step 1: 找出口 (IGP)**

- 我的电脑 -> ... (IGP 导航) ... -> 本地边界路由器 (Gateway)
    
- _作用：把数据汇聚到出口。_
    

**Step 2: 找下一站 (BGP + IGP)**

- 本地边界 -> (BGP 决策: 下一跳是中转 AS) -> 中转入口
    
- 中转入口 -> ... (**BGP 指明去出口路由器的方向，IGP 负责具体的跳跃**) ... -> 中转出口
    
- _作用：跨越自治系统。_
    

**Step 3: 找终点 (IGP)**

- 目的 AS 边界 -> ... (IGP 导航) ... -> 最终服务器
    
- _作用：在目的地内部分发。_
