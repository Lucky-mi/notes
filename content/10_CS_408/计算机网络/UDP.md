## 1. UDP 概述 (Overview)

**UDP (User Datagram Protocol，用户数据报协议)** 是传输层两个主要协议之一（另一个是 TCP）。它在 IP 服务之上仅仅增加了很少一点功能：**复用/分用** 和 **差错检测**。

### 1.1 主要特点 

1. **无连接**：
    
    - 发送数据之前**不需要建立连接**。
        
    - 发送结束后也无需释放连接。
        
    - _优势_：减少了开销和发送数据之前的时延。
        
2. **尽最大努力交付 (Best Effort)**：
    
    - **不可靠**：不保证可靠交付。
        
    - 主机不需要维持复杂的连接状态表（如收发缓存、拥塞控制参数等）。
        
3. **面向报文 (Message-Oriented)**：
    
    - UDP 对应用层交下来的报文，**既不合并，也不拆分**，而是保留这些报文的边界。
        
    - _理解_：应用层给 UDP 多长的报文，UDP 就发多长的（加上首部）。因此应用层必须选择合适大小的报文。
        
4. **无拥塞控制**：
    
    - 网络出现的拥塞不会使源主机的发送速率降低。
        
    - _优势_：适合对实时性要求高、允许少量丢包的应用（如 IP 电话、视频会议、直播）。
        
5. **支持多种交互方式**：
    
    - 支持一对一、一对多、多对一、多对多通信。
        
6. **首部开销小**：
    
    - 只有 **8 字节**（相比 TCP 的 20 字节）。

## 2. UDP 报文段首部格式 (Header Format)

UDP 是面向报文的，其结构非常简单。

|**字段名称**|**长度**|**说明**|
|---|---|---|
|**源端口**|2 字节|源端口号。在需要对方回信时选用，不需要时可用全 0。|
|**目的端口**|2 字节|目的端口号。这在终点交付报文时必须使用。|
|**长度**|2 字节|**UDP 用户数据报的总长度**（首部 + 数据）。最小值为 8（仅有首部）。|
|**校验和**|2 字节|检测 UDP 用户数据报在传输中是否有错。**有错就丢弃**。|

> [!NOTE] 考点提示
> 
> 如果接收方 UDP 发现收到的报文段中的目的端口号不正确（即不存在对应于该端口号的应用进程），就丢弃该报文段，并由 ICMP 发送 "端口不可达" 差错报文给发送方。

## 3. UDP 校验和 (Checksum) - ★ 难点与重点

UDP 的校验和计算是 UDP 知识点中最复杂的，也是考研计算题的潜在考点。

### 3.1 伪首部 (Pseudo-Header)

在计算校验和时，要在 UDP 用户数据报之前增加 12 个字节的**伪首部**。

- **作用**：仅仅为了计算校验和，**既不向下传送也不向上提交**。
    
- **包含内容**：源 IP、目的 IP、协议号等，为了检查该报文是否确实是发给本机的。
    

**伪首部结构 (12 字节)：**

1. **源 IP 地址** (4 字节)
    
2. **目的 IP 地址** (4 字节)
    
3. **全 0** (1 字节)
    
4. **协议** (1 字节)：UDP 的协议字段值为 **17**。
    
5. **UDP 长度** (2 字节)：即 UDP 首部中的长度字段。
    

### 3.2 计算步骤 (二进制反码求和)

1. **添加伪首部**。
    
2. **填充**：若 UDP 数据报部分不是偶数个字节，则需填入一个全 0 字节（此时不发送）。
    
3. **求和**：将伪首部 + 首部 + 数据，按 16 位 (2 字节) 为单位进行**二进制反码求和**。
    
4. **取反**：将求和结果取反码，写入校验和字段。
    

> [!IMPORTANT]  关键细节
> - **可选性**：TCP 的校验和是必须的，但 UDP 的校验和是**可选的**。
>     
> - **全 0 处理**：如果不使用校验和，该字段填 `0`。如果计算出的校验和结果恰好为 `0` (全 0)，则填入 `1` (全 1，即 0xFFFF) 以示区别。

## 4. 基于 UDP 的常见应用层协议

考研常考选择题：下列哪个协议是基于 UDP 的？

|**协议**|**名称**|**端口号**|**说明**|
|---|---|---|---|
|**DNS**|域名系统|53|既用 UDP 也用 TCP，但查询通常用 UDP。|
|**DHCP**|动态主机配置协议|67/68|获取 IP 地址等配置。|
|**TFTP**|简单文件传输协议|69|极简的文件传输，无复杂交互。|
|**SNMP**|简单网络管理协议|161|网络设备管理。|
|**RIP**|路由信息协议|520|一种动态路由协议。|
|**NFS**|网络文件系统|2049|通常基于 UDP (也可 TCP)。|

## 5. TCP 与 UDP 的核心对比总结

> 可以直接用这个表格来回答对比类简答题。

|**对比维度**|**UDP**|**TCP**|
|---|---|---|
|**连接**|无连接|面向连接|
|**可靠性**|不可靠 (丢包不重传)|可靠 (重传、排序)|
|**数据边界**|面向报文 (保留边界)|面向字节流 (无边界)|
|**传输效率**|高 (无握手、无确认)|低 (需握手、确认、窗口调整)|
|**拥塞控制**|无 (网络拥塞照样发)|有 (慢开始、拥塞避免等)|
|**首部大小**|8 字节|20 ~ 60 字节|
|**适用场景**|实时音视频、广播/多播|文件传输、网页、邮件|
