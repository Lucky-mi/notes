## 一、 核心概念与定位

- **类型：** **链路状态路由协议 (Link-State Routing Protocol)**。
    
- **算法：** **Dijkstra 最短路径算法 (SPF)**。
    
- **度量值 (Metric)：** **开销 (Cost)**。
    
    - 计算公式：$Cost = \frac{\text{参考带宽}}{\text{接口带宽}}$ （默认参考带宽是 100Mbps）。
        
    - _含义：带宽越大，开销越小，路径越优。_
        
- **封装：** 直接封装在 **IP 数据报** 中，**协议号 89**（不使用 UDP 或 TCP）。
    
- **更新方式：** **触发更新**（变化时发送）+ **周期性刷新**（每30分钟，为了健壮性）。
    
- **组播地址：** 224.0.0.5 (All SPF Routers) 和 224.0.0.6 (All DR/BDR)。

## 二、 工作原理：三张表与四步走

与 RIP “只看下一跳”不同，OSPF 的目标是让每台路由器都拥有一张完整的全网拓扑图。

### 1. 三张核心表 (考点)

1. **邻居表 (Neighbor Table)：** 记录邻居关系（通过 Hello 包建立）。
    
    - _口语理解：_ “我知道谁住在我隔壁。”
        
2. **链路状态数据库 (LSDB - Topology Table)：** 存储所有的 **LSA (链路状态通告)**。这是全网的“地图碎片”集合，同一区域内所有路由器的 LSDB 是**完全一致**的。
    
    - _口语理解：_ “我手里拿着全网的完整拼图。”
        
3. **路由表 (Routing Table)：** 基于 LSDB，用 SPF 算法计算出的最优路径集合。
    
    - _口语理解：_ “经过计算，我知道去哪里走哪条路最快。”
        

### 2. 工作流程

1. **发现邻居：** 发送 Hello 包，建立邻居关系。
    
2. **泛洪 LSA：** 路由器将自己的链路状态（连着谁、带宽多少）生成 LSA，广播给所有人。
    
3. **构建 LSDB：** 收集所有人的 LSA，拼成完整的数据库。
    
4. **计算路由：** 以自己为根，画出一棵**最短路径树 (SPF Tree)**，生成路由表。

## 三、 五种报文类型 (必背!)

考研选择题常考“下面哪个报文用于...？”

|**报文类型**|**名称**|**作用**|
|---|---|---|
|**1. Hello**|问候报文|**发现和维持邻居关系**，选举 DR/BDR。|
|**2. DBD**|数据库描述报文|(Database Description) 发送 LSDB 的**摘要**信息（目录）。|
|**3. LSR**|链路状态请求报文|(Link State Request) 看了目录后，请求自己缺少的详细 LSA。|
|**4. LSU**|链路状态更新报文|(Link State Update) **最重要！** 携带真正的 LSA 信息（回应 LSR 或主动触发）。|
|**5. LSAck**|链路状态确认报文|(Link State Acknowledgment) 确认收到了 LSU，保证传输的**可靠性**。|

> **哈基米小贴士：** 注意！OSPF 不用 TCP，但它需要保证可靠传输，所以它自己设计了 LSAck 机制。

## 四、 核心机制 (大题难点)

### 1. 区域 (Area) 划分

为了解决 LSDB 过大、计算太慢的问题，OSPF 将网络划分为两层结构：

- **骨干区域 (Area 0)：** 核心区域，负责连接其他区域。
    
- **非骨干区域 (Area 1, 2...)：** 普通区域。
    
- **规则：** 所有非骨干区域必须**直接连接**到骨干区域，防止环路。
    
- **设备角色：**
    
    - **IR：** 内部路由器（所有接口在同一区域）。
        
    - **ABR：** **区域边界路由器**（连接 Area 0 和其他区域），负责在区域间传递路由。
        
    - **ASBR：** 自治系统边界路由器（连接 OSPF 和外部协议，如 RIP/BGP）。
        

### 2. DR 和 BDR (指定路由器)

在**广播多路访问网络 (Broadcast Multi-Access)**（例如 Ethernet）中，为了减少邻居关系数量（$n(n-1)/2$）和泛洪流量，需要选个“班长”。

- **DR (Designated Router)：** 指定路由器（班长）。所有路由器只与 DR/BDR 建立“完全邻接关系”，LSA 先发给 DR，由 DR 广播给大家。
    
- **BDR (Backup DR)：** 备份指定路由器（副班长）。DR 挂了它立刻顶上。
    
- **DROther：** 普通路由器。
    
- **选举规则：**
    
    1. 优先级 (Priority) 大的优先（默认是 1，0 表示不参选）。
        
    2. Router ID 大的优先。
        
    
    - **注意：** 选举是非抢占的！一旦 DR 选定，新来的即使 ID 更大也只能当小弟，除非现任 DR 挂了。

## 五、 OSPF 与 RIP 的终极对比 (简答题素材)

|**特性**|**RIP**|**OSPF**|
|---|---|---|
|**协议类型**|距离矢量|链路状态|
|**收敛速度**|慢 (可能数到无穷大)|**快**|
|**度量值**|跳数 (最大 15)|**带宽** (Cost)|
|**防环机制**|水平分割、毒性逆转|**SPF 算法本身无环** (但在区域间可能存在，靠骨干区域防环)|
|**适用规模**|小型网络|中大型网络|
|**层级**|应用层 (UDP)|网络层 (IP)|
|**负载均衡**|只支持等跳数|支持等开销 (Cost 相同)|

疑问：书上说只涉及与相邻链路的联通状态，与整个网络的规模无直接关系，互联网规模大时，比RIP好得多，但是难道不是ospf会存的多一些吗？否则怎么得到全网拓扑图呢？
### 1. 核心矛盾：什么是“只涉及相邻链路”？

书上说“OSPF 只涉及与相邻链路的联通状态”，这句话描述的是 **LSA（链路状态通告）的内容**，而不是路由器最终知道的内容。

- **RIP (距离向量):**
    
    - **它说什么？** “我知道去往全网所有地方的路径和距离（虽然也是听别人说的）。”
        
    - **比喻：** 就像传话游戏。A 告诉 B：“我知道怎么去美国，距离 5 步。” B 告诉 C：“我知道怎么去美国，距离 6 步。” C 其实根本不知道美国的方位，它只知道 B。
        
    - **缺点：** 只要网络规模一大，路由表就很大，每次发包都要把整个路由表发给邻居，带宽浪费严重。
        
- **OSPF (链路状态):**
    
    - **它说什么？** 它**只**说：“我是 A，我的邻居是 B（代价 10）和 C（代价 20）。” —— 这就是书上说的“只涉及相邻链路”。
        
    - **比喻：** 拼图游戏。A 手里只有一块拼图（它自己和邻居），它把这块拼图复印了很多份，发给所有人。
        
    - **结果：** 虽然 A 嘴里只说了它的邻居，但因为**每个人都说了自己的邻居**，大家汇总了所有人的拼图后，就拼出了**完整的全网拓扑图**。
        

### 2. 你的疑问：OSPF 难道不是存得更多吗？

**是的，你是对的。**

- **存储消耗：** OSPF 确实比 RIP 消耗更多的内存。因为它要存一个**LSDB（链路状态数据库）**，也就是那张完整的“地图/拓扑图”。
    
- **计算消耗：** OSPF 收到地图后，要运行 **Dijkstra（迪杰斯特拉）算法** 算出最短路径，这非常消耗 CPU。
    

**那为什么还说它适合大规模网络？**

这里的“适合”不是指“省内存”，而是指**收敛快、无环路、带宽占用更合理**。

1. **更新量小（带宽优势）：**
    
    - RIP：哪怕网络只有一点点变化，也要周期性地把**整个路由表**发给邻居。网络越大，路由表越大，轰炸越猛。
        
    - OSPF：当网络稳定时，几乎不发包（只有 Hello 包）。当网络变化时，只把**变化的那一条链路状态**（比如 A 和 B 断了）洪泛出去。这相对整个网络的规模来说，流量微乎其微。
        
2. **避免“坏消息传得慢”（收敛优势）：**
    
    - RIP 容易产生“计数到无穷”的问题，网络一大，出故障时收敛极慢。
        
    - OSPF 因为手里有全网地图，一旦链路断了，立刻就能重新计算出新路径，不会瞎传话。
