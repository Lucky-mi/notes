## 一、 协议定位与基本概念

BGP (Border Gateway Protocol) 是互联网的“外交官”，用于在不同的 **自治系统 (AS)** 之间交换路由信息。

| **维度**   | **内容**                 | **备注 (408 考点)**               |
| -------- | ---------------------- | ----------------------------- |
| **协议类型** | **外部网关协议 (EGP)**       | 不同于 OSPF/RIP (IGP)            |
| **算法类型** | **路径矢量 (Path Vector)** | 这种算法记录经过的 AS 序列，而不是单纯的跳数      |
| **工作层级** | **应用层**                | 封装在 TCP 报文中                   |
| **端口号**  | **TCP 179**            | 提供可靠的路由传输，无需像 OSPF 那样自己设计确认机制 |
| **更新方式** | **触发更新**               | 只在路由变化时发送增量更新，不定期泛洪           |

> **💡 核心逻辑：** BGP 的目的不是为了“快”（像 OSPF 计算最短路径），而是为了 **“可控”** （策略选择）和**“能装”**（承载全球路由表）。

---

## 二、 核心机制：eBGP 与 iBGP

BGP 根据运行的邻居位置不同，分为两种模式。这是 BGP 最容易混淆的地方。

### 1. eBGP (External BGP)

- **定义：** 运行在**不同 AS 之间**的 BGP。
    
- **作用：** 在自治系统之间传递路由（“国与国建交”）。
    
- **物理要求：** 通常要求物理直连（TTL 默认 1）。
    
- **防环机制：** **AS_PATH 属性**。如果收到的路由 AS_PATH 中包含自己的 AS 号，直接丢弃。
    

### 2. iBGP (Internal BGP)

- **定义：** 运行在**同一个 AS 内部**的 BGP。
    
- **作用：** 在 AS 内部传递从外部学来的路由（“国内传达外交文件”）。
    
    - _为什么要 iBGP？_ 为了让 AS 内部的非边界路由器也能知道如何去往外部网络，且不需要重分发到 IGP 中导致 IGP 崩溃。
        
- **物理要求：** 不需要物理直连，只要 TCP 能通（IGP 可达）即可。
    
- **防环机制：** **水平分割原则**（见下文）。
    

---

## 三、 BGP 的四大报文 (Packet Types)

考研选择题高频考点。BGP 头部通用，依靠 Type 字段区分。

1. **OPEN 报文**
    
    - **作用：** 建立邻居关系（类似 Hello，但只发一次）。
        
    - **内容：** 包含版本号 (v4)、AS 号、Hold Time、BGP Identifier (Router ID)。
        
2. **UPDATE 报文** (最核心)
    
    - **作用：** 撤销不可达路由、发布新路由。
        
    - **特点：** 一个报文可以撤销多条路由，但只能发布一组具有相同属性的路由。
        
3. **KEEPALIVE 报文**
    
    - **作用：** 维持邻居关系（心跳）。
        
    - **频率：** 周期性发送（通常 60s），告诉对方“我还活着”。确认 OPEN 报文也用它。
        
4. **NOTIFICATION 报文**
    
    - **作用：** 报错。
        
    - **后果：** 一旦发送，立即关闭 TCP 连接。

## 四、 核心路径属性 (Path Attributes)

BGP 不看“度量值”，看“属性”。这是选路的关键。

### 1. AS-PATH (必考)

- **定义：** 记录路由经过的所有 AS 编号的列表（例如：`AS100, AS200, AS300`）。
    
- **作用：**
    
    1. **防环：** 看到自己 AS 号就丢弃。
        
    2. **选路：** **AS_PATH 越短越优先**（类似 RIP 跳数，但是是以 AS 为单位）。

#### 一、 彻底搞懂 AS-PATH 的“盖戳”过程

假设：

- **目的前缀（Prefix）：** `1.1.1.0/24`（这代表**“正宗麻辣烫”**）。
    
- **拥有者：** 它属于 **AS 100**（四川）。
    
- **中间商：** **AS 200**（湖北）。
    
- **接收者：** **AS 300**（北京，也就是你）。
    

#### 1. 谁开始转发？从“前缀”的老家开始！

一切始于 AS 100。AS 100 说：“我有麻辣烫（`1.1.1.0/24`）！”

#### 2. 具体的传播过程（注意看 AS-PATH 怎么变长）：

- **第一步：AS 100 -> AS 200**
    
    - AS 100 的边界路由器把这条路由发给 AS 200。
        
    - 在发出去的一瞬间，AS 100 把自己的名字写进 AS-PATH。
        
    - **此时 AS-PATH：** `[100]`
        
    - **含义：** “想吃麻辣烫，来 AS 100。”
        
- **第二步：AS 200 -> AS 300 (你)**
    
    - AS 200 收到后，告诉 AS 300：“嘿，我也能搞到麻辣烫，但我得去 AS 100 拿。”
        
    - AS 200 把这条路由转发给 AS 300 时，把自己的名字**加在最前面（Prepend）**。
        
    - **此时 AS-PATH：** `[200, 100]`
        
    - **含义：** “经过我 AS 200，再去 AS 100，就能吃到麻辣烫。”
        
- **第三步：你在 AS 300 收到路由**
    
    - 你看到的路由条目是：
        
        - **前缀 (Prefix)：** `1.1.1.0/24` (终点)
            
        - **AS-PATH：** `200, 100` (路径)
            
        - **下一跳 (Next Hop)：** AS 200 的边界路由器的 IP (比如 `2.2.2.2`)。
            

#### 3. 你的问题解答

- **是从目的前缀开始转发吗？** 是的！路由信息是从“目的地”发出来的，向外扩散。
    
- **前缀就是终点？** 对！前缀（Prefix）就是我们要去的那个 IP 网段。
    
- **下一跳是哪？**
    
    - 对于 AS 300 里的你来说，下一跳是 **AS 200** 的那个接口 IP。
        
    - **注意：** AS-PATH 告诉你“宏观路线”（要经过 200 和 100），而下一跳告诉你“微观动作”（把包发给谁）。

### 2. NEXT-HOP (下一跳) - 坑点！

- **规则 1 (eBGP)：** A 发给 eBGP 邻居 B，下一跳自动改为 A 自己。
    
- **规则 2 (iBGP)：** B 发给 iBGP 邻居 C，**下一跳默认不变**（还是指向外部的 A）。
    
    - _问题：_ C 如果不知道怎么去 A（路由黑洞前兆），就会丢包。
        
    - _解决：_ 在 B 上配置 `next-hop-self`，强行把下一跳改成 B 自己。
        

### 3. ORIGIN (起源)

- 标记路由是怎么来的：
    
    - **IGP (i)：** 始发于 AS 内部（最优先）。
        
    - **EGP (e)：** 始发于 EGP 协议（已淘汰）。
        
    - **Incomplete (?)：** 引入的，如重分发（优先级最低）。

## 五、 BGP 的两大防环死穴 (难点攻克)

### 1. eBGP 防环：靠 AS_PATH

很简单，就是检查“身份证”。

### 2. iBGP 防环：靠“水平分割” (Split Horizon)

- **原则：** **从 iBGP 邻居学到的路由，绝不传给其他的 iBGP 邻居。**
    
- **原因：** AS 内部传递时不修改 AS_PATH，无法通过属性防环，只能禁止“二传”。
    
- **后果：** **iBGP 全互连 (Full Mesh)**。
    
    - AS 内部所有运行 BGP 的路由器必须两两建立 TCP 连接。
        
    - _如果节点多怎么办？_ 工程上使用 **路由反射器 (Route Reflector)** 或 **联盟 (Confederation)** 解决（408 只要知道名字即可）。

## 六、 路由黑洞 (Routing Black Hole)

- **现象：** 控制平面（路由表）通了，数据平面（Ping）不通。
    
- **原因：** AS 内部的中间路由器（未运行 BGP）没有外网路由。
    
- **解决：** [[MPLS]]（多协议标签交换）是当前主流解法。
    

---
**BGP 选路 "面试" 流程表 (从上到下，一票否决)：**

1. **权重 (Weight)**：我自己偏心的 (本地有效)。 -> **越高越好**
    
2. **本地优先级 (Local_Pref)**：全公司商量的 (AS内有效)。 -> **越高越好**
    
3. **AS-PATH**：护照上的签证章数量。 -> **越短越好**
    
4. **起源 (Origin)**：血统纯正度 (i > e > ?)。 -> **IGP 最牛**
    
5. **MED**：邻居的建议。 -> **越小越好**
    
6. **来源**：eBGP > iBGP。 -> **一手优于二手**
    
7. **IGP 开销**：热土豆原则。 -> **离我越近越好**

## 📝 哈基米划重点 (408 避坑指南)

1. **BGP 是应用层协议**，别因为它管路由就以为它是网络层。它是寄生在 TCP 上的软件。
    
2. **OSPF vs BGP：**
    
    - OSPF：我画地图，我找最短路，我信自己算的。
        
    - BGP：我听传闻，我选策略，我信邻居给的属性。
        
3. **连接状态：** BGP 邻居建立成功的状态是 **ESTABLISHED**。
    
4. **路由表大小：** 只有 BGP 能承载 90万+ 路由，IGP 几千条就卡死了，所以 IGP 只能给 BGP “打辅助”。
有iBGP还要有IGP的原因：
### 原因一：建立 TCP 连接的前提 (地基)

**BGP 是运行在 TCP 之上的（端口 179）。**

- **场景：** 假设在一个 AS 内部，路由器 A 和 路由器 C 想建立 iBGP 邻居关系。它们中间隔着路由器 B（A — B — C）。
    
- **问题：** BGP 建立邻居时，A 需要向 C 的 IP 地址发起 TCP 连接。
    
- **死结：** 如果没有 IGP（比如 OSPF），A 的路由表里根本就没有 C 的 IP 地址！A 连 C 在哪里都不知道，怎么发 TCP 握手包？
    
- **解决：** **必须先运行 IGP**，让 A 学习到 C 的 IP 地址（通常是 Loopback 接口地址），确保网络**联通**。只有路通了，TCP 连接才能建立，BGP 协议才能开始跑。
    

> **结论：** IGP 为 iBGP 提供了底层的**网络可达性 (Reachability)**。

---

### 原因二：下一跳的递归查询 (Recursive Lookup)

这是考研最常考的机制！请务必看懂这个例子。

**1. BGP 路由的特点** BGP 传递的路由信息，通常只告诉你 **“下一跳（Next Hop）是谁”** ，而不会告诉你 **“怎么去下一跳”**。

- **eBGP 告诉 iBGP：** “要去访问 `8.8.8.8`（谷歌），请把包发给边界路由器 `Router D`。”
    
- **路由器 A 的困惑：** “好的，我知道要去 `Router D`。但是……**Router D 在哪？我该从哪个接口出去才能找到 D？**”
    

**2. IGP 的作用** 这时候，路由器 A 必须查第二次路由表（这就是**递归查询**）：

1. **查 BGP 表：** 去 `8.8.8.8` -> 下一跳是 `Router D`。
    
2. **查 IGP 表 (OSPF)：** 去 `Router D` -> 下一跳是直连的 `Router B`，从 `eth0` 接口出去。
    

> **结论：** 如果没有 IGP，你的路由器只知道“目标负责人是谁”，但不知道“怎么走到负责人的办公室”。IGP 负责导航到 BGP 的下一跳。

---

### 原因三：iBGP 不具备拓扑感知能力

你可能会想：“那为什么不让 iBGP 自己把地图画出来，直接取代 OSPF 呢？”

- **设计目的不同：**
    
    - **IGP (OSPF)：** 专为**计算拓扑**设计。它知道哪里断了、哪里堵了，反应极快（毫秒级）。它的任务是**发现网络结构**。
        
    - **BGP：** 专为**承载海量路由**设计。它不关心网络具体的物理连线，它只关心“策略”和“路标”。
        
- **如果强行用 iBGP 取代 IGP：** BGP 也是基于“下一跳”的，如果它自己还要负责发现直连邻居、计算链路开销、画拓扑图，那它就会变得无比臃肿，根本跑不动全球几十万条路由。

>在 AS 内部，路由器 A 和 C 建立了 iBGP 邻居，中间经过了路由器 B (A-B-C)。如果 B 没有运行 BGP，只运行了 OSPF。 当 A 想发数据给外网，数据包传到中间的 B 时，会发生什么？
# BGP 路由黑洞问题

### 1. 为什么会丢包？（控制层面 vs 数据层面）

这个问题的核心在于：**路由条目（地图）能“飞”过去，但数据包（车）得一步步“开”过去。**

- **控制层面 (Control Plane) - 传话：**
    
    - A 和 C 建立了 **iBGP** 连接（基于 TCP）。
        
    - A 通过 TCP 告诉 C：“去往外网 X 的路我知道。”
        
    - 这就像 A 和 C 打了个电话，中间的 B **根本听不到**（因为 B 没有运行 BGP，它不处理 BGP 报文，只是像搬运工一样转发 TCP 包）。
        
    - **结果：** A 和 C 的路由表里都有了去 X 的路由。
        
- **数据层面 (Data Plane) - 转发：**
    
    - 现在，C 收到了一个真正要去往 X 的数据包。
        
    - C 查路由表：去 X 的下一跳是 A。
        
    - C 把包扔给必经之路上的 **B**。
        
    - **悲剧发生：** B 收到包，看一眼目的 IP 地址（是外网 X）。
        
    - B 查自己的路由表（只有 OSPF）：**“我是谁？我在哪？我的 OSPF 表里只有公司内部的地址，没有外网 X 啊！”**
        
    - **结局：** B 认为目标不可达，直接**丢弃 (Drop)**，并返回一个 ICMP Destination Unreachable。
        

### 2. 怎么解决这个问题？(408 考点扩展)

既然 B 不认识路，怎么解决？考研中通常涉及以下几种思路：

1. **物理全互连（笨办法）：**
    
    - 让 B 也运行 BGP。这样 B 就也能学到外网路由了。
        
    - _缺点：_ 路由器 B 这种中间设备通常性能较弱，扛不住全球几十万条路由表，会撑爆内存。
        
2. **重分发 (Redistribution)（极其危险）：**
    
    - 让边界路由器 A 把 BGP 路由全部“倒进” OSPF 里，强行教给 B。
        
    - _后果：_ OSPF 会瞬间崩溃，因为它处理不了这么多路由。
        
3. **MPLS (多协议标签交换)（现在的主流，408 了解即可）：**
    
    - C 给数据包贴个标签（Label），告诉 B：“别管 IP 是啥，你只管把这个标签的包扔给 A 就行。”
        
    - B 只要看标签转发，不需要查复杂的路由表。这就相当于给 B 建了一条**隧道**。

### 3. 一个古老的考点：BGP 同步规则 (Synchronization)

在早期的 BGP 版本（以及旧版教材）中，为了防止黑洞，有一条**同步规则**：

> **“如果一个 iBGP 路由器（比如 C）从 iBGP 邻居（比如 A）学到了一条路由，它不能使用、也不能告诉 eBGP 邻居，除非……它也能从 IGP (OSPF) 里学到这条路由。”**

- **人话翻译：** “除非中间的 B（通过 OSPF）也知道怎么走，否则我 C 就算知道了也不敢走，因为怕 B 丢包。”
    
- **现状：** 现代网络（包括现在的思科/华为设备）默认都**关闭**了这个同步规则，因为我们现在都用 MPLS 隧道来解决黑洞了。
