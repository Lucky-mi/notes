## 实验第一部分：ICMP 与 Ping (Q1-Q5)

**实验操作：** 使用 Windows 命令行工具执行 `ping -n 10 www.ust.hk`，并使用 Wireshark 捕获数据包。
### 数据包分析与问答

根据 Wireshark 捕获的第 102 号（请求）和 103 号（回复）数据包，回答以下问题：
#### **Q1. What is the IP address of your host?**
**(你的主机 IP 地址是什么？)**
- **答案：** `172.22.129.81`
- **分析：** 在 Wireshark 列表中查看第 102 行 "Echo (ping) request" 数据包的 **Source**（源地址）列。
#### **Q2. What is the IP address of the destination host?**
**(目标主机的 IP 地址是什么？)**
- **答案：** `143.89.209.9`
- **分析：** 在 Wireshark 列表中查看第 102 行 "Echo (ping) request" 数据包的 **Destination**（目的地址）列。此 IP 对应 `www.ust.hk`。
#### **Q3. Why is it that an ICMP packet does not have source and destination port numbers?**
**(为什么 ICMP 数据包没有源端口和目的端口号？)**
- **答案：** ICMP 协议被设计用于处理**网络层 (Network Layer)** 的控制信息和错误报告，而不是用于应用程序之间的数据传输。
    1. **层级不同：** 端口号 (Port Numbers) 是**传输层 (Transport Layer)**（如 TCP 或 UDP）的概念，用于区分主机上运行的不同进程或应用程序。
    2. **功能不同：** ICMP 直接封装在 IP 数据报中（Protocol 协议号为 1），它的作用是在主机和路由器之间传递网络状况信息（如“主机不可达”或“Echo请求”），不需要通过端口号来定位具体的上层应用程序。
#### **Q4. Examine one of the ping request packets sent by your host.**
**(分析一个由你主机发送的 Ping 请求包)**
- **ICMP Type (类型):** `8` (Echo Request)
- **ICMP Code (代码):** `0`
- **其他包含的字段 (Other fields):**
    - Checksum (校验和)
    - Identifier (标识符) - 用于匹配请求和回复
    - Sequence Number (序列号) - 用于标识包的顺序
- **字段字节大小 (Bytes):**
    - **Checksum:** 2 字节 (16 bits)
    - **Identifier:** 2 字节 (16 bits)
    - **Sequence Number:** 2 字节 (16 bits)
#### **Q5. Examine the corresponding ping reply packet.**
**(分析对应的 Ping 回复包)**
- **ICMP Type (类型):** `0` (Echo Reply)
- **ICMP Code (代码):** `0`
- **其他包含的字段 (Other fields):**
    - Checksum (校验和)
    - Identifier (标识符)
    - Sequence Number (序列号)
- **字段字节大小 (Bytes):**
    - **Checksum:** 2 字节
    - **Identifier:** 2 字节
    - **Sequence Number:** 2 字节
### 实验小结 (Self-Reflection)
在本次实验中，通过观察 Request 和 Reply 的交互，验证了 ICMP 协议的回显机制。
- **遇到的问题：** 初始抓包时未显示 ICMP 数据，后经分析发现是因为开启了 VPN 导致数据包被封装加密。
- **解决方案：** 关闭 VPN 并在 Ping 命令中添加 `-4` 参数强制使用 IPv4，成功抓取到明文 ICMP 数据包。
