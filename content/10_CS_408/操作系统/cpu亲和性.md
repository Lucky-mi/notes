### 一、 什么是 CPU 亲和性？（基本定义）

简单来说，CPU 亲和性就是一种**“调度倾向性”**，即操作系统尽量将一个进程（或线程）保持在同一个 CPU 核心上运行，而不轻易将其迁移到其他核心。

它分为两类：

1. **软亲和性（Soft Affinity）**：
    
    - **行为**：Linux 内核调度器（如 CFS）默认的行为。它会“尽量”让进程留在上次运行的 CPU 上。
        
    - **原因**：如果没有特殊情况（比如某个核实在太闲，或者当前核太忙），调度器不会主动搬动进程。
        
2. **硬亲和性（Hard Affinity）**：
    
    - **行为**：通过编程手段（系统调用）明确指定进程 A 只能在 CPU 0、1、2 上运行。
        
    - **手段**：在 Linux 中使用 `sched_setaffinity()` 函数或 `taskset` 命令。哪怕其他核心（如 CPU 3）完全空闲，内核也绝不会把该进程挪过去。

### 二、 核心驱动力：为什么要搞亲和性？

这是你建立“知识直觉”的核心点：**为了保护缓存（Cache）的“温热度”。**

1. **Cache Locality（缓存局部性）**：
    
    - 进程在 CPU 0 上运行时，其频繁访问的代码、数据、页表项（TLB）都会填满 CPU 0 的 L1/L2 缓存。
        
    - **如果切走**：进程迁移到 CPU 1。CPU 1 的缓存里全是别人的数据（冷启动）。该进程必须重新从内存拉取数据，这会导致数千个时钟周期的延迟。
        
2. **TLB（快表）的保护**：
    
    - 正如我们之前聊到的，进程切换或迁移会导致 TLB 刷新（或者因为进程 ID 不同而失效）。保持在同一个核，能最大限度利用现有的 TLB 映射。
        
3. **NUMA 架构的必然要求**：
    
    - 在现代多路服务器（比如你有两颗物理 CPU 插槽）中，内存是分区的。CPU 0 访问自己旁边的内存（本地内存）比访问 CPU 1 旁边的内存快得多。
        
    - **亲和性直觉**：如果一个进程的内存已经分配在 Node 0 的内存条上，那么将它绑定在 Node 0 的 CPU 上运行，效率是最高的。

### 三、 内核是如何实现亲和性的？（技术细节）

在内核源码（Linux）层面，亲和性是通过 **`cpumask`（CPU 掩码）** 实现的。

- **数据结构**：在进程控制块（`task_struct`）中，有一个字段叫 `cpus_allowed`。
    
- **位图表示**：它是一个位图（Bitmask）。如果值为 `00001011`（二进制），表示该进程被允许在 CPU 0、CPU 1 和 CPU 3 上运行。
    
- **调度检查**：每次调度器（Scheduler）在为某个 CPU 挑选下一个任务时，都会检查这个位图。如果该 CPU 不在位图中，调度器会直接跳过这个进程。

### 四、 进阶：CPU 隔离（CPU Isolation）

作为架构师，你可能会用到比亲和性更狠的一招：**隔离**。

- **场景**：你有一个高频交易系统或者一个实时的 AI 推理引擎，你希望 CPU 7 全力以赴跑这个任务，不准任何其他杂碎进程干扰。
    
- **操作**：
    
    1. 在 Linux 启动参数里设置 `isolcpus=7`。这样，操作系统默认的调度器就不会把任何普通进程分给 CPU 7。
        
    2. 通过**硬亲和性**，手动将你的关键线程绑定到 CPU 7。
        
- **直觉结果**：CPU 7 变成了一个“专用处理器”，几乎没有上下文切换，没有缓存污染，延迟极低。

### 五、 408 考研直击：关于亲和性的高频考点

1. **负载均衡 vs. 亲和性**：
    
    - 这是一个**矛盾对立面**。负载均衡想要“雨露均沾”，而亲和性想要“从一而终”。
        
    - **考点**：操作系统如何在两者间平衡？（答案：通常采用“推/拉”机制，只有当负载失衡超过一定阈值时，才会破坏亲和性进行迁移）。
        
2. **开销对比**：
    
    - 考卷可能会问：为什么在多处理器系统中，频繁迁移进程是不划算的？
        
    - **直觉回答**：因为会引起 **Cache 失效、TLB 失效和总线流量增加**。
        
3. **多线程与亲和性**：
    
    - **考点**：同一进程下的多个子线程，是共用亲和性还是独立？
        
    - **答案**：在 Linux（NPTL 架构）下，每个线程都有独立的 `task_struct`，所以可以为每个线程设置不同的 CPU 绑定策略。
