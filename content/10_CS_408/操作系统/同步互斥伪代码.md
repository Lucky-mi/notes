### 核心符号约定

在考研答题中，通常使用以下标准符号，阅卷老师最认可：

- `semaphore`: 信号量类型
    
- `P(S)` 或 `wait(S)`: 申请资源（S减1，若<0则阻塞）
    
- `V(S)` 或 `signal(S)`: 释放资源（S加1，唤醒等待进程）
    

---

### 1. 生产者-消费者问题 (Producer-Consumer Problem)

这是最基础也是最重要的模型。考察重点是**缓冲区的互斥访问**和**非空非满的同步**。

场景描述：

一组生产者向缓冲区放入产品，一组消费者从缓冲区取出产品。缓冲区大小为 $N$。

```c
// 1. 定义信号量
semaphore mutex = 1;  // 互斥信号量，保护缓冲区
semaphore empty = N;  // 同步信号量，表示空闲缓冲区的数量
semaphore full = 0;   // 同步信号量，表示已存入产品的数量

// 生产者进程
void Producer() {
    while(TRUE) {
        produce_item(); // 生产一个产品

        P(empty);       // 【同步】申请一个空位 (必须在P(mutex)之前!)
        P(mutex);       // 【互斥】申请缓冲区使用权

        put_item();     // 将产品放入缓冲区

        V(mutex);       // 【互斥】释放缓冲区
        V(full);        // 【同步】增加一个满位（唤醒消费者）
    }
}

// 消费者进程
void Consumer() {
    while(TRUE) {
        P(full);        // 【同步】申请一个产品 (必须在P(mutex)之前!)
        P(mutex);       // 【互斥】申请缓冲区使用权

        take_item();    // 从缓冲区取出产品

        V(mutex);       // 【互斥】释放缓冲区
        V(empty);       // 【同步】增加一个空位（唤醒生产者）

        consume_item(); // 消费产品
    }
}
```

> 架构师视角/考研避坑：
> 
> 注意 P(empty) 和 P(mutex) 的顺序。如果反过来（先锁缓冲区，再等空位），一旦缓冲区满了，生产者拿着锁等待空位，消费者想取数据却拿不到锁，会直接导致死锁。

### 2. 读者-写者问题 (Readers-Writers Problem)

考察重点是**读写互斥、写写互斥，但读读允许并发**。这也是考研常考的复杂逻辑。

#### 情况 A：读者优先 (Reader Priority)

这是最经典的解法。只要有一个读者在读，后续读者就可以直接进入，无需排队等待写者。
```c
// 定义信号量和变量
semaphore rw_mutex = 1;    // 用于实现读写互斥、写写互斥
semaphore count_mutex = 1; // 用于保护 read_count 变量的互斥修改
int read_count = 0;        // 记录当前有多少个读者在读

// 写者进程
void Writer() {
    while(TRUE) {
        P(rw_mutex);       // 申请写权限（如果有读者在读，这里会阻塞）
        writing();         // 写操作
        V(rw_mutex);       // 释放写权限
    }
}

// 读者进程
void Reader() {
    while(TRUE) {
        P(count_mutex);        // 互斥访问 read_count
        if (read_count == 0) {
            P(rw_mutex);       // 【关键】如果是第一个读者，负责抢占“写锁”
        }
        read_count++;
        V(count_mutex);

        reading();             // 读操作（此时 rw_mutex 被锁住，写者进不来，但其他读者可以进）

        P(count_mutex);        // 互斥访问 read_count
        read_count--;
        if (read_count == 0) {
            V(rw_mutex);       // 【关键】如果是最后一个读者，负责释放“写锁”
        }
        V(count_mutex);
    }
}
```

### 3. 哲学家进餐问题 (Dining Philosophers Problem)

考察重点是**死锁的处理**。如果所有哲学家同时拿起左边的筷子，就会死锁。

408 通用解法：

限制同时进餐的人数（例如 $N=5$ 时，最多允许 $4$ 人同时抢筷子），或者采用“仅当左右两只筷子都可用时才拿起”的策略。下面展示限制人数法（这也是最容易写且不易出错的）。
```c
// 定义信号量
semaphore chopstick[5] = {1, 1, 1, 1, 1}; // 5根筷子
semaphore count = 4;                      // 最多允许4人同时请求进餐

// 第 i 号哲学家进程 (i = 0, 1, 2, 3, 4)
void Philosopher(int i) {
    while(TRUE) {
        think();             // 思考

        P(count);            // 【死锁预防】请求进餐名额，限制最多4人
        P(chopstick[i]);     // 拿左边的筷子
        P(chopstick[(i+1)%5]); // 拿右边的筷子

        eat();               // 进餐

        V(chopstick[i]);     // 放下左边的筷子
        V(chopstick[(i+1)%5]); // 放下右边的筷子
        V(count);            // 归还进餐名额
    }
}
```

### 4. 吸烟者问题 (Smokers Problem)

这是一个典型的**单生产者（供应者）多消费者**问题，但消费者需要的资源组合不同。考察重点是**如何通过中间信号量实现特定的唤醒顺序**。

**场景：** 供应者每次随机提供三种组合之一：（烟草+纸）、（纸+火柴）、（烟草+火柴）。三个抽烟者分别拥有：火柴、烟草、纸。
```c
// 定义信号量
semaphore offer1 = 0; // 代表桌上有组合1（烟草+纸），唤醒有火柴的人
semaphore offer2 = 0; // 代表桌上有组合2（纸+火柴），唤醒有烟草的人
semaphore offer3 = 0; // 代表桌上有组合3（烟草+火柴），唤醒有纸的人
semaphore finish = 1; // 互斥信号量，表示抽烟完成，可以放下一组东西了

// 供应者进程
void Agent() {
    while(TRUE) {
        P(finish); // 等待桌子变空
        int num = random() % 3; // 随机决定放什么
        if (num == 0)
            V(offer1); // 放烟草+纸 -> 唤醒抽烟者1
        else if (num == 1)
            V(offer2); // 放纸+火柴 -> 唤醒抽烟者2
        else
            V(offer3); // 放烟草+火柴 -> 唤醒抽烟者3
    }
}

// 抽烟者1（拥有火柴）
void Smoker1() {
    while(TRUE) {
        P(offer1); // 等待烟草+纸
        smoke();
        V(finish); // 通知供应者可以放新东西了
    }
}

// 抽烟者2（拥有烟草）
void Smoker2() {
    while(TRUE) {
        P(offer2); // 等待纸+火柴
        smoke();
        V(finish);
    }
}

// 抽烟者3（拥有纸）
void Smoker3() {
    while(TRUE) {
        P(offer3); // 等待烟草+火柴
        smoke();
        V(finish);
    }
}
```
