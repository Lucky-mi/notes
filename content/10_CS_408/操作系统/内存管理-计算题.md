页面大小：页内偏移
### 1. 逻辑地址转物理地址 (基础变换)

这是最基本也是最高频的题型。

- **核心公式**：
    
    - $物理地址 = 物理页框号 (Frame\_No) \times 页面大小 (Page\_Size) + 页内偏移 (Offset)$
        
    - **技巧**：通常不需要乘法，而是直接**拼接**（对于 2 的幂次页面大小）。
        
- **题型一：分页存储 (Paging)**
    
    - **已知**：逻辑地址 A，页面大小 L，页表。
        
    - **步骤**：
        
        1. 算页号：$P = \lfloor A / L \rfloor$
            
        2. 算偏移：$W = A \% L$
            
        3. 查页表：找到页号 $P$ 对应的物理块号 $b$。
            
        4. 拼接：物理地址 = $b \times L + W$
            
    - **位运算捷径**：如果页面大小是 4KB ($2^{12}$)，直接看逻辑地址的**低 12 位**是偏移，**高位**是页号。物理块号直接拼上低 12 位即可。
        
- **题型二：分段存储 (Segmentation)**
    
    - **已知**：逻辑地址 $<S, W>$ (段号, 段内偏移)，段表。
        
    - **步骤**：
        
        1. **越界检查**：判断 $W < 段长 (Limit)$？若不满足，报错。
            
        2. 查段表：找到段号 $S$ 对应的**基址 (Base)**。
            
        3. 计算：物理地址 = $Base + W$ (注意这里是**加法**，不是拼接！)。
            
- **题型三：段页式 (Segmented Paging)**
    
    - **步骤**：
        
        1. 按段号 $S$ 查段表 -> 得到该段的**页表始址**。
            
        2. 按页号 $P$ 查页表 -> 得到**物理块号 $b$**。
            
        3. 拼接：$b \times L + W$。

### 2. 页表大小与页表项计算 (多级页表核心)

这类题目考察你对“套娃”机制的理解。

- **核心约束**：
    
    - **一级页表（页目录）必须能放进一个物理页框内。**
        
    - $页表项数 = 虚拟地址空间大小 / 页面大小$
        
    - $页表大小 = 页表项数 \times 每个页表项的大小$
        
- **题型：求多级页表的级数或地址结构**
    
    - **场景**：32 位系统，页面大小 4KB，页表项大小 4B。
        
    - **推导**：
        
        1. 一页能装多少个页表项？ $4KB / 4B = 1024 = 2^{10}$ 个。
            
        2. 这意味着每一级索引只能覆盖 10 位地址。
            
        3. 32 位地址 = 10位(一级) + 10位(二级) + 12位(偏移)。
            
        4. **结论**：这是两级页表。
            
    - **变体**：如果页表项是 8B？一页装 $2^9$ 个。32位 = 9+9+?+12... 需要重新拆分。

### 3. 访存时间 (EAT) 与 TLB 计算

考察 TLB 命中与未命中时的总耗时。

- **核心参数**：
    
    - $t$：访问一次内存的时间。
        
    - $\alpha$：TLB 命中率。
        
    - $t_{TLB}$：查快表的时间（通常忽略或很小）。
        
- **公式（以单级页表为例）**：
    
    - **命中 (Hit)**：查TLB + 查数据 = $t_{TLB} + t$ (或者只是 $t$，看题目怎么说)。
        
    - **未命中 (Miss)**：查TLB + 查页表 + 查数据 = $t_{TLB} + t + t$。
        
    - **平均有效访问时间 (EAT)** = $\alpha \times (Hit) + (1-\alpha) \times (Miss)$。
        
- **陷阱**：
    
    - **多级页表**：未命中时，要查 $N$ 次页表 + 1 次数据。
        
    - **并行查找**：如果题目说“同时查找 TLB 和内存”，那么命中时的时间就是 $t$，不需要加 $t_{TLB}$。

### 4. 页面置换算法模拟 (缺页次数计算)

这是最像“连连看”的游戏题，考察 LRU, FIFO, OPT, Clock。

- **题型**：给定物理块数 $N$ 和引用序列，求缺页次数或缺页率。
    
- **计算步骤**：
    
    1. 画格子（行数 = 物理块数，列数 = 序列长度）。
        
    2. 逐个填入。
        
    3. **注意区分**：“缺页次数” vs “置换次数”。
        
        - **缺页次数**：刚开始空的时候调入也算缺页。
            
        - **置换次数**：只有满了之后踢人，才算置换。
            
        - 通常：$置换次数 = 缺页次数 - 物理块数$。
            
- **高频坑点**：**Belady 异常**（只有 FIFO 会有）。

### 5. 内存容量与位示图计算

- **题型一：位示图 (Bitmap)**
    
    - **场景**：用一个 bit 表示一个物理页框是否空闲。
        
    - **计算**：
        
        - 物理内存 16GB，页大小 4KB。共有 $16GB/4KB = 4M$ 个页框。
            
        - 需要 $4M$ 个位。
            
        - 位示图大小 = $4M / 8$ (字节) = 512KB。
            
    - **坐标转换**：第 $i$ 行第 $j$ 列对应的是第几个块？（注意行列是从 0 开始还是 1 开始，字长是 32位 还是 16位）。
        
- **题型二：反置页表大小**
    
    - **公式**：反置页表大小 = 物理页框总数 $\times$ 表项大小。
        
    - **考点**：跟虚拟地址空间多大没关系！只跟物理内存多大有关系。

### ⚡️ 拿分秘籍 (One More Thing)

遇到所有带 **KB, MB, GB** 的题，第一时间换算成 **2 的幂次**：

- $1KB = 2^{10}$
    
- $1MB = 2^{20}$
    
- $1GB = 2^{30}$
    
- $4KB = 2^{12}$
    

例子：逻辑地址空间 4GB，页面 4KB。

直接反应：页表项总数 = $2^{32} / 2^{12} = 2^{20}$ (100万)。

如果不换算，去算 $4 \times 1024 \times 1024 \times 1024 / 4096$，算出死都算不完。
