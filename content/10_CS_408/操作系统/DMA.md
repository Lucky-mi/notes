## 1. 为什么要引入 DMA？（对比三种 I/O 方式）

在理解 DMA 之前，我们需要看看它的前辈们：

- **程序查询方式：** CPU 必须不停地轮询 I/O 设备是否就绪。CPU 几乎 100% 的时间被浪费在等待上。
    
- **中断驱动方式：** 设备准备好一个字（Word）后发出中断，CPU 暂停手头工作去搬运数据。
    
    - _痛点：_ 如果传输海量数据（如 4K 视频流），CPU 会被频繁的中断淹没（每传输一个字就要中断一次），导致 CPU 效率极低。
        
- **DMA 方式：** 数据传输以 **“块”** 为单位。CPU 只需要下达指令（起始地址、数据长度），剩下的数据搬运由 DMA 控制器（DMAC）完成，只有在**整块数据**传输结束时，才向 CPU 发送一个中断。
    

---

## 2. DMA 控制器的内部结构

DMAC（DMA Controller）本质上是一个简化版的处理器，它能够接管总线控制权。其核心部件包括：

- **DAR (Device Address Register)：** 设备地址寄存器，存放设备内部的偏移。
    
- **MAR (Memory Address Register)：** 内存地址寄存器，存放数据要写入或读出的内存起始地址。
    
- **WC (Word Count)：** 传送字计数器，记录还需要传送多少数据。
    
- **Control/Status Register：** 控制/状态寄存器，记录工作状态和传输方向。
    

---

## 3. DMA 传送的过程（三大阶段）

DMA 的工作过程通常分为以下三个阶段，这是 408 选择题的高频考点：

### ① 预处理 (Preparation)

CPU 执行 I/O 指令，向 DMAC 发送：

- 测试设备状态。
    
- 设置 MAR（内存首址）。
    
- 设置 WC（字数）。
    
- 启动设备。
    
    注意：此时 CPU 仍然在运行。
    

### ② 数据传送 (Data Transfer)

这是 DMA 的核心。DMAC 获得总线控制权后，直接在 I/O 设备与内存间传输数据。

- **不需要 CPU 参与**，CPU 可以继续执行其他不涉及总线的指令。
    

### ③ 后处理 (Post-processing)

当 WC 减至 0，表示数据传输完成：

- DMAC 向 CPU 发送一个**中断请求**。
    
- CPU 执行中断服务程序，进行校验、错误检查或关闭设备。
    

---

## 4. DMA 传送方式（总线权分配）

DMAC 如何从 CPU 手中“抢”走总线的使用权？主要有三种方式：

|**方式**|**描述**|**特点**|
|---|---|---|
|**停止 CPU 访问内存**|DMA 传送期间，CPU 完全放弃总线控制权。|简单；但 CPU 效率低。|
|**周期挪用 (Cycle Stealing)**|**(考研重点)** 当 I/O 有请求时，DMA 挪用一个或几个总线周期。|适合 I/O 速率高于内存速率的情况，对 CPU 影响较小。|
|**交替访问 (Transparent)**|CPU 周期分为两个时间片：一个给 CPU，一个给 DMA。|CPU 几乎不受影响；但硬件逻辑最复杂。|

## 5. 关键考点对比：DMA vs 中断

这是 408 考研最喜欢考的辨析题，请务必记牢：

1. **数据单位：** 中断以“字/字节”为单位；DMA 以“数据块”为单位。
    
2. **触发时机：** 中断在**每个字**传送完时触发；DMA 仅在**整块数据**传送完时触发。
    
3. **硬件需求：** DMA 需要专门的硬件控制器（DMAC）；中断主要靠软件（中断服务程序）。
    
4. **响应时机：** * 中断必须在**指令执行结束**后响应。
    
    - DMA 可以在**任何机器周期结束**时响应（总线周期结束）。
        
5. **优先级：** DMA 的响应优先级通常**高于**中断响应，因为 I/O 设备（如硬盘）的数据流如果不及时处理会丢失。

## 6. 进阶思考：现代系统中的 DMA

作为 AI 架构师方向的学子，你可以关注到 DMA 的延伸概念：

- **Scatter-Gather DMA：** 允许 DMA 从非连续的物理内存块中读取数据，这对现代虚拟内存管理非常关键。
    
- **Zero-copy (零拷贝)：** Linux 中的 `sendfile` 系统调用正是利用 DMA 技术，避免了数据在内核缓冲区和用户缓冲区之间的多次拷贝，极大地提升了高性能服务器（如 Nginx、Kafka）的效率。
