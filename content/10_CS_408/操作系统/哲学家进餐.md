# 哲学家进餐问题

## 1. 模型图解与核心矛盾

- **场景**：5 位哲学家围坐在一张圆桌旁，中间是一碗通心粉。
    
- **资源**：每两人之间放着一只筷子，总共 **5 只筷子**。
    
- **规则**：
    
    1. 哲学家只有同时拿到**左、右两只**筷子才能吃饭。
        
    2. 吃完后，放下筷子继续思考。
        

### **致命死锁 (Deadlock)**：

如果 5 位哲学家**同时**感到饥饿，每人都拿起了自己**左手**边的筷子。

- 结果：每个人手里都有一只筷子，都在等右边的人放下筷子。
    
- 后果：全员饿死，系统卡死。
    

---

## 2. 信号量定义

```c
semaphore chopstick[5] = {1, 1, 1, 1, 1}; // 5 只筷子，每只都是一个互斥资源
```

---

## 3. 错误的代码实现（会导致死锁）

```c
void Philosopher_i() {
    while (true) {
        think();
        P(chopstick[i]);          // 拿起左手边的筷子
        P(chopstick[(i + 1) % 5]);  // 拿起右手边的筷子
        eat();
        V(chopstick[i]);
        V(chopstick[(i + 1) % 5]);
    }
}
```

---

## 4. 解决死锁的三种方案 (408 核心考点)

为了破坏“死锁的四个必要条件”，我们有三种经典的改进方法：

### **方案一：限制进餐人数 (破坏请求并保持)**

规定最多允许 4 位哲学家同时去拿筷子。这样保证至少有一位哲学家能凑齐两只筷子。

- **增加信号量**：`semaphore count = 4;`
    
- **逻辑**：进餐前先执行 `P(count)`。
    

### **方案二：设置取筷子的原子性 (破坏不剥夺/请求并保持)**

利用一个互斥信号量 `mutex`，要求哲学家取筷子的过程必须是“一气呵成”的。要么两只都拿，要么一只都不拿。
```c
void Philosopher_i() {
    while (true) {
        P(mutex);                 // 锁住拿筷子的动作
        P(chopstick[i]);          // 拿左
        P(chopstick[(i + 1) % 5]);  // 拿右
        V(mutex);                 // 拿完放开锁
        eat();
        V(chopstick[i]);
        V(chopstick[(i + 1) % 5]);
    }
}
```

> [!TIP] 注意
> 
> 这种方法虽然防止了死锁，但在极端情况下可能效率较低，因为一个人拿筷子时，其他人连尝试拿筷子的机会都没有。

### **方案三：奇偶号策略 (破坏循环等待) —— 最推荐**

规定奇数号哲学家先拿左边再拿右边，而偶数号哲学家先拿右边再拿左边。

```c
void Philosopher_i() {
    while (true) {
        if (i % 2 != 0) { // 奇数号
            P(chopstick[i]); P(chopstick[(i + 1) % 5]);
        } else {          // 偶数号
            P(chopstick[(i + 1) % 5]); P(chopstick[i]);
        }
        eat();
        // 释放逻辑同上...
    }
}
```

**原理**：这样 0 号和 1 号哲学家会争抢同一只筷子（1号的左手/0号的右手），竞争被提前了，从而破坏了环路。

---

## 5. 进阶：如何用“管程”解决哲学家问题？

在考研的高级题目中，可能会要求你用管程实现。管程的思路更像“上帝视角”：

1. 哲学家告诉管程：“我饿了”。
    
2. 管程检查他的左右邻居是不是都没在吃。
    
3. 如果满足，就把他的状态设为 `EATING`，否则让他 `wait()`。
    

---

## 6. 总结回顾 

- **核心教训**：死锁往往来源于**资源的循环等待**。
    
- **做题套路**：
    
    - 看到“环状资源” $\rightarrow$ 想到哲学家。
        
    - 看到“防止死锁” $\rightarrow$ 想到限制人数、原子取放、顺序取放。
