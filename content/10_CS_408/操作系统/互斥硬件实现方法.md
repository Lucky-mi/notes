# 临界区互斥的硬件实现方法

## 核心复习导图

- **核心思想**：软件做不到“原子性”，那就让硬件来做。硬件提供一条特殊的指令，这条指令在执行过程中**绝对不会被中断**，也不会允许其他 CPU 干扰。
    
- **两大主角**：
    
    1. **TSL 指令** (Test-and-Set-Lock)
        
    2. **Swap 指令** (Exchange / XCHG)
        
- **共同产物**：它们构建出的锁，被称为 **[[自旋锁]] (Spinlock)**。
    

---

## 1. TSL 指令 (Test-and-Set-Lock) #考研高频

这是硬件最经典的支持方式。它的名字非常直白：**“测试并上锁”**。

### (1) 硬件层面的逻辑 (原子操作)

想象这是一个黑盒子函数，**它在硬件电路上是一气呵成的**：
```c
// 这是一个原子操作，中间不能断！
boolean TSL(boolean *lock) {
    boolean old = *lock; // 1. 读出锁原来的状态
    *lock = true;        // 2. 不管原来是啥，把锁设置为“占用”(true)
    return old;          // 3. 返回原来的状态
}
```

> [!NOTE] 这里的关键点
> 
> “读”和“写”是分开的两步操作，但在 TSL 指令下，硬件（通过锁住内存总线）保证了这两步是原子的。哪怕旁边站着 100 个 CPU，也没人能插手。

### (2) 软件层面的应用 (怎么用它写代码？)

有了这个神兵利器，写互斥代码就变得极其简单：
```c
// 共享变量
boolean lock = false; // false 代表空闲，true 代表被占

// 进程逻辑
while (TSL(&lock));   // 1. 只要 TSL 返回 true，说明原来被人锁着，我就一直循环（忙等）
                      // 2. 如果 TSL 返回 false，说明原来没锁，我现在锁上了，循环结束，进门！

critical_section();   // 访问临界区

lock = false;         // 3. 离开：把锁还原成 false（解锁）
remainder_section();
```

### (3) 通俗理解：自动落锁的把手

想象一个特殊的门把手：

- 你要进门，必须转动把手（执行 TSL）。
    
- **瞬间效果**：当你手碰到把手的一刹那，门把手会自动弹成“锁定”状态。
    
- **反馈**：
    
    - 如果刚才门是开的，把手会告诉你“刚才没锁”，你就进去了（现在门锁了）。
        
    - 如果刚才门是锁的，把手会告诉你“刚才锁着”，你进不去，但门依然保持锁定。

## 2. Swap 指令 (Exchange / XCHG)

这是 x86 架构中常用的指令（`XCHG`）。逻辑和 TSL 只有细微差别。

### (1) 硬件层面的逻辑 (原子操作)

它的作用是**交换**两个位置的数据。
```c
// 原子操作
void Swap(boolean *a, boolean *b) {
    boolean temp;
    temp = *a;
    *a = *b;
    *b = temp;
}
```

### (2) 软件层面的应用

每个想进临界区的进程，手里都拿一把“旧钥匙”（key = true）。
```c
// 共享变量
boolean lock = false; // 全局锁

// 进程逻辑
boolean key = true;   // 我手里的牌：假设它是锁着的
while (key) {
    Swap(&lock, &key);// 和全局锁交换！
                      // 如果 lock 原来是 false (没锁)：
                      //    换完后，lock 变 true (锁上了)，key 变 false。
                      //    循环条件 key 变 false -> 跳出循环，进入！
                      // 如果 lock 原来是 true (锁着)：
                      //    换完后，lock 还是 true，key 还是 true。
                      //    循环继续 -> 忙等。
}

critical_section();

lock = false;         // 解锁
remainder_section();
```

## 3. 硬件实现的优缺点 (408 必背)

不管是 TSL 还是 Swap，它们的特性几乎是一模一样的。

### ✅ 优点

1. **实现简单**：代码只有寥寥几行，把复杂的逻辑丢给硬件。
    
2. **适用于多核**：这是它秒杀“关中断”的地方。不管多少核，总线锁住了，谁也别想抢。
    
3. **适用于多重临界区**：不像 Peterson 算法那样只能处理两个进程，硬件指令可以处理 $N$ 个进程争抢。
    

### ❌ 缺点 (非常重要)

1. **不满足“[[让权等待]]”**：
    
    - 这是硬件实现最大的硬伤。
        
    - 当进程进不去时，它在 `while` 循环里疯狂执行 TSL 指令。
        
    - 这叫 **[[忙等]] (Busy Waiting)**。CPU 占用率直接飙升到 100%，却什么正事都没干。
        
2. **可能导致“[[饥饿]]” (Starvation)**：
    
    - 如果有 10 个进程都在抢，TSL 并没有排队机制。
        
    - 全靠运气（CPU 调度）。运气不好的进程可能一万年也抢不到锁。

## 4. 深度概念辨析：自旋锁 vs [[互斥锁]]

你在复习中可能会看到 **Spinlock (自旋锁)** 和 **Mutex (互斥锁)** 这两个词。

- **自旋锁 (Spinlock)**：就是我们要么用 TSL，要么用 Swap 实现的这种**“进不去就在门口转圈圈”**的锁。
    
    - _适用场景_：预计等待时间很短（比如我就进去改个变量就出来），这时候“转圈圈”比“切换进程”的开销小。
        
- **互斥锁 (Mutex)**：通常指结合了 **“休眠”** 机制的锁（如信号量）。
    
    - _逻辑_：进不去？那我让出 CPU，去睡觉（阻塞），等有人叫我我再醒。
        
    - _适用场景_：预计等待时间较长。

## 5. 总结对比表 (Obsidian Table)

|**维度**|**中断屏蔽 (关中断)**|**TSL / Swap 指令**|
|---|---|---|
|**适用范围**|仅单核系统 (OS 内核态)|**单核 & 多核均可** (用户态也能用)|
|**实现机制**|禁止 CPU 响应时钟中断|硬件原子操作，锁内存总线|
|**是否忙等**|否 (直接独占 CPU)|**是 (忙等 / Spin)**|
|**满足让权等待**|N/A|**不满足**|
|**408 考点**|局限性大，多核失效|简单、多核可用、但浪费 CPU|
