# 临界区互斥的软件实现方法

## 核心复习导图

- **背景**：在没有硬件指令（如 TSL）支持的情况下，仅靠纯代码逻辑实现互斥。
    
- **目标**：满足互斥的四大准则（空闲让进、忙则等待、有限等待、让权等待）。
    
- **演进路线**：单标志法 $\rightarrow$ 双标志先检查 $\rightarrow$ 双标志后检查 $\rightarrow$ **Peterson 算法**（最终形态）。
    

> [!WARNING] 408 避坑指南
> 
> 所有的软件实现方法（包括 Peterson），都无法实现 “让权等待”。它们在等待进入临界区时，都会执行 while 循环，处于 “忙等” (Busy Waiting) 状态。

---

## 1. 单标志法 (Single Flag)

这是最简单的思路，类似于“轮流值日”。

### 算法逻辑

设置一个公用整型变量 `turn`，用于指示**当前允许谁进入临界区**。

- `turn = 0`：允许 P0 进程进入。
    
- `turn = 1`：允许 P1 进程进入。

```c
// P0 进程逻辑
while (turn != 0);  // 只要不是 0，我就死等
critical_section(); // 访问临界区
turn = 1;           // 离开时，把权限转交给 P1
remainder_section();

// P1 进程逻辑
while (turn != 1);  // 只要不是 1，我就死等
critical_section();
turn = 0;           // 离开时，把权限转交给 P0
```

### 考研透析

- **原理**：强制交替执行。P0 $\rightarrow$ P1 $\rightarrow$ P0 $\rightarrow$ P1...
    
- **缺点**：
    
    - 如果 P0 做完了，把 `turn` 改成了 1，但 P1 迟迟不来（或者 P1 根本不想进临界区）。
        
    - 此时临界区是**空闲**的，但 P0 想再次进入时，发现 `turn` 还是 1，进不去。
        
- **结论**：**违背了“[[空闲让进]]”原则**。
    

---

## 2. 双标志先检查法 (Double Flag, Check-Then-Set)

为了解决“必须轮流”的问题，引入 `flag` 数组。`flag[i] = true` 表示进程 Pi **“想要”** 进入临界区。

### 算法逻辑

先看别人想不想进（检查），如果没人想进，我再举手说我要进（设置）。
```c
// P0 进程逻辑
while (flag[1]);    // 1. 检查：P1 想进吗？如果想，我就等
flag[0] = true;     // 2. 设置：没人想进，那我进。举手！
critical_section();
flag[0] = false;    // 3. 离开：放下手
remainder_section();
```

### 考研透析

- **场景演绎（Bug 复现）**：
    
    1. P0 执行第一句 `while(flag[1])`，发现 P1 没举手（`flag[1]` 是 false），准备往下走。
        
    2. **发生进程切换！** P0 暂停。
        
    3. P1 上场，执行 `while(flag[0])`，发现 P0 也没举手（因为 P0 还没来得及执行第二句）。
        
    4. P1 把 `flag[1]` 设为 true，进入临界区。
        
    5. 切回 P0，P0 继续执行第二句，把 `flag[0]` 设为 true，也进入临界区。
        
- **结论**：**违背了“[[忙则等待]]”原则**。两个人同时进去了，彻底失败。

## 3. 双标志后检查法 (Double Flag, Set-Then-Check)

吸取上一次的教训：先举手（设置），再检查别人。

### 算法逻辑

```c
// P0 进程逻辑
flag[0] = true;     // 1. 设置：我先举手！
while (flag[1]);    // 2. 检查：你举手了吗？如果你举了，我就等。
critical_section();
flag[0] = false;
remainder_section();
```

### 考研透析

- **场景演绎（死锁复现）**：
    
    1. P0 说“我要进”，执行 `flag[0] = true`。
        
    2. **发生进程切换！**
        
    3. P1 说“我也要进”，执行 `flag[1] = true`。
        
    4. P1 检查 `while(flag[0])`，发现 P0 举手了，P1 开始死循环等待。
        
    5. 切回 P0，P0 检查 `while(flag[1])`，发现 P1 也举手了，P0 也开始死循环等待。
        
- **结论**：**违背了“[[空闲让进]]”和“[[有限等待]]”原则**。两人互相谦让，导致**死锁 (Deadlock)**。

## 4. Peterson 算法 (重点掌握) #考研必考

这是软件实现的**集大成者**，由 Gary Peterson 在 1981 年提出。它巧妙地结合了“单标志法”和“双标志后检查法”。

### 核心思想

**“孔融让梨”**。

1. 我举手（表示我想进）。
    
2. 但我先客气一下，把轮次（`turn`）让给你。
    
3. **判断条件**：如果**你也想进**，并且**轮次是你**（我确实让给你了），那我就等着。
    
4. 如果你不想进，或者你把轮次让给我了，我就冲！
    

### 代码实现 (背诵级)
```c
// 共享变量
bool flag[2]; // 意愿数组
int turn;     // 谦让变量

// P0 进程逻辑
flag[0] = true;        // 1. 我想进
turn = 1;              // 2. 客气一下，让 P1 先进（turn = opponent）
while (flag[1] && turn == 1); // 3. 关键判断：P1 想进 且 确实轮到 P1，那我就等
critical_section();
flag[0] = false;       // 4. 我不想了
remainder_section();

// P1 进程逻辑
flag[1] = true;
turn = 0;              // P1 也是客气，让 P0 先进
while (flag[0] && turn == 0);
critical_section();
flag[1] = false;
```

### 逻辑推演 (为什么它是对的？)

假设 P0 和 P1 几乎同时想进：

1. P0: `flag[0]=true`, `turn=1`。
    
2. P1: `flag[1]=true`, `turn=0`。（注意：`turn` 是全局变量，最后被改写成了 0）。
    
3. **P0 检查**：`while (flag[1] && turn == 1)`。
    
    - `flag[1]` 是 true (P1 想进)。
        
    - `turn` 是 0 (因为被 P1 改写了)。
        
    - **条件不成立！** P0 **跳出循环，进入临界区**。
        
4. **P1 检查**：`while (flag[0] && turn == 0)`。
    
    - `flag[0]` 是 true。
        
    - `turn` 是 0。
        
    - **条件成立！** P1 **陷入循环等待**。
        

> [!NOTE] 考研结论
> 
> Peterson 算法完美解决了互斥问题。
> 
> - 满足：[[空闲让进]]、[[忙则等待]]、[[有限等待]]。
>     
> - **不满足：[[让权等待]]**（还是会 While 循环空转）。
>

## 5. 拓展知识 (408 加分项/复试储备)

根据搜索结果，为你补充两个稍微高级一点的考点，虽然选择题不常考细节，但出现在综合题背景里不要慌。

### (1) Dekker 算法

- **地位**：它是**第一个**正确解决两进程互斥的软件算法（比 Peterson 早）。
    
- **特点**：逻辑非常复杂，分支判断多。
    
- **与 Peterson 的关系**：Peterson 是 Dekker 的简化版。如果考题问“第一个正确的”，选 Dekker；问“最好的双进程软件解法”，选 Peterson。
    

### (2) 面包店算法 (Bakery Algorithm)

- **提出者**：图灵奖得主 Leslie Lamport。
    
- **适用场景**：Peterson 只能用于**两个进程**，面包店算法可以解决 **N 个进程** 的互斥问题。
    
- **原理**：模仿面包店取号。
    
    1. 每个进程进店取一个号（Number），号越小优先级越高。
        
    2. 如果有两个进程拿到了相同的号（并发导致），则比较进程 ID（PID），小的先进。
        
- **考研相关性**：通常不考具体代码，但要理解其**“多进程互斥”**的定位。

# TS和swap的区别
## 1. 动作逻辑的区别 (最核心)

### (1) TSL (Test-and-Set)

它的名字叫“测试并设置”。它的动作非常霸道：不管内存里原来是啥，我读完之后，**一定会把它变成 `true` (上锁)**。

- **指令内部逻辑**：
    
    1. 记下内存 `lock` 现在的样子（保存旧值）。
        
    2. **强制**把内存 `lock` 改为 `true`。
        
    3. 返回旧值给 CPU 判断。
        

### (2) Swap (Exchange / XCHG)

它的名字叫“交换”。它的动作是“交易”：它不生产 `true`，它只是把寄存器里的值搬到内存，把内存的值搬到寄存器。

- **指令内部逻辑**：
    
    1. CPU 寄存器里有一个值（通常软件先把它设为 `true`）。
        
    2. 内存 `lock` 里有一个值。
        
    3. **互换**这两个位置的内容。
        

---

## 2. 代码实现的区别 (考试常考)

我们在写伪代码时，这两者的写法略有不同。

### TSL 的写法

你不需要准备“钥匙”，直接去撞门。

C

```
// 共享变量
boolean lock = false;

// 进程代码
while (TSL(&lock)) {
    // 循环体内其实啥也不用做，光检查就行
    // 因为 TSL 指令本身已经包含了“写 true”的操作
    // 只要返回 true，说明原来有人，我就继续撞
}
// 到了这里说明 TSL 返回了 false，且我已经把它置为 true 了
critical_section();
lock = false;
```

### Swap 的写法

你需要先在手里拿一把“上锁牌”（`key = true`），然后去和桌上的牌交换。

C

```
// 共享变量
boolean lock = false;

// 进程代码
boolean key = true; // 我手里拿个“占用”的牌子
do {
    Swap(&key, &lock); // 和全局锁交换
    // 只有当桌上原来是 false (没锁)
    // 交换后，我手里的 key 变成了 false
    // 此时 while (key) 条件不满足，才能跳出循环
} while (key);

critical_section();
lock = false;
```

## 3. 生活中的类比 (形象记忆)

为了帮你彻底记住，我们用一个**“公共卫生间”**的例子，卫生间门上有一个**挂牌**（Red=有人，Green=没人）。

### TSL 就像“自动喷漆机”

- **动作**：你拿着一个红色喷漆罐走过去。
    
- **逻辑**：
    
    1. 你看了一眼挂牌（Read）。
        
    2. 不管刚才是什么颜色，你**立刻**对着挂牌喷了一层红漆（Set True）。
        
- **结果**：
    
    - 如果你看到刚才是绿的，你喷成了红色 $\rightarrow$ 你进去了（因为是你锁的）。
        
    - 如果你看到刚才是红的，你又喷了一层红漆 $\rightarrow$ 没什么变化，你进不去，继续等。
        

### Swap 就像“换牌游戏”

- **动作**：你手里时刻拿着一张**红色**的牌（Key = True）。
    
- **逻辑**：
    
    1. 你走过去，把门上的牌摘下来，把自己手里的红牌挂上去（Swap）。
        
    2. 看看你刚才摘下来的是什么牌。
        
- **结果**：
    
    - 如果你摘下来的是**绿色**的 $\rightarrow$ 恭喜，你手里现在是绿牌（Key = False），你可以进去了（门上现在挂着你刚才给的红牌）。
        
    - 如果你摘下来的是**红色**的 $\rightarrow$ 倒霉，你用红牌换了个红牌。你手里的还是红牌（Key = True），说明里面有人。你只能拿着红牌继续换，直到换到绿牌为止。

## 4. 408 考研结论 (Obsidian Summary)

在做选择题或简答题时，只需要记住以下两点区别：

1. **硬件实现微操不同**：TSL 是“读+写固定值”；Swap 是“读+写寄存器值（交换）”。
    
2. **通用性**：
    
    - **Swap (XCHG)** 在现代主流 CPU (x86等) 中更常见。
        
    - **TSL** 更多出现在早期的或者特定的硬件架构中（如 Motorola 68000）。
        
    - 但在**操作系统理论**层面，它们**完全等价**。
        

> [!WARNING] 共同的缺点
> 
> 千万别忘了，虽然它俩动作不一样，但结局是一样的：
> 
> 只要进不去，都会导致进程在 CPU 上忙等 (Busy Waiting)。
